系统信息页是 Root 专属页面，地址为 `/system-info`。普通 Admin 即使拥有其他管理员页面的访问权限，也不能访问该页面及其系统任务接口。页面由「实例」和「系统任务」两个面板组成。

## 实例监控

实例面板展示已经向当前部署上报状态的节点。实例启动时会立即上报，之后通常每 30 秒上报一次；页面也会每 30 秒自动刷新，并提供手动刷新按钮。

### 状态与字段

后端根据最后心跳时间计算状态：距离当前时间不超过 90 秒为 `online`，超过 90 秒为 `stale`。90 秒是当前实现中的固定阈值，不能在此页面配置。

| 字段 | 含义 |
| --- | --- |
| 节点名、主机名 | 节点名优先取 `NODE_NAME`，主机名用于辅助识别。未设置 `NODE_NAME` 时，节点名回退为操作系统主机名。 |
| 状态 | `online` 表示最近 90 秒内有心跳；`stale` 表示超过 90 秒未上报。 |
| 角色 | `NODE_TYPE=slave` 时显示 Worker；其他情况默认显示 Master。Master 执行系统任务，Worker 不启动主节点专属任务执行器。 |
| CPU、内存 | 性能监控器的最近采样值，不保证是严格实时数据。关闭性能监控后，可能保留旧值或初始值。 |
| 存储 | 磁盘缓存目录所在文件系统的使用率；未设置缓存目录时使用系统临时目录所在文件系统。悬浮信息还会显示已用、可用和总空间。 |
| 版本、运行平台 | New API 版本以及 GOOS/GOARCH 运行平台。 |
| 启动时间、最后心跳 | 节点进程启动时间和最近一次上报时间。 |

多实例部署时，应为每个节点配置稳定且唯一的 `NODE_NAME`，修改后重启服务。多个实例使用相同节点名时，实例上报记录可能互相覆盖，页面无法可靠区分节点。

<Callout type="info">
  页面中的资源指标用于运行状态观察，不等同于数据库容量、整个宿主机的完整磁盘统计或实时性能监控面板。遇到资源异常时，应结合部署环境和服务端监控进一步确认。
</Callout>

### 删除失联实例记录

对于当前仍满足 90 秒失联条件的 `stale` 实例，Root 可以删除单条记录，也可以删除全部失联记录。两种删除接口都会在执行时再次检查状态：如果节点已经重新上报并恢复在线，则不会被删除。

删除的只是数据库中的实例状态记录，不会停止、重启或移除真实服务节点。仍在运行的节点下一次上报后会重新出现在列表中，因此删除操作不能替代修复网络、进程或部署故障。

<Callout type="warn">
  删除全部失联记录是针对整个实例列表的清理操作，不是删除当前页面上某一条筛选结果。执行前请确认节点确实已经下线或不再需要保留状态记录。
</Callout>

## 系统任务

系统任务面板显示后台维护、检测或轮询的一次执行批次。它与用户指南中的单个绘图、音乐或视频异步任务不同：用户异步任务的业务状态仍应在对应功能页面或日志中查看。

### 当前任务类型

当前实现注册以下五种系统任务：

| 类型 | 来源与触发条件 |
| --- | --- |
| `log_cleanup` | 在[运维设置](/zh/docs/guide/feature-guide/admin/settings-operations)的日志维护区域手动创建，用于按批次清理指定时间以前的数据库日志；默认每批 100 条。 |
| `channel_test` | 渠道页面手动触发，或由自动渠道测试设置按周期触发；具体检测范围和周期取决于监控配置。 |
| `model_update` | 渠道页面手动触发上游模型检测，或由自动模型更新任务按周期触发；默认检查间隔为 30 分钟，但仍受环境变量和渠道配置影响。 |
| `midjourney_poll` | 启用 `UPDATE_TASK` 且存在未完成的 Midjourney 任务时，约每 15 秒轮询一次；没有待处理任务时不会创建记录。 |
| `async_task_poll` | 启用 `UPDATE_TASK` 且存在未完成的 Suno/视频异步任务时，约每 15 秒轮询一次；空闲时不会创建记录。 |

计划任务不是每个周期都必然产生一条记录：同类型已有活动任务、系统未启用对应功能或没有待处理业务时，调度器会跳过创建。

### 状态与页面显示

系统任务只有以下四种状态：

- `pending`：任务已创建，等待 Master 节点领取；
- `running`：任务已被执行器领取并运行；
- `succeeded`：本次处理批次正常结束；
- `failed`：参数、执行器、数据库操作、租约等导致本次批次失败。

页面固定请求最近 20 条任务，按任务 ID 倒序，再拆分为「活动任务」和「任务历史」两个列表。任务历史只是这 20 条中的已完成或失败记录，不是完整历史；当前页面没有分页、搜索、类型筛选或时间筛选。

表格显示任务类型、状态、进度、执行器、更新时间和错误文本。只有任务状态中包含有效数字进度时才显示百分比；“详情”列实际显示的是 `error` 字段，不是独立的任务日志或完整结果摘要。页面不会直接展示任务 ID、payload、result 或完整执行日志。

存在 `pending` 或 `running` 任务时，系统任务面板每 8 秒自动刷新；没有活动任务时会暂停自动轮询，但仍可手动点击「刷新」。

<Callout type="warn">
  `succeeded` 只表示该批次的调度处理完成，不保证批次内每个渠道或上游子任务都成功。批量操作的局部失败可能只出现在结果摘要或服务端日志中，当前系统信息页不会展示这些摘要。
</Callout>

## 多实例调度与租约

系统任务执行器只在 Master 节点启动。多个 Master 同时运行时，系统通过数据库中的活动任务去重和按任务类型的租约，确保同一类型通常只有一个活动执行者；不同类型的任务可以并行运行。

执行器会在任务运行期间续租，租约有效期约为 60 秒并通常每 20 秒续期。60 秒是故障检测窗口，不是任务最长执行时间。执行器异常退出或持续无法续租时，过期租约会被清理，运行中的任务最终会标记为 `failed`，错误通常为 `task lease expired`。

若需要重新执行某项工作，应回到产生该任务的功能页面重新触发；同类型仍有活动任务时，重复触发通常会复用现有任务，而不是创建多个并行批次。

## 功能边界与排查

当前系统信息页和系统任务接口不提供以下操作：

- 重试任务；
- 取消任务或手动修改状态；
- 删除任务历史；
- 打开独立的任务日志详情。

排查时可以按以下顺序检查：

1. **Admin 看不到页面**：确认使用的是 Root 账户；这是后端权限要求，不是侧边栏显示问题。
2. **实例显示 `stale`**：查看节点进程、网络连通性、数据库连接和最近心跳时间；不要只删除记录。
3. **列表没有绘图或异步轮询任务**：确认 `UPDATE_TASK` 已启用，并且确实存在未完成的对应业务任务；空闲时没有记录是正常现象。
4. **任务长时间为 `running` 或出现租约过期**：检查 Master 节点是否仍在运行、数据库锁和服务端日志；租约过期表示执行器失去续租，不代表任务可以在页面上直接重试。
5. **任务显示成功但业务仍有失败项**：到渠道页面、用户异步任务页面、[日志与异步任务](/zh/docs/guide/feature-guide/user/log)或服务端日志查看批次内的详细结果。
6. **多实例名称重复**：为每个节点设置唯一 `NODE_NAME` 并重启服务，避免实例记录互相覆盖。
