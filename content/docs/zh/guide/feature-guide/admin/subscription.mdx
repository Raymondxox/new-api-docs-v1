管理员从侧边栏进入「订阅」，或访问 `/subscriptions` 管理订阅套餐。页面及管理接口要求 Admin 或 Root；创建、编辑、启停套餐和管理员代绑订阅等受保护操作，还要求 Root 已确认当前版本的支付合规条款。合规确认由 Root 在[计费与支付设置](/zh/docs/guide/feature-guide/admin/settings-billing)中完成。

## 套餐列表与上下架

管理端列表包含启用和停用套餐，按「排序值降序、ID 降序」排列。用户钱包只会显示启用套餐；如果实例尚未完成支付合规确认，用户端不会返回可购买的套餐。

套餐目前只有启用和停用两种发布操作，没有删除套餐功能：

- **启用**：允许符合条件的用户在钱包中看到并购买套餐。
- **停用**：不再向用户公开，也不接受新的普通购买。
- 停用不会自动取消已经创建的订阅；已有订阅继续按照自身有效期和权益运行。
- 管理员仍可在用户管理中为指定用户代绑停用套餐。已经创建的待支付订单，后续即使套餐被停用，支付回调仍可能完成订单。

<Callout type="warn">
  启停套餐只影响公开购买入口，不是撤销既有权益的工具。需要立即终止某个用户的订阅时，应在「用户管理 → 管理订阅」中执行失效操作，并先核对分组回退影响。
</Callout>
2. 填写以下信息：
   - **套餐名称**：用户购买时看到的名称
   - **价格**：套餐售价
   - **有效期类型**：选择 年 / 月 / 天 / 小时 / 自定义时长（秒）
   - **包含配额**：套餐内包含的配额数量
3. 点击「提交」，套餐创建完成并默认处于下架状态

## 创建和编辑套餐

点击「创建套餐」或打开已有套餐的编辑操作，填写以下字段：

| 字段 | 说明与限制 |
| --- | --- |
| 标题 | 必填，不能为空。 |
| 副标题 | 可选，用于用户端套餐卡说明。 |
| 价格 | 管理接口接受 `0–9999`；具体支付网关可能还有最低金额要求。 |
| 货币 | 套餐记录由后端固定保存为 `USD`；实际支付页面的币种还取决于网关配置。 |
| 有效期单位和值 | 支持年、月、日、小时；控制台要求对应值至少为 1。未填写有效单位时后端默认按月，直接提交的非自定义单位非正值会被修正为 1。 |
| 自定义有效期 | 选择自定义单位时填写自定义秒数，必须大于 0。 |
| 总额度 | 套餐每个计费周期包含的内部额度；`0` 表示不限总额度。显示单位跟随实例计费设置。 |
| 额度重置 | 不重置、每日、每周、每月或自定义秒数；自定义周期必须大于 0 秒。 |
| 启用状态 | 控制套餐是否向用户公开。 |
| 排序值 | 用户端和管理端均按排序值降序展示，排序相同时再按 ID 降序。 |
| 每用户购买上限 | `0` 表示不限；正数限制该用户在此套餐下可保留的订阅记录数量。 |
| 余额购买 | 是否允许用户使用钱包余额购买此套餐。 |
| 钱包溢出回退 | 订阅额度用尽后，是否允许计费流程回退到钱包余额。 |
| 升级分组 | 购买成功后切换到的用户分组；填写时必须存在于分组倍率配置。 |
| 降级分组 | 订阅到期、失效或删除时优先切换到的分组；填写时必须存在于分组倍率配置。 |
| 支付产品 | Stripe Price ID、Creem Product ID、Waffo Pancake Product ID，用于把套餐关联到对应网关产品。 |

套餐总额度和用户购买上限不能为负，自定义重置秒数在选择自定义重置时必须大于零；标题、价格、重置周期和分组会在保存时再次校验。自定义有效期秒数主要由当前控制台限制为正数，后端会在创建订阅时再次拒绝非正值。表单中的额度是内部额度的可读显示值，不应把它当作所有实例通用的固定货币汇率。

## 有效期与额度重置

创建一份订阅时，系统从当前套餐计算开始时间和结束时间：

- 年、月使用日历计算，分别增加对应的年数或月数；
- 日、小时使用固定时长；
- 自定义单位使用自定义秒数。

额度重置规则决定 `next_reset_time` 的计算方式。每日、每周和每月分别推进到下一个日历周期；自定义规则按秒数推进。若下一次重置时间已经超过订阅结束时间，则不再安排下一次重置。

自动维护仅由 Master 节点执行：服务启动后先运行一次，之后约每分钟处理到期订阅、分组回退和额度重置，每批最多处理 300 条。额度重置只针对仍为 `active` 且尚未到期的订阅，并将已用额度清零。

管理员还可以手动重置额度。当前订阅页会在合规未确认时禁用重置按钮，但重置接口本身没有再次检查支付合规，因此权限与合规状态应由控制台和部署访问策略共同约束：

- 套餐列表中的重置操作处理该套餐下所有用户的有效订阅；
- 用户管理中的重置操作处理指定用户在该套餐下的所有有效订阅；
- 「推进下次重置时间」默认开启，关闭时只清零已用额度并保留原来的重置时间；
- 用户没有该套餐的有效订阅时，按用户重置会返回错误。

## 套餐修改与权益快照

用户订阅不是实时引用套餐的全部字段。创建订阅时会保存以下权益信息：

- 总额度；
- 开始时间和结束时间；
- 购买时的升级分组及购买前分组；
- 到期时使用的降级分组；
- 订阅额度耗尽后是否允许回退钱包。

因此，修改套餐的价格、有效期、总额度、升级/降级分组或钱包溢出设置，不会重写已经创建的订阅权益。修改套餐前应先评估后续购买和管理员代绑的影响，不要把编辑套餐当作批量迁移既有订阅的操作。

额度重置周期及自定义重置秒数不会完整保存到用户订阅中。自动重置和管理员推进重置时间时会读取套餐当前配置，因此修改这两项规则可能影响已经存在的有效订阅。

待支付订单只保存套餐 ID 和支付金额。支付回调完成订单时，会重新读取该套餐并创建订阅；如果支付期间修改了套餐，最终创建的权益可能与用户发起支付时看到的内容不同。套餐停用也不会阻止已创建订单在成功回调后完成。

## 用户订阅管理

要查看或维护某个用户的订阅，请进入「用户管理」，打开用户行操作中的「管理订阅」。这里可以查看全部订阅记录（包括历史记录）、套餐、来源、状态、有效期和额度使用情况，并执行以下操作：

| 操作 | 行为 |
| --- | --- |
| 添加订阅 | 从现有套餐中为用户创建一份无需支付的管理员代绑订阅，来源记录为 `admin`，仍受该套餐的购买上限约束。 |
| 重置额度 | 清零指定用户和套餐下仍有效的 `active` 订阅，可选择是否推进下一次重置时间。 |
| 失效 | 立即将订阅状态设为 `cancelled`，结束时间改为当前时间，并保留订阅记录。 |
| 删除 | 硬删除该订阅记录及其权益数据；不会连带删除支付订单、充值流水或日志。 |

订阅状态包括：

- `active`：订阅有效且尚未结束；
- `expired`：达到结束时间后由维护流程标记为到期；
- `cancelled`：管理员提前使订阅失效。

购买上限统计该用户在此套餐下仍存在的全部订阅记录，包括已到期、已取消和管理员代绑的记录。只有删除订阅记录后，该条记录才不再占用购买次数。

## 分组升级与到期回退

如果套餐配置了升级分组，创建订阅时会立即把用户切换到该分组，并保存购买前分组。订阅到期、手动失效或删除时，系统按以下优先级处理回退：

1. 配置了明确的降级分组时，优先切换到该分组；
2. 未配置降级分组时，仅当用户当前仍处于这份订阅的升级分组，才尝试恢复购买前分组；
3. 用户仍有其他有效的升级型订阅，或当前分组已经发生其他变化时，系统可能不会立即回退。

分组切换会刷新分组缓存，但不会因为订阅变化主动撤销用户登录会话。管理员执行失效或删除前，应确认用户是否还有其他订阅以及目标分组是否仍存在。

## 支付方式与续费边界

套餐的支付按钮同时取决于全局网关配置、支付回调和套餐自身的字段。仅填写产品 ID 不代表支付已经可用。

| 方式 | 套餐侧配置与当前语义 |
| --- | --- |
| 钱包余额 | 套餐开启「余额购买」且用户余额足够时，直接扣除余额并创建一份订阅。 |
| EPay | 使用套餐价格创建支付订单，不需要单独的套餐产品 ID；还需要全局 EPay 配置可用。 |
| Stripe | 使用套餐的 Stripe Price ID，并通过 Stripe Checkout 创建支付会话；还需要全局 Stripe 密钥和 Webhook 配置。 |
| Creem | 使用套餐的 Creem Product ID；还需要全局 Creem 网关和回调配置。 |
| Waffo Pancake | 使用套餐的 Waffo Pancake Product ID；管理表单创建的是 Pancake `OnetimeProduct`，还需要全局凭证、店铺和回调配置。 |

当前实现不能描述为支持完整的自动续订：Creem、Waffo Pancake、EPay 和余额购买在本地均按一次购买创建一份订阅权益；Stripe Checkout 虽然使用 `subscription` 模式，但本地只处理首次结账完成和订单过期，没有处理 `invoice.paid` 等续费事件来延长 `UserSubscription`。

<Callout type="warn">
  Stripe 可能在第三方平台继续自动扣款，但本地订阅权益不会因此自动延长。生产环境不要把 Stripe 的订阅模式当作 New API 已实现的自动续费；如需续期，应等待项目明确支持相应事件处理，或让用户重新购买。
</Callout>

## 钱包溢出与计费偏好

用户可以在钱包页面选择「优先订阅」「优先钱包」「仅用订阅」或「仅用钱包」。套餐的「钱包溢出回退」只决定订阅额度耗尽后是否允许使用钱包，不会改变用户的计费偏好。

- 多份订阅按结束时间从近到远尝试；
- 一次请求必须由一份订阅完整承担，不会拆分到多份订阅；
- 「优先订阅」在订阅额度不足时，只有全部有效订阅都允许钱包溢出，才会回退钱包；
- 「钱包优先」在钱包不足时仍可能尝试订阅；
- 「仅用订阅」和「仅用钱包」不会切换到另一种余额来源。

完整的用户侧计费流程请参阅[钱包与订阅](/zh/docs/guide/feature-guide/user/wallet)。

## 常见问题与排查

- **用户看不到套餐**：确认套餐已启用且支付合规已确认。套餐即使没有第三方支付产品，也可能只提供余额购买；具体购买按钮还取决于套餐开关和全局网关配置。
- **支付按钮不可用**：检查对应产品 ID、全局网关凭证、Webhook/回调地址和网关要求的金额；EPay 还要求套餐金额达到其最低值。
- **管理员无法创建或编辑套餐**：确认 Root 已完成当前支付合规确认；普通 Admin 仍可查看列表，但受保护写操作会被拒绝。
- **套餐停用后用户订阅仍在生效**：这是预期行为。停用只阻止新的公开购买，不会取消既有订阅。
- **修改套餐后旧订阅没有变化**：总额度、有效期、分组和钱包溢出等字段按创建时快照运行；重置周期是例外，会读取当前套餐规则。
- **用户仍达到购买上限**：购买次数包含过期、取消和管理员代绑记录；只有删除旧订阅记录才会释放名额。
- **订阅到期后分组没有回退**：检查明确降级分组、用户当前分组以及是否存在其他有效的升级型订阅。
- **重置后额度没有按预期重新计时**：检查「推进下次重置时间」开关和套餐当前重置周期；关闭开关时只会清零已用额度。
- **Stripe 已扣款但本地期限未延长**：当前实现没有续费事件处理。保留支付订单信息并联系维护者，不要把同一笔扣款重复记账。
