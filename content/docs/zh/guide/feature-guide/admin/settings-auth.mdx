身份验证配置位于 `/system-settings/auth`，仅 Root 可访问。该工作区包含「基础认证」「OAuth」「Passkey」「机器人防护」和「自定义 OAuth」五个分区。SMTP 服务器、端口和发信凭证属于[运维设置](./settings-operations)；本页只说明邮箱验证对 SMTP 的依赖。

## 基础认证

### 开关与字段

| 字段 | 作用与边界 |
| --- | --- |
| 密码登录 | 控制是否允许使用用户名和密码登录。后端登录接口会再次检查此开关，隐藏登录入口不能替代它。 |
| 注册已启用 | 控制是否允许创建新用户。关闭后，注册接口会拒绝新注册；已经存在的用户仍可按其他已启用方式登录。 |
| 密码注册 | 控制注册流程是否接受密码注册。它受「注册已启用」共同约束。 |
| 邮箱验证 | 要求通过密码注册的新账户提交邮件验证码；配置此项前应先完成[运维设置](./settings-operations)中的 SMTP。 |
| 邮箱域名限制 | 启用后只接受白名单中的邮箱域名。当前实现只有白名单，没有单独的“拒绝列表”。 |
| 邮箱别名限制 | 启用后拒绝邮箱本地部分包含 `+` 或 `.` 的地址，例如 `user+test@example.com`。 |
| 邮箱域名白名单 | 文本框每行填写一个域名，保存时转换为逗号分隔值。启用域名限制前必须提供非空白名单。 |

用户名最长 20 个字符，邮箱最长 50 个字符，密码长度为 8–20 个字符。新注册用户创建为普通用户；管理员角色应在[用户管理](./user)中由有权限的管理员创建或调整。

### 邮箱限制的实际作用范围

当前代码在 `/api/verification` 发送邮箱验证码时检查域名白名单和邮箱别名规则；该接口既用于密码注册验证码，也可用于已登录用户的邮箱绑定验证码。不要将这两项设置理解为覆盖所有邮箱相关操作的全局拒绝策略；例如密码重置邮件请求有自己的 Turnstile 与限流流程，并未复用这两项限制。

邮箱验证关闭时，密码注册不会把请求中的邮箱写入新账户。标准 OAuth 和微信的新用户创建也不经过本节的邮件验证码、域名白名单或别名检查。

域名匹配按域名精确比较。白名单应填写 `example.com` 这类域名，不要把完整邮箱、协议、路径或通配符当作域名输入。

<Callout type="warn">
  开启邮箱验证前先确认 SMTP 能从服务端正常连接并发信。保存认证选项不会测试 SMTP；如果邮件无法送达，用户可能无法完成注册验证或找回密码。
</Callout>

## Turnstile 机器人防护

「机器人防护」分区包含以下字段：

| 字段 | 说明 |
| --- | --- |
| 启用 Turnstile | 启用后，相关匿名或敏感操作必须提交有效的 Cloudflare Turnstile 挑战令牌。 |
| Site Key | 前端渲染挑战所需的站点密钥。 |
| Secret Key | 服务端向 Cloudflare 验证令牌所需的密钥。 |

当前中间件会在以下流程检查 Turnstile：注册、密码登录、请求注册邮箱验证码、请求密码重置邮件，以及用户签到。它不只影响登录和注册页面。

启用时应同时配置 Site Key 和 Secret Key，并使用实际流程测试。通用选项保存处理器可能只对 Site Key 做基础检查；缺少 Secret Key、站点域名不匹配、令牌过期或服务端无法访问 Cloudflare，仍会在运行时导致验证失败。

<Callout type="warn">
  Turnstile Secret Key 是服务端凭证。不要把它写入首页、页脚、公告、截图或前端代码；修改后应立即验证登录、注册、验证码和密码重置等受保护流程。
</Callout>

## OAuth 集成

OAuth 分区以标签页展示内置提供商。先在提供商后台创建应用，再把凭证和回调信息填入本页，最后开启对应开关。

| 提供商 | 配置字段或特殊行为 |
| --- | --- |
| GitHub | 开关、Client ID、Client Secret。系统使用 GitHub 用户 ID 作为稳定的第三方绑定标识；修改显示名称不会改变该 ID。 |
| Discord | 开关、Client ID、Client Secret。 |
| OIDC | 开关、显示名称、Client ID/Secret、Well-Known URL，以及授权、令牌和用户信息端点。显示名称为空时使用 `OIDC`。填写 `http://` 或 `https://` 开头的 Well-Known URL 并保存时，浏览器会直接获取发现文档并自动填充端点；也可以手动填写端点。 |
| LinuxDO | 开关、Client ID、Client Secret、最低信任等级。只有达到配置阈值的 LinuxDO 账户才允许继续登录。 |
| Telegram | 开关、Bot Token、Bot Name。使用 Telegram Login Widget 与签名断言，不是标准的授权码换 token 页面；当前登录流程只接受已经绑定 Telegram 的账户，未绑定身份不会自动注册新用户。 |
| 微信 | 开关、微信登录服务地址、服务 Token、二维码图片 URL。登录时后端调用配置服务的 `/api/wechat/user?code=...` 获取用户信息，属于依赖外部服务的专用流程。 |

标准 OAuth 页面会显示当前 `ServerAddress` 推导出的主页和 `/oauth/{provider}` 回调地址。Discord 与 OIDC 的令牌交换会发送由 `ServerAddress` 生成的对应回调；GitHub 当前令牌交换不发送 `redirect_uri`；LinuxDO 则根据收到请求的协议和主机拼接 `/api/oauth/linuxdo`，与管理界面显示的地址可能不同。因此不要把所有提供商套用一个回调模板，应复制页面为当前实例生成的地址，并结合提供商要求和反向代理实际转发路径逐项核对。

### OAuth 登录与绑定流程

1. 在提供商后台登记应用名称、主页和该提供商要求的回调地址。
2. 在本页填写凭证和端点，保存后再开启提供商。
3. 用未登录窗口测试登录；用已登录的个人设置测试账户绑定。
4. 检查回调后的错误提示、用户绑定记录和服务端日志。

标准 OAuth 和绑定流程使用一次性、短时有效的认证流程令牌，当前有效期约 10 分钟；绑定令牌还会绑定发起操作的当前会话。提供商返回错误时，流程令牌也可能被消费，不能反复刷新同一个回调地址重试。

标准 OAuth 创建新用户时会检查全局注册开关；微信流程也明确检查该开关。Telegram 不提供自动注册分支，需要用户先从个人设置完成绑定。关闭某个提供商会阻止通过它发起新的登录和绑定，但不会删除历史第三方绑定；停用前应确认用户仍有密码、Passkey 或其他可用登录方式。管理员解除历史绑定请使用[用户管理](./user)。

<Callout type="warn">
  回调地址、浏览器公开地址和服务端看到的协议必须一致。HTTPS 反向代理若未正确转发 Host/Proto，可能出现回调地址错误、状态令牌失效或令牌交换被拒绝。
</Callout>

## Passkey 认证

Passkey 使用 WebAuthn。启用后，用户可以注册 Passkey 并用它登录；管理员不在此页面管理某个用户的具体凭证。

| 字段 | 说明 |
| --- | --- |
| 启用 Passkey | 开启 Passkey 注册和登录。 |
| RP 显示名称 | 在浏览器或系统 Passkey 提示中展示的可读名称。 |
| RP ID | Passkey 的有效域名。留空时尝试根据 `ServerAddress` 的主机名推导；必须与当前域名或其父域匹配。 |
| Allowed Origins | 每行填写一个允许的 Origin，保存时转换为逗号分隔值。留空时回退到 `ServerAddress`。 |
| 用户验证 | `required`（必须验证生物识别/PIN）、`preferred`（推荐验证）或 `discouraged`（不主动要求）。 |
| 设备类型偏好 | 不限、内置设备（如指纹/面容、Windows Hello）或外部设备（如 USB 安全密钥）。 |
| 允许不安全 Origin | 允许非 HTTPS Origin，仅适合开发和本地测试。开关关闭时，显式填写的 `http://` Origin 会被拒绝；仅在系统自动按当前请求推导 Origin 时，localhost 和 `127.0.0.1` 可作为本地开发例外。生产环境应关闭。 |

站点域名、协议或反向代理地址变化后，应重新检查 RP ID、Allowed Origins 和 `ServerAddress`。已注册凭证属于原域范围，配置不匹配时可能无法登录；修改配置不会自动迁移已有凭证。

Passkey 与密码登录开关彼此独立，不会自动提供密码回退。启用前应为 Root 和用户保留至少一种经过验证的替代登录方式；浏览器不支持 WebAuthn 时，前端会禁用 Passkey 入口。

管理员若需为单个用户清理 Passkey，请到[用户管理](./user)执行「重置 Passkey」。该操作会删除凭证、推进用户认证版本并撤销其现有登录会话。

## 双重验证（2FA）的边界

2FA 是用户级安全功能，不是本页的全局开关。用户在个人设置中启用和管理 2FA；管理员重置某个用户的 2FA、备用码和登录会话时，应使用[用户管理](./user)中的「重置 2FA」。

## 自定义 OAuth

自定义 OAuth 是身份验证工作区的正式分区，地址为 `/system-settings/auth/custom-oauth`。只有 Root 可以创建、编辑、启用、禁用、发现或删除提供商；普通管理员只能在具备相应用户管理权限时查看或解除用户绑定。

### 创建前准备

先在第三方提供商后台创建 OAuth 应用，并准备 Client ID、Client Secret、授权端点、令牌端点和用户信息端点。管理页提供以下创建预设：GitHub Enterprise、GitLab、Gitea、Nextcloud、Keycloak、Authentik 和 ORY Hydra。

预设只是辅助填写名称、Slug、端点、Scopes 和常见字段映射，不保证提供商可以直接连通。使用 Keycloak 预设时必须替换路径中的 `{realm}`；其他预设也应根据实际版本和部署路径逐项核对。

### 字段说明

| 字段 | 作用与边界 |
| --- | --- |
| 名称、图标、启用状态 | 决定管理页和登录入口的显示；只有启用的提供商会出现在登录页。 |
| Slug | 提供商的唯一标识，会转为小写，只允许小写字母、数字和连字符；不能与其他自定义或内置提供商冲突。 |
| Client ID / Client Secret | 创建时均为必填项。接口不会回显 Secret；编辑时留空表示保留原值，填写新值才会替换。 |
| 授权、令牌、用户信息端点 | 分别用于跳转授权、交换 Token 和读取用户资料。 |
| Scopes | 使用空格分隔，例如 `openid profile email`。 |
| 用户字段映射 | 从用户信息响应中读取用户 ID、用户名、显示名和邮箱；支持 `ocs.data.id` 这类 gjson 嵌套路径。 |
| Well-Known | 供管理页手动执行 Discovery，不会在每次登录时自动同步。 |
| Auth Style | 控制 Token 请求如何发送 Client ID 和 Client Secret。 |
| 访问策略、拒绝消息 | 根据用户信息限制允许登录的账号，并定制不满足条件时的提示。 |

用户 ID 映射必须返回稳定且非空的标识。不要使用可能变化的昵称作为用户 ID；修改映射前应检查已有账号绑定，避免同一个外部身份被识别成新用户。

### 创建、编辑与启停

1. 点击「添加 OAuth 提供商」，选择预设或从空白表单开始。
2. 填写名称、Slug、客户端凭证、三个端点和所需高级字段；保存前确认回调地址已登记。
3. 保存后，在列表中单独切换「启用」状态。只有启用并完成端点配置的提供商才会注入登录页。
4. 编辑已有提供商时，Client Secret 输入框为空表示保留原值；不要用占位符覆盖它。修改端点、字段映射或访问策略后，应重新测试登录和绑定。
5. 修改 Slug 前先更新第三方后台的回调登记；保存后旧地址不再对应当前提供商。

### 回调地址

提供商后台应登记管理页显示的地址：

```text
<ServerAddress>/oauth/<slug>
```

这是浏览器可见的回调页；`/api/oauth/<slug>` 是该页面随后调用的内部接口，不应登记到第三方提供商后台。`ServerAddress` 为空时，页面会以 `Site URL` 作为占位前缀显示 `Site URL/oauth/<slug>`，必须先配置公开站点地址再复制完整回调 URL。

浏览器发起登录时使用当前公开 Origin，后端交换 Token 时使用 `ServerAddress` 生成 `redirect_uri`。生产环境应确保浏览器公开地址、`ServerAddress` 和提供商登记地址的协议、主机、端口与路径一致。修改 Slug 会立即改变回调地址，应先同步更新提供商后台登记信息，再验证登录和绑定。

<Callout type="warn">
  生产环境使用 HTTPS，并确认反向代理正确传递 Host 和协议。回调地址不一致时，授权页面可能成功，但 Token 交换仍会因 `redirect_uri` 不匹配而失败。
</Callout>

### Discovery 与认证方式

点击 Discovery 时，管理页把完整 Well-Known URL 交给后端请求。URL 必须以 `http://` 或 `https://` 开头；后端请求超时为 20 秒，并要求返回 HTTP 200 的 JSON 文档。成功后会填充授权、令牌和用户信息端点；只有当前 Scopes 为空时，页面才会从发现结果中采用 `openid`、`profile`、`email` 中存在的常用 Scope。字段映射不会自动填写。

Discovery 只在点击按钮时辅助填表，登录运行时不会再次读取 Well-Known 文档。端点或 Scope 变化后，需要管理员重新发现或手动更新并保存。

| Auth Style | 当前行为 |
| --- | --- |
| `0` Auto Detect | 当前实现直接按请求体参数方式发送，不会根据错误响应自动改用 Basic Auth。 |
| `1` Params | 在 `application/x-www-form-urlencoded` 请求体中发送 Client ID 和 Client Secret。 |
| `2` Header | 使用 HTTP Basic `Authorization` 请求头发送凭证。 |

Token 交换固定为 POST，用户信息请求固定为 GET；两者超时均为 20 秒。用户信息端点必须返回 HTTP 200，访问令牌通过 `Authorization` 请求头发送。

### 访问策略

访问策略为空时允许所有通过该提供商完成认证的用户。非空策略使用 JSON，可通过 `and`、`or` 组合 `conditions`，也可用 `groups` 嵌套条件组。字段名是用户信息响应中的 gjson 路径。

支持的操作符：

- 比较：`eq`、`ne`、`gt`、`gte`、`lt`、`lte`；
- 集合：`in`、`not_in`，其 `value` 必须是数组；
- 包含：`contains`、`not_contains`，用于字符串子串或数组成员；
- 存在性：`exists`、`not_exists`。

示例：

```json
{
  "logic": "and",
  "conditions": [
    { "field": "email_verified", "op": "eq", "value": true },
    {
      "field": "groups",
      "op": "contains",
      "value": "new-api-users"
    }
  ]
}
```

拒绝消息支持 `{{provider}}`、`{{field}}`、`{{op}}`、`{{required}}`、`{{current}}`，以及 `{{current.path}}`、`{{required.path}}` 形式的占位符。登录错误可能直接展示渲染结果，不要在消息中输出 Token、内部权限数据或其他敏感用户资料。

### 登录、绑定与生命周期

保存并启用后，用未登录窗口测试登录，再用已登录测试用户验证账户绑定。OAuth state 当前有效期约 10 分钟；绑定 state 还会关联发起用户和会话，不能跨会话复用。

同一用户对同一自定义提供商只能保留一个绑定，同一提供商账号也不能绑定到多个本地用户。全局注册关闭时，已有绑定用户仍可登录，但未绑定的新 OAuth 用户不能自动创建本地账户。

禁用提供商只会阻止后续登录和绑定，不会删除历史绑定。删除提供商前必须先由用户在个人设置中解绑，或由有权限的管理员在[用户管理](./user)中解除全部绑定；仍有任意绑定时，删除请求会被拒绝。

> **截图建议：** 自定义 OAuth 列表、创建表单、回调地址和访问策略区域。请遮盖 Client ID、Client Secret、内部端点及用户信息样例中的敏感字段。

## 保存与凭证安全

身份验证表单通常只提交发生变化的选项，并按字段逐项保存，不是整体原子提交。密钥字段不会通过通用 `/api/option/` 读取接口回填；需要更换凭证时必须明确输入新值。

保存后按以下顺序验证：

1. 先用 Root 刷新设置页，确认非敏感字段的保存值。
2. 使用测试账户验证密码登录、注册、邮箱验证码和密码重置。
3. 对每个启用的 OAuth 提供商分别测试登录和绑定，并检查历史绑定是否符合预期。
4. 对自定义 OAuth 额外核对回调地址、字段映射、访问策略和禁用／解绑／删除流程。
5. 在支持 WebAuthn 的 HTTPS 浏览器中测试 Passkey 注册和登录。
6. 若启用了 Turnstile，重复测试所有受保护流程，而不只测试登录。

## 常见问题

- **注册开关已开但注册失败**：检查密码注册开关、邮箱验证、SMTP、白名单、别名规则和 Turnstile；再查看后端返回的具体错误。
- **邮箱白名单不生效**：确认域名限制已启用、列表非空，并且每行是精确域名而非完整邮箱或通配符。
- **密码重置仍接受被域名限制的邮箱**：当前域名/别名规则重点用于注册验证码流程，密码重置有独立的 Turnstile 与限流逻辑，不应假定两者完全相同。
- **OAuth 回调报错或状态失效**：检查 `ServerAddress`、反向代理的 Host/Proto、提供商后台回调登记和一次性流程令牌是否已过期。
- **OIDC 保存时报发现文档错误**：Well-Known URL 必须以 `http://` 或 `https://` 开头，且保存页面的浏览器必须能访问该地址；否则手动填写端点并检查网络策略。
- **自定义 OAuth 的 Auto Detect 仍交换失败**：当前 `0` 按请求体参数方式发送凭证，不会动态重试 Basic Auth；根据提供商要求明确选择 Params 或 Header。
- **自定义 OAuth 无法删除**：先在用户个人设置或用户管理中解除该提供商的全部历史绑定；禁用不会自动解绑。
- **关闭 OAuth 后用户仍显示绑定**：关闭只阻止新的登录或绑定，不会清理历史身份；需要到用户管理解除绑定。
- **Passkey 在新域名上不可用**：重新核对 RP ID、Allowed Origins、HTTPS 和 `ServerAddress`；管理员可在用户管理重置后让用户重新注册。
- **Turnstile 保存成功但所有请求仍失败**：同时检查 Site Key、Secret Key、Cloudflare 站点域名、服务端出网和令牌有效期；保存选项不会代替运行时验证。
