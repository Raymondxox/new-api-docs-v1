模型与路由配置位于 <code>/system-settings/models</code>，仅 Root 可访问。页面包含「全局模型配置」「路由可靠性」「Gemini」「Claude」「Grok」「渠道亲和」和「模型部署」七个分区。

本页负责实例级的模型协议适配、重试和可靠性策略。渠道的模型列表、模型映射、优先级、权重、自动禁用开关和上游凭证仍在[渠道管理](./channel)中配置；模型的可见信息和部署管理入口参见[模型管理](./model)。

## 保存与生效边界

多数分区只提交发生变化的配置项，并按键逐项保存，不是整页原子提交。一次保存中如果后续字段失败，前面已经成功的字段不会自动回滚。保存前应记录原值，保存后刷新页面并通过真实请求验证。

io.net API Key 等名称以 <code>Key</code>、<code>Secret</code>、<code>Token</code> 或 <code>api_key</code> 结尾的敏感选项不会通过通用设置接口回显。更换密钥时输入新值；密钥框留空通常只表示本次不更新已有密钥。

<Callout type="warn">
  模型转换、重试、自动禁用和亲和规则会直接改变生产流量。不要只根据“保存成功”判断配置可用；应使用测试 Token、指定模型和可观察的渠道日志完成小流量验证。
</Callout>

## 全局模型配置

### 请求透传

「请求透传」开启后，Relay 会在相关协议链路中把客户端原始请求体直接发送给上游，跳过许多请求体转换、字段移除、系统提示词合并和参数覆盖步骤。它不会绕过 New API 的身份验证、额度检查、渠道选择、计费和日志，也不是透明 TCP 代理。

全局透传会影响所有适用渠道；单个渠道还可以独立开启请求体透传。启用前确认客户端请求格式与目标上游完全兼容，否则可能出现上游字段不识别、模型映射与请求体不一致或供应商适配失效。

### 保留 Thinking 后缀的模型

该字段填写 JSON 字符串数组，例如：

```json
[
  "moonshotai/kimi-k2-thinking",
  "kimi-k2-thinking"
]
```

列表按去除首尾空白后的完整模型名精确匹配，不支持正则表达式。命中的模型会保留 <code>-thinking</code>、<code>-nothinking</code> 或推理等级等后缀，不参与相应的自动追加或移除处理。

这个字段虽然在内部沿用“blacklist”命名，但它不是禁用模型或关闭思考能力的黑名单。模型是否可用仍由渠道和模型配置决定。

### Chat Completions 转 Responses

该预览功能可以让命中的 Chat Completions 请求通过 Responses 兼容链路发送。策略使用 JSON，例如：

```json
{
  "enabled": true,
  "all_channels": false,
  "channel_ids": [1, 2],
  "channel_types": [1],
  "model_patterns": ["^gpt-4o.*$", "^gpt-5.*$"]
}
```

| 字段 | 作用 |
| --- | --- |
| <code>enabled</code> | 总开关。关闭时其他字段不生效。 |
| <code>all_channels</code> | 为 <code>true</code> 时允许所有渠道参与渠道匹配。 |
| <code>channel_ids</code> | <code>all_channels</code> 为 <code>false</code> 时，按渠道 ID 匹配。 |
| <code>channel_types</code> | <code>all_channels</code> 为 <code>false</code> 时，按渠道类型编号匹配。 |
| <code>model_patterns</code> | 正则表达式数组；请求模型至少命中一项才转换。 |

请求必须同时满足总开关、渠道范围和模型正则表达式。全局请求透传或目标渠道的请求体透传开启时，不会进入该转换链路。无效的模型正则表达式在运行时按不匹配处理，因此保存 JSON 成功并不代表每条正则表达式有效。

<Callout type="info">
  这是实验性兼容策略，配置格式和行为可能调整。先限定少量渠道和模型验证工具调用、流式输出、用量统计及错误响应，再逐步扩大范围。
</Callout>

### 流式 Keep-alive Ping

开启后，系统在适用的流式连接中按配置秒数向下游客户端写入保活帧，降低代理或客户端因长时间没有数据而断开连接的概率。

它不是渠道健康检测、上游请求重试或模型心跳，也不能保证所有代理都接受该帧。Gemini 原生 SSE 等明确禁止自定义 Ping 的链路会跳过此设置。间隔必须大于等于 1 秒；生产环境应结合反向代理和客户端超时设置选择足够保守的值。

## 路由可靠性

### 请求重试

「重试次数」可填写 0–10，表示首次请求失败后最多再尝试的次数，因此总尝试次数最多为 <code>1 + 重试次数</code>。重试会重新选择满足分组、模型和请求路径条件的渠道；渠道优先级和权重仍由[渠道管理](./channel)决定。

「自动重试状态码」接受逗号分隔的单个状态码或闭区间，例如：

    401,403,429,500-503

默认规则覆盖 <code>100-199</code>、<code>300-399</code>、<code>401-407</code>、<code>409-499</code>、<code>500-503</code>、<code>505-523</code> 和 <code>525-599</code>。<code>504</code>、<code>524</code> 以及无法可靠读取上游响应体的错误始终跳过状态码重试。

状态码命中只是允许重试的条件之一，不保证一定重试。以下情况也可能直接结束请求：

- 重试次数已经耗尽；
- Token 指定了固定渠道；
- 错误被标记为不可重试；
- 命中的渠道亲和规则要求亲和渠道失败后不重试；
- 找不到其他满足模型、分组和路径要求的渠道。

### 自动禁用

自动禁用同时受全局开关和渠道自身「自动禁用」选项约束。只有两者都开启，满足自动禁用条件的渠道才会进入自动禁用状态。

| 字段 | 行为 |
| --- | --- |
| 自动禁用状态码 | 接受与重试状态码相同的单值和区间格式，默认只包含 <code>401</code>。 |
| 失败关键词 | 每行一个关键词；上游错误文本包含任一关键词时匹配，不区分大小写。 |
| 响应时间阈值 | 单位为秒，只在渠道测试流程中比较测试耗时，不会检查每一次真实业务请求。填写 0 相当于不按测试耗时禁用。 |

真实 Relay 请求仍会根据渠道错误、状态码和关键词判断是否自动禁用，但不会使用响应时间阈值。自动禁用会记录原因并通知 Root；多密钥渠道还可能只更新发生错误的密钥状态。

### 自动恢复与计划测试

「成功后重新启用」只恢复处于自动禁用状态的渠道，不会恢复 Root 或 Admin 手动禁用的渠道。恢复依赖一次成功的渠道测试，并且需要开启自动恢复开关。

计划测试提供三种模式：

| 模式 | 测试范围 |
| --- | --- |
| 主动检查所有渠道 | 测试除手动禁用外的渠道，可检测故障并恢复自动禁用渠道。 |
| 主动检查已开启自动禁用的渠道 | 只测试开启渠道级自动禁用且未被手动禁用的渠道。 |
| 仅检查等待恢复的渠道 | 只测试自动禁用渠道，不对健康渠道执行定时探测，也不会在本轮继续禁用其他渠道。 |

测试间隔最小为 1 分钟。环境变量 <code>CHANNEL_TEST_FREQUENCY</code> 可强制启用全量计划测试并指定分钟数，<code>CHANNEL_TEST_ENABLED</code> 可覆盖是否启用；部署环境设置了这些变量时，管理页面保存值可能不是最终运行值。

## Gemini

Gemini 分区控制 Gemini 和部分 Vertex 转换链路使用的实例级默认行为。

| 字段 | 格式与作用 |
| --- | --- |
| 安全设置 | JSON 字符串映射。按安全类别精确取值，未配置时回退到 <code>default</code>，再回退到 <code>OFF</code>。 |
| API 版本覆盖 | JSON 字符串映射。按上游模型名精确匹配，未命中时使用 <code>default</code>。 |
| 支持 Imagine 的模型 | JSON 字符串数组。命中的上游模型在 OpenAI Chat/Responses 转 Gemini 时加入 <code>TEXT</code> 和 <code>IMAGE</code> 输出模态。 |
| Thinking 后缀适配 | 识别 <code>-thinking</code>、<code>-thinking-预算</code>、<code>-nothinking</code> 等后缀，并转换为对应 Gemini 思考配置。 |
| Budget Tokens 比例 | 思考预算按最大输出 Token 乘以该比例估算，可填写 0.002–1，默认 0.6。 |
| 补全 FunctionCall thoughtSignature | 在 Gemini/Vertex 渠道使用 OpenAI 格式时补全相应签名，默认开启。 |
| 移除 <code>functionResponse.id</code> | 为不接受该字段的 Vertex 路径移除它，默认开启。 |

安全设置示例：

```json
{
  "default": "OFF",
  "HARM_CATEGORY_DANGEROUS_CONTENT": "BLOCK_ONLY_HIGH"
}
```

可用阈值包括 <code>OFF</code>、<code>BLOCK_NONE</code>、<code>BLOCK_ONLY_HIGH</code>、<code>BLOCK_MEDIUM_AND_ABOVE</code>、<code>BLOCK_LOW_AND_ABOVE</code> 和 <code>HARM_BLOCK_THRESHOLD_UNSPECIFIED</code>。

版本覆盖示例：

```json
{
  "default": "v1beta",
  "gemini-1.0-pro": "v1"
}
```

「支持 Imagine 的模型」只改变协议转换时的输出模态，不会自动添加模型、价格或渠道能力。模型名应填写模型映射后的上游名称，并通过实际图片输出请求确认供应商是否支持。

关闭 Thinking 后缀适配只关闭该后缀适配规则，不等于禁止客户端提交原生 Gemini 思考配置，也不保证供应商模型关闭思考。全局请求透传或渠道透传还可能绕过相应请求体转换。

## Claude

### 请求头覆盖

请求头覆盖使用“原始请求模型 → 请求头 → 值数组”的 JSON 结构，例如：

```json
{
  "claude-3-7-sonnet-20250219-thinking": {
    "anthropic-beta": ["output-128k-2025-02-19"]
  }
}
```

模型名按原始请求模型精确匹配，没有 <code>default</code> 回退。配置值会与已有同名请求头合并、去重后发送；不要在此保存 API Key、Authorization 或其他用户凭证。

### 默认最大输出 Token

当 Claude 请求未提供 <code>max_tokens</code> 或值为 0 时，系统先按请求模型精确查找，再使用 <code>default</code>：

```json
{
  "default": 8192,
  "claude-3-haiku-20240307": 4096
}
```

值必须是非负整数。建议始终保留 <code>default</code>；缺失时运行时会补回 8192。这个默认值不会扩大上游模型本身的上下文或输出上限，超出供应商限制仍会被上游拒绝。

### Thinking 后缀适配

开启后，带 <code>-thinking</code> 后缀的 Claude 请求可转换为 Anthropic 原生思考参数，并按 <code>max_tokens × 比例</code> 设置思考预算。比例可填写 0.1–1，默认 0.8。

部分 Claude Opus 推理等级后缀有单独的自适应思考处理；不要把本开关理解为所有 Claude 推理行为的总开关。请求透传开启时，原始请求体会直接发送，以上转换也不应作为上游兼容保证。

## Grok

Grok 分区用于配置特定使用规范违规错误的额外扣费策略：

| 字段 | 行为 |
| --- | --- |
| 启用违规扣费 | 是否在识别到受支持的违规错误标记后收取额外额度，默认开启。 |
| 违规扣费金额 | 以系统美元基准填写非负数，默认 0.05。 |

当前实现只在错误中识别到特定安全检查或“Content violates usage guidelines”标记时触发。普通上游错误、内容审核失败或所有 Grok 请求不会因此自动额外扣费；此类错误还会标记为不可重试。

实际扣除额度按“基础金额 × <code>QuotaPerUnit</code> × 当前计费分组倍率”计算并取整。正常预扣额度会先按失败流程处理，违规费再作为一条独立消费记录写入日志，因此排查时应同时查看原请求错误和违规费日志。

<Callout type="warn">
  该设置涉及用户余额。启用或调整金额前，应核对上游最新违规收费规则、分组倍率和面向用户的价格说明，并用可控测试验证日志和额度变化。
</Callout>

## 渠道亲和

渠道亲和会根据请求中的稳定标识复用最近一次成功的渠道，适合会话缓存、CLI 线程或需要保持上游状态的请求。

### 匹配顺序

规则按列表顺序检查。第一条同时满足模型、路径、User-Agent、Key 来源和值正则的规则会建立本次亲和上下文；即使该规则当前没有缓存命中，也不会继续尝试后面的规则，因此应把更具体的规则放在前面。

每条规则至少需要一个模型正则表达式和一个有效 Key 来源。路径正则和 User-Agent 包含条件可以留空。

Key 来源按配置顺序取第一个非空值：

| 类型 | 取值位置 |
| --- | --- |
| <code>context_int</code> | Gin 请求上下文中的正整数，例如用户或 Token ID。 |
| <code>context_string</code> | Gin 请求上下文中的字符串。 |
| <code>request_header</code> | 指定 HTTP 请求头。 |
| <code>gjson</code> | 使用 GJSON 路径从 JSON 请求体读取，例如 <code>metadata.user_id</code>。 |

可选的值正则会再次校验提取结果。规则 TTL 为 0 时使用全局默认 TTL；全局值无效时运行时回退到 3600 秒。

### 缓存键与隔离

「包含使用分组」「包含模型名」「包含规则名」只决定这些字段是否加入缓存键。关闭某项会扩大缓存复用范围，也可能使不同分组、模型或规则共用同一个 Key，因此修改前应确认隔离要求。

启用 Redis 时亲和缓存可在连接同一 Redis 的实例间共享；未启用 Redis 时使用当前进程内存缓存，多实例之间不共享。最大条目数限制内存缓存容量，超出后按缓存淘汰策略清理。

按规则清空缓存要求该规则启用「包含规则名」；否则缓存键无法可靠归属到某一规则。修改规则、Key 结构或模型范围后，建议清除旧缓存，避免等待 TTL 自然过期。

### 渠道可用性与重试

命中缓存后，系统仍会检查渠道是否启用、是否支持当前模型和分组，以及高级自定义渠道是否支持当前请求路径。缓存渠道不可用时会回到普通选路：

- 「渠道禁用时保留亲和」关闭：删除当前缓存，再选择其他渠道；
- 该选项开启：保留缓存，但本次仍选择其他可用渠道，不会强制请求已禁用渠道。

「失败时跳过重试」只在本次确实使用了亲和缓存渠道后生效；缓存未命中时的普通选路不受它直接约束。开启「成功后切换亲和」后，如果亲和渠道失败而其他渠道重试成功，缓存会更新为最终成功渠道。

页面提供 Codex CLI 和 Claude CLI 模板。模板会预填模型、路径、Key 来源和请求头透传参数；它们只是可编辑的起点，保存前应核对客户端版本、请求字段和需要透传的请求头。不要在模板中加入认证密钥或不可信的任意请求头。

## io.net 模型部署

当前模型部署集成只支持 io.net。Root 在「模型部署」分区开启服务并配置 io.net API Key；页面建议创建或选择 Project 为 <code>io.cloud</code> 的密钥。

「测试连接」优先使用当前输入框中的未保存 Key；输入框为空时，后端会尝试使用已经保存的 Key。测试成功只表示凭证能够访问当前测试接口，不代表特定硬件、区域、余额或容器镜像一定可用。

启用并保存后，Admin 和 Root 可以在模型管理的「部署」标签中查看、创建、更新、延长或终止 io.net 部署，并检查容器、日志、位置、硬件和价格估算等信息。

启用开关不会自动：

- 创建 io.net 部署；
- 购买或预留硬件资源；
- 创建 New API 渠道；
- 把部署端点绑定到模型或渠道；
- 承担或限制 io.net 产生的外部费用。

部署完成后仍需根据 io.net 返回的公网端点，在[渠道管理](./channel)中手动创建或调整相应渠道，并配置模型、分组、价格和健康检查。删除 New API 中的模型或渠道也不会自动终止 io.net 资源。

<Callout type="warn">
  创建、延长和终止部署会改变第三方资源和费用。执行前核对 io.net 账户、区域、GPU 数量、持续时间、价格估算和终止状态；New API 不能保证第三方容量、账单或部署成功率。
</Callout>

## 变更后验证

建议按以下顺序验证：

1. 刷新当前分区，确认非敏感字段显示为预期值。
2. 使用测试 Token 发送一个非流式请求和一个流式请求，检查模型映射、上游请求格式、用量和日志。
3. 使用可控的失败渠道验证重试次数、状态码、自动禁用原因和自动恢复；不要在生产高峰直接制造大量失败。
4. 为亲和规则准备固定 Key，连续请求并检查渠道 ID、缓存统计和重试后的缓存切换。
5. 分别验证 Gemini、Claude 或 Grok 的实际适配场景，不要只验证 JSON 能保存。
6. io.net 先测试连接和价格估算，再创建最小部署；部署完成后单独验证渠道配置。

系统没有本页专用的配置快照或一键回滚。异常时应根据变更记录逐项恢复原值，清除受影响的亲和缓存，并重新验证。

## 常见问题

- **策略 JSON 保存成功但 Chat Completions 没有转为 Responses**：检查 <code>enabled</code>、渠道范围和模型正则是否同时命中，并确认全局及渠道请求透传均已关闭。
- **Thinking 列表中的模型仍可调用**：该列表只保留模型后缀，不禁用模型；要限制调用应修改渠道、模型或 Token 权限。
- **配置了重试状态码却没有重试**：检查重试次数、固定渠道、不可重试错误、亲和规则和其他可用渠道；状态码不是唯一条件。
- **渠道因响应慢被禁用，但真实请求没有超过阈值记录**：响应时间阈值只用于渠道测试耗时，不逐个监控真实业务请求。
- **手动禁用的渠道没有自动恢复**：自动恢复只处理自动禁用状态。手动禁用渠道必须由有权限的管理员显式启用。
- **计划测试模式与页面设置不同**：检查部署环境中的 <code>CHANNEL_TEST_FREQUENCY</code> 和 <code>CHANNEL_TEST_ENABLED</code>。
- **Gemini 图片模型只返回文字**：确认「支持 Imagine 的模型」填写的是映射后的精确上游模型名，并核对供应商、渠道和请求协议是否支持图片输出。
- **Claude 请求头覆盖没有生效**：模型键按原始请求模型精确匹配；检查模型后缀、JSON 值数组和请求透传设置。
- **亲和缓存命中后仍选择其他渠道**：缓存渠道仍必须满足启用状态、模型、分组和路径要求；保留缓存也不会强制使用不可用渠道。
- **按规则无法清空亲和缓存**：该规则必须启用「包含规则名」。否则只能清空全部缓存或等待 TTL 到期。
- **io.net 开关已启用但部署页不可用**：确认 API Key 已保存、连接测试成功、当前账户至少为 Admin，并检查 io.net 账户权限和网络连接。
- **部署已创建但模型请求没有使用它**：部署不会自动创建或绑定 New API 渠道；需要使用部署端点手动配置渠道和模型。
