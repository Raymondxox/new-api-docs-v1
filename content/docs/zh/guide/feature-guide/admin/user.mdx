管理员从侧边栏进入「用户」，或访问 `/users` 查看用户列表。该页面要求 Admin 或 Root；普通 Admin 只能管理普通用户，Root 可以管理普通用户和 Admin。任何操作者都不能通过普通用户管理流程操作同级或更高角色的账户。

## 搜索、筛选和排序

用户列表可以显示 ID、用户名与显示名称、管理员备注、状态、剩余和已用额度、分组、角色、邀请统计、创建时间及最后登录时间。已软删除的用户也可能出现在列表中，但不会再显示行操作。

| 功能 | 说明 |
| --- | --- |
| 关键词搜索 | 匹配用户名、邮箱和显示名称；关键词为纯数字时还会精确匹配用户 ID。 |
| 分组筛选 | 按一个用户分组精确筛选。 |
| 角色筛选 | 按普通用户、Admin 或 Root 筛选。 |
| 状态筛选 | 按启用、禁用或已删除筛选。 |
| 排序 | 支持按 ID、用户名、剩余额度、分组、创建时间或最后登录时间升序/降序排列。 |

未选择排序字段时，后端默认按 ID 倒序返回。页面使用服务端分页、筛选和排序，因此排序会先应用到完整查询结果，再进行分页。

## 创建用户

1. 点击「添加用户」。
2. 填写用户名和 8–20 位密码。
3. 按需填写显示名称；留空时会使用用户名。
4. 选择角色并保存。

创建表单可选择普通用户或 Admin，但最终仍受操作者角色限制：Admin 只能创建普通用户；Root 可以创建普通用户或 Admin，不能创建另一个 Root。用户名和显示名称最长 20 个字符。

创建接口只接收表单中的用户名、密码、显示名称和角色。新用户会使用实例配置的新用户初始额度、默认分组和默认侧边栏设置；若要调整分组、额度或备注，应在创建成功后编辑该用户。

<Callout type="info">
  Root 创建 Admin 时可以同时设置当前后端权限目录中的 Admin 权限覆盖。普通 Admin 无权设置这类覆盖。
</Callout>

## 编辑用户资料

打开用户行的「编辑」，可以维护以下内容：

- 显示名称；
- 密码，留空表示不修改；
- 用户分组；
- 仅管理员可见的备注；
- Admin 权限矩阵，仅 Root 编辑 Admin 时显示。

当前编辑抽屉中的用户名为只读，角色也不能在编辑表单中修改。剩余额度显示为只读值，需要使用独立的「调整额度」操作；第三方绑定在编辑抽屉中只作摘要展示，需要从行菜单进入「管理绑定」处理。

修改密码或分组会推进账户的认证版本，并撤销该用户当前的登录会话。保存后，用户需要重新登录；已有 API 密钥是否继续可用，还取决于新的账户状态、分组和密钥自身限制。

## 角色、状态和权限

### 管理层级

| 操作者 | 可管理的目标 |
| --- | --- |
| Admin | 普通用户。 |
| Root | 普通用户和 Admin。 |

用户行菜单提供启用、禁用、提升和降级操作：

- **启用 / 禁用**：切换账户状态。Root 不能被禁用。
- **提升**：只有 Root 可以把普通用户提升为 Admin。
- **降级**：把 Admin 降为普通用户；Root 不能被降级。

状态或角色变化会更新认证状态，并使已有登录会话失效。Admin 被降级时，系统还会清除该账户的细粒度权限覆盖。

### Admin 权限矩阵

只有 Root 可以编辑 Admin 权限矩阵。当前后端权限目录主要为渠道资源提供以下动作：

| 权限 | 用途 |
| --- | --- |
| `read` | 查看渠道列表和不含完整密钥的详情。 |
| `operate` | 测试、刷新余额以及启用或禁用渠道。 |
| `write` | 编辑模型、分组和路由等普通配置。 |
| `sensitive_write` | 创建渠道或修改密钥、Base URL、覆盖规则等敏感配置。 |
| `secret_view` | 为完整密钥查看保留的独立能力；实际接口还可能要求 Root 和安全验证。 |

普通 Admin 的默认基线包含 `read`、`operate` 和 `write`，不默认包含 `sensitive_write` 与 `secret_view`。不要把这套渠道权限矩阵理解为所有管理员资源都已经具备相同的细粒度动作；用户、模型和订阅等接口仍按各自的角色与后端规则授权。

更多渠道权限和敏感操作说明请参阅[渠道管理](/zh/docs/guide/feature-guide/admin/channel)。

## 调整额度

在用户编辑抽屉中点击「调整额度」，选择操作模式并输入金额：

| 模式 | 行为 |
| --- | --- |
| 增加 | 在当前剩余额度上增加指定值。 |
| 扣减 | 从当前剩余额度中扣除指定值。 |
| 覆盖 | 直接把剩余额度设置为输入值。 |

对话框会按照实例配置的货币或 Token 显示单位，并预览调整后的结果。该操作只改变用户的剩余额度，不会重置累计已用额度或请求次数。

<Callout type="warn">
  扣减或覆盖前应核对当前余额、显示单位和预览结果。额度调整会写入管理审计；不要把页面显示的货币换算理解为所有实例通用的固定汇率。
</Callout>

## 管理登录绑定

从用户行菜单进入「管理绑定」，可以查看内置登录方式和自定义 OAuth 的绑定状态，并切换显示「仅已绑定」或全部提供商。

管理员可以解除以下已经存在的绑定：

- 邮箱；
- GitHub、Discord、OIDC、微信、Telegram 和 LinuxDO；
- Root 配置的自定义 OAuth 提供商。

该对话框只能解除绑定，不能替用户绑定新的账号。系统未启用的提供商仍可能作为历史绑定显示；解除后，用户不能再用该身份登录。

<Callout type="warn">
  解除绑定前先确认用户仍有密码、Passkey 或其他可用登录方式。管理绑定流程不会自动替用户建立新的恢复方式。
</Callout>

## 重置 Passkey 与 2FA

用户行菜单提供「重置 Passkey」和「重置 2FA」：

- 重置 Passkey 会删除该用户现有的 Passkey 凭证，用户需要重新注册后才能再次使用无密码登录。
- 重置 2FA 会删除现有的双重验证配置及备用码，用户需要重新设置 2FA。

两项操作都要求操作者能管理目标角色；普通 Admin 不能操作 Admin 或 Root。成功重置会更新认证状态并撤销目标用户的全部登录会话。若目标尚未配置对应的安全方式，接口会返回失败提示。

## 管理用户订阅

从用户行菜单进入「管理订阅」，可以查看该用户的订阅状态、有效期、来源和额度使用情况，并执行以下操作：

| 操作 | 说明 |
| --- | --- |
| 添加订阅 | 从现有套餐中为用户创建一份管理员代绑订阅；需要实例已确认支付合规，并遵守套餐的用户购买上限。 |
| 重置额度 | 将该用户指定套餐下仍有效的活动订阅已用额度清零；可以选择是否推进下一次重置时间。 |
| 失效 | 立即把订阅标记为已取消并结束，保留历史记录，且可能按套餐规则回退用户分组。 |
| 删除 | 永久删除该订阅记录及其权益明细，也可能触发套餐配置的分组回退。 |

添加订阅会使用当前套餐配置创建权益快照，可能立即把用户切换到套餐的升级分组。这里不能修改套餐价格、期限或总额度；套餐本身应在订阅管理页面维护。

<Callout type="warn">
  「失效」与「删除」含义不同：失效保留历史记录，删除则移除订阅记录。操作前应核对用户、套餐、当前状态和分组变化。
</Callout>

## 删除用户

当前用户列表中的「删除」会执行永久删除，不是禁用或软删除。只有角色高于目标的操作者可以执行，Root 账户不能通过此流程删除。

永久删除会清理用户主记录，以及系统明确关联的认证和凭证数据，包括：

- API 密钥；
- 登录会话和认证流程；
- Passkey；
- 2FA 配置与备用码；
- 内置第三方身份占用记录；
- 自定义 OAuth 绑定。

<Callout type="warn">
  永久删除不可撤销。当前删除链路没有承诺一并删除使用日志、支付订单、任务、订阅或其他业务记录；如需满足数据保留或隐私要求，应在删除前制定单独的数据审计和清理方案。
</Callout>

禁用账户是可恢复的状态变更，适合临时阻止登录和调用；列表也能识别历史软删除记录，但当前页面不会为这类记录提供恢复或其他行操作。不要把这三种状态混为一谈。

## 常见问题

- **无法编辑某个用户**：确认操作者角色高于目标。Admin 不能管理另一个 Admin，只有 Root 可以管理 Admin。
- **无法创建 Admin**：只有 Root 可以创建或提升 Admin；任何人都不能从该页面创建 Root。
- **保存后用户被退出登录**：密码、分组、状态、角色、Passkey 或 2FA 等认证敏感变化会撤销现有会话。
- **权限矩阵只有渠道项**：权限目录由后端注册；当前细粒度矩阵主要覆盖渠道操作，不代表其他资源缺失角色校验。
- **解除绑定后用户无法登录**：管理员解绑不会自动创建替代登录方式，需由 Root 或用户通过仍可用的方式恢复账户。
- **订阅添加失败**：检查支付合规状态、套餐状态、用户购买上限和套餐分组规则。
- **删除后仍有业务记录**：永久删除明确清理账户认证数据，但不等同于清空所有日志、订单、任务和订阅数据。
