站点与品牌配置位于 `/system-settings/site`，仅 Root 可访问。进入该地址时默认打开「系统信息」，还可以切换到「系统公告」「顶部导航」和「侧边栏模块」。

## 系统信息

### 基础字段

| 字段 | 行为与用途 |
| --- | --- |
| 系统名称 | 必填，显示在站点标题、认证页面和其他品牌位置。 |
| 服务器地址 | 面向浏览器和第三方服务的站点根地址，用于生成 OAuth 回调、Webhook 等地址。保存时会移除结尾的 `/`，但当前表单不严格验证它是否为可用 URL。 |
| Logo URL | 接受完整 URL 或空值。前端会预加载图片，并尝试把它用作 favicon；加载失败通常只影响品牌图片显示。 |
| 页脚 | 自定义页脚 HTML，显示在页面底部。其安全边界与其他内容字段不同，见下方警告。 |
| 关于页 | 可填写 HTTP(S) URL、HTML 或 Markdown，决定「关于」页面的内容。 |
| 首页内容 | 可填写 HTTP(S) URL、HTML 或 Markdown。非空时替换内置首页内容；清空后恢复内置首页区块。 |
| 用户协议、隐私政策 | 各自支持完整 URL、HTML 或 Markdown；清空相应字段会关闭该文档入口和同意要求。 |

`ServerAddress` 应填写用户实际访问的公网根地址，例如 `https://api.example.com`，不要附加 `/api` 或 OAuth 路径。反向代理部署时还要确保浏览器访问协议、代理转发协议和第三方后台登记地址一致。

### 内容渲染方式

关于页和首页内容按输入类型选择展示方式：

| 输入 | 展示方式 |
| --- | --- |
| 以 `http://` 或 `https://` 开头的完整 URL | 使用带沙箱限制的 iframe 嵌入。远端站点仍可能因 `X-Frame-Options`、CSP、证书或混合内容策略而拒绝显示。 |
| 可识别的 HTML | 经 DOMPurify 净化后，在隔离的 Shadow DOM 中渲染；其中的 iframe 还会受到沙箱和 referrer 限制。脚本或危险属性可能被移除。 |
| 其他文本 | 按 Markdown 渲染，并进行相应的内容净化。 |

用户协议和隐私政策也支持 HTML 与 Markdown；如果填写完整 HTTP(S) URL，页面会提供外部打开入口，而不是把法律文档嵌入站内 iframe。

首页内容会在浏览器侧缓存。保存后若仍看到旧首页，可以刷新页面或清理该站点的 `home_page_content` 本地缓存后再验证。

<Callout type="warn">
  页脚当前直接作为 HTML 插入页面，没有经过关于页和首页内容使用的同一套 DOMPurify 净化流程。只应粘贴由可信 Root 审核的静态 HTML，不要加入不可信脚本、事件属性或第三方注入代码。
</Callout>

### 法律文档

用户协议或隐私政策字段非空后，登录、注册和页脚会提供相应入口；认证页面还会要求用户勾选同意已配置的文档。清空某一字段会停用对应入口和要求。

该功能用于发布当前内容或外部链接，不是法律版本、签署记录或历史留存系统。如果需要可审计的协议版本和再次同意机制，应在 New API 之外建立相应流程。

### 公开内容边界

站点状态、系统公告、关于页、首页内容、用户协议和隐私政策可通过公开接口读取，包括 `/api/status`、`/api/notice`、`/api/about`、`/api/home_page_content`、`/api/user-agreement` 和 `/api/privacy-policy`。

<Callout type="warn">
  这些字段面向未登录访问者。不要写入 API Key、客户端密钥、内网地址、内部管理员资料或任何不应公开的信息。
</Callout>

## 系统公告

「系统公告」分区保存 `Notice` 内容，没有独立的启用开关。内容非空时，前端通过公开的 `/api/notice` 接口读取并显示在通知中心；清空内容即可停止发布。

浏览器以完整的、去除首尾空白后的公告内容记录已读状态。修改标题、标点或正文都会形成新的内容，用户可能再次看到未读提示。

本分区的系统公告与「控制台内容 → 结构化公告」是两套配置：前者是一段全局通知内容，后者管理可启停的结构化公告列表，不应互相替代。

## 顶部导航

顶部导航只控制内置入口，不支持自定义标题、任意链接或拖动排序。

| 入口 | 可配置行为 |
| --- | --- |
| 首页、控制台、文档、关于 | 显示或隐藏。 |
| 模型广场、排行榜 | 显示或隐藏，并可要求登录后才能访问。 |

文档入口的目标地址来自「[计费与支付配置](./settings-billing) → 额度设置」中的文档链接。前端运行时值为空时使用站内 `/docs`；源码还提供默认文档地址，因此最终应以实例当前读取到的配置值为准。

隐藏顶部入口只改变导航展示，不等同于关闭对应后端能力。需要限制访问时，还应检查该页面自身的认证中间件和公开接口。

## 侧边栏模块

侧边栏按区域和模块控制内置入口是否显示：

| 区域 | 当前内置模块 |
| --- | --- |
| 聊天 | Playground、聊天。 |
| 控制台 | 数据看板、API 令牌、使用日志、绘图日志、任务日志。 |
| 个人中心 | 钱包、个人设置。 |
| 管理员 | 渠道、模型、兑换码、用户、系统设置、订阅管理。 |

关闭整个区域会同时隐藏该区域下的模块；重新打开后，各模块仍按自身开关决定是否显示。页面提供「恢复默认」，但该按钮先把表单恢复为代码中的默认组合，仍需保存才能写入服务端。

全局侧边栏配置决定模块是否可展示；拥有个人侧边栏设置权限的用户还可以在全局允许范围内进一步隐藏自己的非管理员模块。Root 不应用这层个人隐藏覆盖。

<Callout type="info">
  隐藏侧边栏入口不会授予或撤销角色权限，也不保证直接访问路由一定被阻止。真实访问能力仍由账户角色、前端路由守卫和后端接口权限共同决定。
</Callout>

## 保存与检查

1. 修改前记录当前值，特别是服务器地址、法律内容和导航开关。
2. 保存系统信息后分别检查首页、关于页、登录、注册、页脚和浏览器标签图标。
3. 保存公告后使用未登录窗口和已登录账户检查公开内容与未读提示。
4. 保存导航设置后分别使用普通用户、Admin 和 Root 检查入口；再直接访问相关路由确认权限。
5. 多实例部署时为其他节点预留选项同步时间。

## 常见问题

- **Logo 或 favicon 没有更新**：确认图片 URL 可由浏览器公开访问，并清理浏览器 favicon 缓存；图片失败不代表 API 服务失败。
- **首页仍显示旧内容**：刷新页面，并检查浏览器中的首页内容缓存。清空首页字段才会恢复内置首页。
- **外部 URL 无法嵌入**：检查目标站点的 `X-Frame-Options`、CSP、HTTPS 证书和混合内容限制；New API 无法绕过远端禁止嵌入的策略。
- **HTML 中的脚本或样式失效**：关于页、首页和法律正文会经过净化或隔离，不保证执行任意脚本。页脚虽然边界不同，也不应依赖动态脚本。
- **登录或注册要求勾选协议**：只要相应法律字段非空，认证页面就会显示入口和同意要求；不需要时清空并保存。
- **公告更新后再次显示未读**：已读状态与完整公告内容绑定，任何内容变化都可能被视为新公告。
- **菜单隐藏后仍能通过地址访问**：导航开关控制可见性，不改变路由和后端授权；按具体功能的权限规则判断是否应允许访问。
- **找不到文档入口的链接字段**：到「计费与支付 → 额度设置」修改文档链接，而不是在顶部导航分区填写。
