管理员从侧边栏进入「模型」，或访问 `/models/metadata`。页面包含「元信息」和「部署」两个标签。模型管理页维护的是平台模型目录；渠道中的实际模型、分组和路由仍由[渠道管理](/zh/docs/guide/feature-guide/admin/channel)页面维护。

## 权限与数据关系

模型元信息、供应商、预填充组和部署接口要求 Admin 或 Root。价格和倍率字段虽然会在模型编辑抽屉中显示，但实际保存到系统选项，相关选项接口当前要求 Root；普通 Admin 可以编辑模型元信息，却不能可靠保存这些计费选项。

模型记录中的绑定渠道、启用分组、计费类型和匹配模型是根据渠道能力与计费配置计算出的派生信息，不是模型表单中独立保存的字段。

## 模型元信息

### 查看、搜索和筛选

列表可按关键词搜索模型名称、描述或标签，并按供应商、状态和「官方同步」状态筛选。行操作支持编辑、启用/禁用和删除；批量操作支持启用、禁用、复制模型名称和删除。

模型详情可能显示以下信息：

| 字段 | 说明 |
| --- | --- |
| 模型名称 | 用户请求、渠道映射和定价展示使用的标识。 |
| 描述、图标、标签 | 用于模型目录和控制台展示。 |
| 供应商 | 关联供应商元信息，可在模型编辑器中选择。 |
| 端点 | JSON 格式的能力/入口描述，参与模型能力展示和端点推导。 |
| 状态 | 控制模型元信息是否启用。 |
| 官方同步 | 控制该模型是否允许官方元数据覆盖；关闭后同步会跳过该模型。 |
| 名称匹配规则 | 精确、前缀、包含或后缀匹配。 |

### 新建和编辑

1. 点击「添加模型」，或打开已有模型的编辑操作。
2. 填写模型名称；名称必须非空，并注意已有客户端、渠道模型列表和映射中的引用。
3. 按需填写描述、图标、标签、供应商和端点 JSON。
4. 选择名称匹配规则、状态和官方同步开关。
5. 保存后检查模型列表及其绑定渠道信息。

模型编辑器中的价格/倍率区域是计费选项的便捷入口，并不改变上述元信息存储关系。若模型名称发生变化，编辑器只会迁移该名称对应的部分价格/倍率键，不会自动改写渠道模型列表或模型映射；重命名前应先协调渠道配置。

## 名称匹配和端点

### 名称匹配规则

模型名称规则有四种：

| 规则 | 匹配方式 |
| --- | --- |
| 精确 | 只匹配完全相同的模型名称。 |
| 前缀 | 匹配以该名称开头的模型。 |
| 包含 | 匹配名称中包含该字符串的模型。 |
| 后缀 | 匹配以该名称结尾的模型。 |

使用非精确规则时，一个模型元信息可能汇总多个渠道模型、端点和分组。规则不会把渠道中每个具体名称都写入模型表，也不能保证「缺失模型」列表因此为空。

### 端点 JSON

端点字段描述模型可用的 API 入口或能力，例如聊天、Responses、图像或音频入口。它不是渠道 Base URL，也不会单独创建上游渠道；未填写时，系统可能根据已绑定渠道和高级自定义路由推导可用端点。填写后应先验证 JSON，再检查模型详情中的端点展示。

## 价格与倍率

模型编辑器可以展示并编辑以下按模型名称保存的计费字段：固定按请求价格、模型倍率、输入/输出倍率、缓存倍率、图片倍率和音频输入/输出倍率。它们对应系统选项 `ModelPrice`、`ModelRatio`、`CompletionRatio`、`CacheRatio`、`ImageRatio`、`AudioRatio` 和 `AudioCompletionRatio`。

固定按请求价格与倍率同时存在时，计费链优先使用固定价格。按 Token 的输入/输出价格会由界面换算为倍率，最终额度仍受 `QuotaPerUnit`、分组倍率、工具价格和其他计费设置影响，不能把界面换算值当作所有实例的固定汇率。

<Callout type="warn">
  价格和倍率的保存接口是 Root 专属。普通 Admin 保存模型时，元信息可能已经成功而计费选项更新失败；遇到这种情况应让 Root 在系统设置中复核相关选项，不要重复提交造成名称或配置混淆。
</Callout>

模型页不覆盖缓存阶梯、工具价格、分组倍率、计费表达式等完整计费能力，这些内容属于系统设置中的计费配置。

## 缺失模型

「缺失模型」用于发现已启用渠道引用、但模型元信息目录中没有同名记录的模型。打开缺失模型对话框后，可以搜索并把选中的名称带入新建模型表单。

处理缺失模型时应注意：

1. 先确认渠道模型名称、模型映射和名称匹配规则，避免为同一上游模型创建重复条目。
2. 通过新建模型补充描述、供应商、端点和状态。
3. 保存后重新检查绑定渠道和公开模型列表。

删除模型元信息只会软删除模型目录记录，不会删除渠道中的模型字符串、能力记录或计费选项；启用渠道继续引用该名称时，它可能再次出现在缺失模型列表中。

## 官方元数据同步

「同步上游」从项目配置的官方元数据源读取模型和供应商信息。同步流程默认只创建本地缺失且上游存在的模型，必要时创建供应商，不会整体覆盖已有模型。

推荐流程：

1. 打开同步向导，选择语言并执行预览。
2. 检查缺失模型、供应商以及已有模型的冲突字段。
3. 对已有模型逐项选择要覆盖的字段。
4. 确认同步并查看创建、更新和跳过列表。

可选择覆盖的已有模型字段包括描述、图标、标签、供应商、名称规则和状态。`sync_official` 已关闭的模型会被跳过。同步不会覆盖模型名称、端点、价格、倍率、分组或计费类型。

<Callout type="info">
  官方同步依赖外部元数据源和网络连接。同步结果中的创建数量、跳过原因和供应商数量应以向导返回结果为准；不要把官方目录当作当前实例已配置的渠道清单。
</Callout>

## 供应商与预填充组

### 供应商

模型可以关联已有供应商。当前模型页提供供应商选择和供应商管理入口；后端同时提供供应商的分页、搜索、新建、编辑和删除能力。删除供应商前应检查仍被模型引用的记录，避免模型目录出现缺少归属的信息。

### 预填充组

预填充组是控制台中复用模型、标签或端点集合的模板，不是用户分组、渠道分组，也不直接改变计费。管理员可以创建、编辑和删除三类预填充组：

| 类型 | 用途 |
| --- | --- |
| 模型 | 快速把一组模型名称带入渠道或模型相关表单。 |
| 标签 | 复用一组标签。 |
| 端点 | 复用一组端点能力配置。 |

## 模型部署

部署标签对应当前实现的 io.net 托管部署能力。Root 需要先在「系统设置 → 模型与路由 → 模型部署」启用服务并配置 API Key；配置完成后，Admin 或 Root 才能在模型页使用部署接口。New API 不会因为创建部署而自动创建或绑定渠道。

### 创建部署

创建向导会向 io.net 提交部署请求，可配置容器名称、镜像、端口、硬件、每容器 GPU 数量、地域、副本、持续时间、支付币种、环境变量/秘密变量、启动命令和镜像仓库凭据等字段。可用硬件、地域、副本和价格估算结果来自 io.net，不能把页面默认值视为所有实例的固定资源规格。

### 查看、更新和终止

部署列表支持按名称和状态搜索。详情可以查看部署状态、硬件、GPU、地域、容器、事件和公开 URL；容器日志支持标准输出、错误输出或全部流，并可刷新、下载。

部署操作包括更新配置、续期、重命名和删除/终止。终止操作会向 io.net 请求终止，不会自动把指向该部署的渠道迁移到其他地址。

<Callout type="warn">
  如果渠道 Base URL 或高级自定义路由指向某个部署，终止或修改部署前必须先切换到其他可用渠道，并验证模型路由。部署属于外部资源，New API 不保证其状态变化会同步修正渠道配置。
</Callout>

## 故障排查

1. 模型不出现在用户列表时，检查模型状态、绑定渠道状态、渠道模型列表、分组和 API 密钥限制。
2. 同步无结果时，检查官方同步开关、上游网络和向导返回的跳过列表。
3. 价格显示异常时，让 Root 检查模型名称对应的计费选项、分组倍率和 `QuotaPerUnit`。
4. 部署页提示未启用或无法连接时，检查 Root 的 io.net 开关和 API Key，并使用连接测试确认凭证。
5. 部署终止或容器异常时，查看部署详情、容器事件和日志，再检查相关渠道是否仍指向该地址。
