管理员从侧边栏进入「兑换码」，或访问 `/redemption-codes` 管理额度兑换码。该页面要求 Admin 或 Root；兑换码的创建、查询、编辑、启停和删除接口目前统一按管理员角色授权，没有单独的细粒度权限矩阵。

## 权限与合规前置

Root 必须先确认当前版本的支付合规条款，管理员才能创建兑换码，用户端也才会启用兑换入口。合规未确认时，已有兑换码仍可由管理员查看和维护，但创建操作及用户兑换会被拒绝。

侧边栏显示设置只影响菜单入口，不等同于撤销后端管理员权限。需要限制某位 Admin 使用兑换码功能时，应同时结合账户角色和部署侧访问控制处理。

## 创建兑换码

1. 点击「创建代码」。
2. 填写名称、额度、过期时间和生成数量。
3. 核对额度显示单位及有效期，然后提交创建。
4. 创建成功后，在列表中复制单个或选中的兑换码，并通过安全渠道分发。

| 字段 | 当前行为 |
| --- | --- |
| 名称 | 必填，长度为 1–20 个 Unicode 字符，用于标识批次或用途。 |
| 额度 | 控制台按实例配置的货币或 Token 形式显示，提交时转换为内部额度单位。 |
| 过期时间 | 留空表示永不过期；设置后不能早于当前时间。 |
| 数量 | 单次生成 1–100 个兑换码；只在创建时使用，编辑已有兑换码时不显示。 |

创建表单会限制额度不能小于零，但后端当前没有对所有额度边界执行同样的强制校验。管理员应在提交前核对额度和显示单位，不要依赖接口自动纠正异常值。

批量创建会逐个生成并写入兑换码，不是一个“全部成功或全部回滚”的事务。如果中途发生数据库错误，已经创建的记录会保留，失败响应也可能包含此前已生成的代码；重新创建前应先搜索并核对现有记录，避免重复发放。

<Callout type="warn">
  完整兑换码等同于可转移的额度凭证。不要将其放入公开截图、群聊、工单、日志或代码仓库；批量创建后应记录发放对象和批次，未使用的明文副本也应限制访问。
</Callout>

## 列表、搜索与筛选

兑换码列表默认按 ID 倒序返回。桌面端默认每页 20 条，移动端默认每页 10 条；搜索和状态筛选由服务端应用到完整结果后再分页。

| 功能 | 说明 |
| --- | --- |
| 关键词搜索 | 关键词为数字时，匹配精确 ID 或名称前缀；其他关键词只匹配名称前缀，不是任意位置包含搜索。 |
| 状态筛选 | 可单独选择未使用、已禁用、已使用或已过期。 |
| 列表字段 | 显示 ID、名称、状态、脱敏代码、额度、创建时间、过期时间和兑换用户。兑换时间位于兑换用户的提示信息中。 |
| 分页 | 翻页后会重新请求服务端；当前页的勾选范围不代表全部查询结果。 |

名称搜索的大小写行为取决于实例使用的数据库及其排序规则，不能假定所有部署都不区分大小写。

## 状态说明

| 页面状态 | 含义 |
| --- | --- |
| 未使用 | 数据状态为启用，并且尚未过期，可以被用户兑换。 |
| 已禁用 | 管理员已暂停使用；重新启用后，只要仍在有效期内即可兑换。 |
| 已使用 | 已成功绑定一位用户并增加其额度，不能再次兑换。 |
| 已过期 | 数据状态仍为启用，但非零过期时间已经早于当前时间。 |

“已过期”不是单独写入数据库的状态，而是页面和搜索接口根据启用状态与过期时间计算出的派生结果。因此筛选“未使用”时，已经过期但仍处于启用状态的代码会被排除。

## 查看与复制完整代码

表格默认只显示兑换码的开头和结尾，中间部分使用掩码隐藏。点击脱敏值可以显示完整代码并复制；这不是独立的“查看”行操作。

勾选当前列表中的多条记录后，可以批量复制，格式为每行：

```text
名称<Tab>完整兑换码
```

当前控制台没有兑换码导入、CSV/文件导出或按勾选项批量删除功能。需要保存发放清单时，应在受控环境中处理复制内容，并避免把完整代码长期存放在普通表格或共享文档中。

## 编辑、启用与禁用

当前控制台按照兑换码状态限制操作：

- 启用且未过期的兑换码可以编辑名称、额度和过期时间，也可以禁用。
- 已禁用兑换码不能直接编辑，可以先重新启用，再根据新的有效期状态决定是否编辑。
- 已使用或已过期的兑换码不能在控制台编辑，也不能切换启停状态。
- 编辑不会重新生成代码，也不会改变兑换用户信息。

这些是当前控制台提供的操作边界。后端更新接口的校验范围较宽，不应把直接调用接口当作绕过状态规则的常规管理方式。

## 删除兑换码

单条「删除」会对兑换码执行软删除。删除后记录不会再出现在默认列表中，当前控制台也没有恢复入口；不要把它描述为立即从数据库物理抹除。

「删除无效」是全局清理操作，会删除所有符合下列任一条件的兑换码：

- 已使用；
- 已禁用；
- 状态为启用，但已经超过有效期。

该操作不受当前分页、搜索条件、状态筛选或勾选项限制。仍然启用且未过期的代码不会被处理。

<Callout type="warn">
  「删除无效」会影响整个实例中所有符合条件的兑换码，并且控制台没有恢复流程。执行前应确认审计和留存要求，尤其要核对已禁用但仍需要保留追踪信息的发放批次。
</Callout>

## 用户兑换后的数据变化

用户在[钱包与订阅](/zh/docs/guide/feature-guide/user/wallet)页面提交兑换码。后端会在数据库事务中锁定兑换码，并再次检查状态和有效期：

1. 只有启用且未过期的代码可以继续处理。
2. 系统以状态比较防止并发请求重复使用同一个代码。
3. 成功后在同一事务内记录兑换用户、兑换时间和已使用状态，并增加用户额度。
4. 事务提交后同步用户额度缓存，并写入充值类型日志。

同一个兑换码在重复或并发请求中最多成功一次。用户端兑换失败时统一返回“兑换失败”，不会区分不存在、已使用、已禁用或已过期等原因，以避免泄露兑换码状态；管理员应在兑换码列表中自行核查。

## 审计与故障排查

创建兑换码会记录批次名称、数量和单个额度；更新、启停、删除及清理操作会进入管理审计链路，成功兑换还会为用户写入充值日志。当前没有兑换码专属审计报表或导出功能。

- **无法创建兑换码**：确认当前账户是 Admin 或 Root，并让 Root 检查支付合规确认状态。
- **搜索不到某个名称**：搜索只匹配名称前缀；如已知数字 ID，可以直接搜索 ID。
- **“未使用”中没有某条启用代码**：检查其过期时间；已过期的启用代码会归入“已过期”。
- **编辑按钮不可用**：当前控制台只允许编辑启用且未过期的记录；禁用代码需先重新启用。
- **用户兑换失败**：检查代码是否完整、是否启用、是否过期或已使用，以及实例是否仍满足支付合规要求。
- **清理数量超出当前页面预期**：「删除无效」作用于全局符合条件的记录，而不是当前页或当前筛选结果。
