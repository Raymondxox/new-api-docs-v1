管理员从侧边栏进入「兑换码」，或访问 `/redemption-codes` 管理额度兑换码。该页面要求 Admin 或 Root；兑换码的创建、查询、编辑、启停和删除接口目前统一按管理员角色授权，没有单独的细粒度权限矩阵。

<Callout type="info">
本页说明控制台当前提供的兑换码管理能力。兑换码可以作为一次性的额度凭证分发给用户；额度和有效期由创建时填写，额度的显示单位由平台的计费设置决定。
</Callout>

## 权限与合规前置

1. Root 必须先在[系统设置] → 「计费与支付」 → 「支付网关」中确认当前版本的支付合规条款，管理员才能创建兑换码，用户端也才会启用兑换入口。[计费与支付配置](/zh/docs/guide/feature-guide/system-settings/settings-billing)
2. 合规状态必须同时满足“已确认”和“条款版本为当前版本”（当前实现版本为 `v1`）；
3. 确认操作只能通过 Root 的控制台会话完成，API Access Token 不能代替该会话。
4. 合规未确认或条款版本与当前版本不匹配时，已有兑换码仍可由管理员查看和维护，但创建操作及用户兑换会被拒绝。

<Callout type="warn">
  - 侧边栏显示设置只影响菜单入口，不等同于撤销后端管理员权限。
  - 需要限制某位 Admin 使用兑换码功能时，应同时结合账户角色(「用户」 → 编辑管理员权限)和部署侧访问控制处理（「系统设置」 → 「站点与品牌」 → 「侧边栏模块」 → 「管理员区域」进行配置）。
</Callout>

## 创建兑换码

1. 点击「创建代码」。
2. 填写名称、额度、过期时间和生成数量。
3. 核对额度显示单位及有效期，然后提交创建。
4. 创建成功后，在列表中复制单个或选中的兑换码，并通过安全渠道分发。

![创建兑换码页面](/assets/guide/feature-guide/redemption-code-management-create-redemption-code.png)

<Callout type="info">
- 创建完成后建议立即完成以下闭环：
1. 先确认列表中的数量、名称、额度和过期时间与发放批次一致。
2. 只在受控环境中复制明文兑换码，并建立批次与发放对象的对应记录。
3. 将兑换码交付给用户后，不要再通过普通聊天、截图或工单重复传播明文兑换码。
</Callout>

| 字段 | 当前行为 |
| --- | --- |
| 名称 | 控制台默认留空；创建提交前若为空会按额度格式自动填充。控制台创建和编辑表单按 1–20 个 Unicode 字符校验；直接调用创建 API 时必须主动提供符合该长度的名称。 |
| 额度 | 控制台默认 10，且前端限制为不小于 0。输入框按平台配置显示货币或 Tokens；提交时转换为内部整数额度单位。货币模式按汇率换算并四舍五入，Tokens 模式按 Token 数量取整。 |
| 过期时间 | 默认永不过期；留空或点击“永不”表示不设置过期时间。控制台按本地日期和时间填写，管理 API 使用 Unix 秒；设置后不能早于服务端当前时间，可用快捷选项为 1 个月、1 周和 1 天。 |
| 数量 | 默认 1，单次生成 1–100 个兑换码；只在创建时使用，编辑已有兑换码时不显示。直接调用管理 API 时也必须传入 1–100 的数量。 |

### 注意事项

1. 创建表单会限制额度不能小于零，但后端当前没有对额度的非负性和业务上限执行同样的完整校验（JSON 类型本身仍须能解析为整数）。直接调用管理 API 时尤其要自行校验输入；管理员应在提交前核对额度和显示单位，不要依赖接口自动纠正异常值。
2. 创建兑换码中的“额度”不是固定的 USD 输入框。页面会读取平台的额度显示类型：USD、CNY、自定义货币或 Tokens；列表中的额度也使用同一配置显示。修改计费或额度显示配置后，历史记录的列表显示会按新配置格式化，但已保存的内部额度不会被后台批量重算。编辑旧记录时请重新核对显示金额，避免因当前汇率和取整规则变化而误改额度。
3. 管理 API 的 `quota` 字段是原始整数配额单位，不是直接的人民币或美元金额。货币显示时，换算会使用系统设置中的 `QuotaPerUnit` 和额度显示汇率；Tokens 显示时则按 Token 数量展示。不要把数据库中的整数直接当作货币金额填写。
4. 如果在控制台创建时不填写或只填写空白名称，提交前页面会用额度的格式化值作为名称。兑换码本身由服务端为每条记录生成 UUID；管理员只能设置名称、额度、有效期和数量，不能在表单中自定义代码，也不能通过编辑重新生成已有代码。通过管理 API 创建时仍应主动提供符合 1–20 个 Unicode 字符限制的名称，不要依赖控制台的自动填充。
5. 批量创建会逐个生成并写入兑换码，不是一个“全部成功或全部回滚”的事务。如果中途发生数据库错误，已经创建的记录会保留，失败响应也可能包含此前已生成的代码；重新创建前应先搜索并核对现有记录，避免重复发放。

<Callout type="warn">
  完整兑换码等同于可转移的额度凭证。不要将其放入公开截图、群聊、工单、日志或代码仓库；批量创建后应记录发放对象和批次，未使用的明文副本也应限制访问。
</Callout>

## 查询、筛选

兑换码列表默认按 ID 倒序返回。桌面端默认每页 20 条，移动端默认每页 10 条；搜索和状态筛选由服务端应用到完整结果后再分页。

![兑换码查询筛选页面](/assets/guide/feature-guide/redemption-code-management-filter.png)

| 功能 | 说明 |
| --- | --- |
| 关键词搜索 | 关键词为数字时，匹配精确 ID 或名称前缀；其他关键词只匹配名称前缀，不是任意位置包含搜索。 |
| 状态筛选 | 可单独选择未使用、已禁用、已使用或已过期。 |
| 分页 | 翻页后会重新请求服务端；当前页的勾选范围不代表全部查询结果。 |

## 状态说明

| 页面状态 | 含义 |
| --- | --- |
| 未使用 | 数据状态为启用，并且尚未过期，可以被用户兑换。 |
| 已禁用 | 管理员已暂停使用；重新启用后，只要仍在有效期内即可兑换。 |
| 已使用 | 已成功绑定一位用户并增加其额度，不能再次兑换。 |
| 已过期 | 数据状态仍为启用，但非零过期时间已经早于当前时间。 |

### 注意事项

1. “已过期”不是单独写入数据库的状态，而是页面和搜索接口根据启用状态与过期时间计算出的派生结果。因此筛选“未使用”时，已经过期但仍处于启用状态的代码会被排除。
2. 过期判断只作用于“启用”状态：已经禁用的记录即使过期，页面仍显示“已禁用”；重新启用后才会显示为“已过期”，并且仍不能兑换。
3. 表格默认只显示兑换码的开头和结尾，中间部分使用掩码隐藏。点击脱敏值会打开弹层查看完整代码，旁边的复制按钮用于复制明文；这不是独立的“查看”行操作。

## 批量复制兑换码

- 勾选当前页的多条记录后，可以批量复制，格式为每行：

```text
名称<Tab>完整兑换码
```

![批量复制兑换码页面](/assets/guide/feature-guide/redemption-code-management-bulk-copy.png)

<Callout type="info">
当前控制台没有兑换码导入、CSV/文件导出或按勾选项批量删除功能。需要保存发放清单时，应在受控环境中处理复制内容，并避免把完整代码长期存放在普通表格或共享文档中。

</Callout>

建议的查询与分发流程如下：

1. 先用名称前缀或 ID 搜索目标批次。
2. 使用状态筛选确认“未使用”且仍在有效期内的数量。
3. 逐行检查额度和过期时间，再勾选当前页需要分发的记录。
4. 点击复制按钮复制单条代码，或使用批量复制获得“名称 + Tab + 完整兑换码”的文本。
5. 完成分发后保留批次记录，不要把完整代码写入公开或未加密的存储。

## 编辑、启用与禁用

当前控制台按照兑换码状态限制操作：

- 启用且未过期的兑换码可以编辑名称、额度和过期时间，也可以禁用。
- 已禁用兑换码不能直接编辑，可以先重新启用，再根据新的有效期状态决定是否编辑。
- 页面显示为“已使用”或“已过期”的兑换码不能在控制台编辑，也不能切换启停状态。
- 编辑不会重新生成代码，也不会改变兑换用户信息。

编辑流程：

1. 在列表中找到“启用”且未过期的记录，点击操作列的铅笔图标。
2. 抽屉打开时会重新读取该记录的最新数据；核对名称、额度和过期时间后再修改。
3. 点击“保存更改”。编辑只会应用名称、额度和过期时间，数量字段不会出现在编辑抽屉中，也不会改变已有记录的数量。

启用或禁用流程：

1. 点击目标行操作列的“…”菜单。
2. 对启用且未显示为“已过期”的记录选择“禁用”，或对已禁用的记录选择“启用”（已禁用但已超过有效期的记录重新启用后会显示为“已过期”）。
3. 操作成功后列表会重新加载；禁用只暂停兑换，不会删除代码或改变额度。

![编辑、启用与禁用页面](/assets/guide/feature-guide/redemption-code-management-edit-redemption-code.png)

<Callout type="info">
  - 已禁用但已经超过有效期的记录仍会显示“已禁用”，并且可以执行“启用”；启用后会立即显示“已过期”，且仍不能兑换。
  - 这些是当前控制台提供的操作边界。后端更新接口的校验范围较宽，不应把直接调用接口当作绕过状态规则的常规管理方式。
</Callout>

## 删除与清理无效兑换码

单条「删除」会对兑换码执行软删除。确认框中的“永久删除”是界面提示，存储层仍会写入删除标记；删除后记录不会再出现在默认列表中，当前控制台也没有恢复入口，不要把它理解为立即从数据库物理抹除。

单条删除流程：

1. 点击目标行操作列的“…”菜单并选择“删除”。
2. 在确认框核对批次名称后确认删除。
3. 删除成功后该记录从默认列表中消失；如果只是暂时停止发放，应改用“禁用”。

「删除无效」是全局清理操作，会删除所有符合下列任一条件的兑换码：

- 已使用；
- 已禁用；
- 状态为启用，但已经超过有效期。

![删除与清理无效兑换码页面](/assets/guide/feature-guide/redemption-code-management-delete-invalid.png)

<Callout type="info">
该操作不受当前分页、搜索条件、状态筛选或勾选项限制。仍然启用且未过期的代码不会被处理。
</Callout>

<Callout type="warn">
  「删除无效」会影响整个平台中所有符合条件的兑换码，并且控制台没有恢复流程。执行前应确认审计和留存要求，尤其要核对已禁用但仍需要保留追踪信息的发放批次。
</Callout>

建议的清理流程：

1. 先在受控环境中保存仍需留存的审计信息；控制台本身没有 CSV 或文件导出，如需导出应使用部署侧的日志或审计留存方案。
2. 在列表中分别筛选已使用、已禁用和已过期，确认清理范围与保留要求。
3. 点击「删除无效」，阅读确认框中“已使用、已禁用、已过期”的范围说明。
4. 确认后再执行；返回的删除数量是整个平台本次受影响的记录数，不是当前页数量。

<Callout type="info">
单条删除也没有恢复入口。若只是暂时停止发放，优先使用“禁用”，不要用删除代替停用。
</Callout>

## 用户兑换后的数据变化

用户在[钱包与订阅](/zh/docs/guide/feature-guide/user/wallet)页面提交兑换码。后端在数据库事务中查询兑换码；支持行锁的数据库会锁定该记录，同时使用带状态条件的更新防止并发重复兑换，并再次检查状态和有效期：

1. 只有启用且未过期的代码可以继续处理。
2. 系统以状态比较防止并发请求重复使用同一个代码。
3. 成功后在同一事务内记录兑换用户、兑换时间和已使用状态，并增加用户额度。
4. 事务提交后尝试同步用户额度缓存，并写入充值类型日志。缓存同步失败只会记录服务端错误，不会回滚已经提交的数据库事务。

<Callout type="info">
同一个兑换码在重复或并发请求中最多成功一次。对于兑换业务本身的失败，用户端统一返回“兑换失败”，不会区分不存在、已使用、已禁用或已过期等原因，以避免泄露兑换码状态；合规未确认、请求格式错误或同一用户同时提交另一笔兑换请求时，接口可能返回相应的前置错误提示。管理员应在兑换码列表中自行核查。当前实现会把失败请求中提交的原始兑换码写入服务端错误日志，部署方应限制日志访问并按自身合规要求做好保护或脱敏。
</Callout>

## 审计与故障排查

成功创建兑换码会记录批次名称、数量和单个额度。更新、启停、单条删除及“删除无效”由管理审计中间件按管理路由记录；成功兑换还会为用户写入充值类型日志。管理审计参数不包含完整明文兑换码，但兑换失败时的服务端错误日志可能包含用户提交的原始兑换码。当前没有兑换码专属审计报表或导出功能，审计记录的可见范围和留存时间以平台日志配置为准。

- **无法创建兑换码**：确认当前账户是 Admin 或 Root，并让 Root 检查支付合规确认状态。
- **搜索不到某个名称**：搜索只匹配名称前缀；如已知数字 ID，可以直接搜索 ID。
- **“未使用”中没有某条启用代码**：检查其过期时间；已过期的启用代码会归入“已过期”。
- **编辑按钮不可用**：当前控制台只允许编辑启用且未过期的记录；禁用代码需先重新启用。
- **用户兑换失败**：检查代码是否完整、是否启用、是否过期或已使用，以及平台是否仍满足支付合规要求。
- **清理数量超出当前页面预期**：「删除无效」作用于全局符合条件的记录，而不是当前页或当前筛选结果。
