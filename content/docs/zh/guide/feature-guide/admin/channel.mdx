---
title: 渠道管理
description: 配置 AI 服务商渠道、模型、密钥、分组和可靠性策略。

渠道是 New API 连接上游 AI 服务商的核心配置单元。访问 `/channels`，管理员可以创建渠道、验证请求并调整路由。

## 创建渠道

1. 点击“创建渠道”。
2. 在基础信息中选择渠道类型、填写名称、Base URL 和认证信息。
3. 在模型区域填写或同步上游模型。
4. 在分组区域设置该渠道可被哪些分组使用。
5. 保存后在列表中确认渠道状态。

### 认证和 API 访问

不同渠道类型可能使用 API Key、Bearer Token、组织 ID、项目 ID、签名或自定义请求头。敏感凭证只保存在服务端，不要写入截图和文档。

### 模型和模型映射

模型列表决定用户可请求的模型。模型映射可把用户模型名转换为上游模型名，内容必须是有效 JSON；保存前用预览或测试请求验证。

## 高级配置

高级设置包含请求头覆盖、参数覆盖、重试、优先级、权重、自动禁用、模型同步和高级自定义路由。

### 参数覆盖

简单模式直接填写要覆盖的 JSON 字段：

```json
{
  "temperature": 0.8,
  "max_tokens": 2000
}
```

高级模式使用 `operations` 数组，可执行 `set`、`delete`、`move`、`copy`、`append`、`prepend`、字符串规范化和正则替换，并可用 `conditions` 与 `logic` 控制执行条件。操作按数组顺序执行。

### 路由参数

| 参数 | 作用 |
| --- | --- |
| 优先级 | 数值越高越优先 |
| 权重 | 同优先级渠道之间的选择权重 |
| 最大重试 | 当前渠道失败后的重试次数 |
| 自动禁用 | 连续失败或命中特定状态码后暂时禁用 |
| 标签 | 对渠道分组并执行批量操作 |

## 多 Key

打开渠道的“多 Key 管理”，逐条添加密钥并选择轮询或加权随机模式。系统会记录每个 Key 的成功、失败和冷却状态，单个 Key 失败时可自动跳过。

## 测试和批量操作

可以测试单个渠道、测试所有渠道、查询余额、拉取模型、批量启用/禁用、批量打标签、复制渠道和删除无效渠道。测试请求可能产生上游调用费用，应使用低成本模型。

## 故障排查

1. 查看渠道状态、最近响应时间和错误次数。
2. 在“使用日志”中按渠道和状态筛选。
3. 检查模型映射、分组、参数覆盖和请求路径。
4. 使用单渠道测试确认上游凭证和 Base URL。
5. 若启用了自动禁用或渠道亲和，检查对应 Root 设置。
