渠道是 New API 连接上游 AI 服务商的配置单元。管理员从侧边栏进入「渠道」，或访问 `/channels` 查看渠道列表、创建渠道并维护路由。

## 权限与安全边界

渠道接口先要求当前账户是 Admin 或 Root，再按操作检查渠道权限。Root 可以执行所有渠道操作；普通 Admin 的默认权限如下：

| 权限 | 可执行的操作 |
| --- | --- |
| `read` | 查看渠道列表、详情、模型列表和运行信息，不包含完整密钥。 |
| `operate` | 测试渠道、刷新余额、启用或禁用渠道、修复能力表，以及执行部分检测操作。 |
| `write` | 编辑模型、分组、优先级、权重、标签和其他路由字段。 |
| `sensitive_write` | 创建或删除渠道，修改密钥、Base URL、代理、请求头覆盖、参数覆盖等敏感配置。默认 Admin 不一定拥有此权限。 |
| `secret_view` | 目录中的独立能力，但完整密钥查看接口当前仍强制 Root，并要求安全验证。 |

编辑已有渠道时，如果账户没有 `sensitive_write`，敏感字段会以只读方式显示；仍可修改被授权的模型、分组、优先级和权重等路由字段。权限由 Root 在用户的管理员权限矩阵中覆盖配置，不能根据“能看到菜单”推断某个操作一定可用。

<Callout type="warn">
  完整渠道密钥属于高敏感凭证。查看密钥需要 Root、安全验证、关键操作限流，并且响应禁止缓存。不要把密钥复制到截图、工单、代码仓库或日志中。
</Callout>

## 创建渠道

1. 点击「创建渠道」。
2. 选择渠道类型，填写渠道名称和该类型要求的认证字段。
3. 填写 Base URL（如果该类型支持自定义地址），配置 API Key、Bearer Token、组织或项目标识、区域、服务账号等认证信息。
4. 在「模型与分组」中填写可用模型，并选择允许使用该渠道的分组。
5. 按需设置路由和高级选项，保存后在列表中检查状态并运行单渠道测试。

不同渠道类型显示的认证字段不同。编辑已有渠道时，后端不会把原密钥回填到表单；如果要更换密钥，必须明确输入新值并拥有敏感写入权限。部分类型还要求额外 JSON 配置，例如 Vertex AI 服务账号密钥必须是有效 JSON，Codex 凭证必须包含所需的访问令牌和账户标识。

## 模型与分组

### 模型列表

模型字段是逗号分隔的上游或公开模型名称。渠道能力表会根据渠道状态、模型和分组生成，最终影响用户在模型列表中能看到的模型。可在编辑器中手动输入模型，也可以使用「从上游获取模型」读取渠道支持的模型；上游请求失败时不会自动改变现有列表。

### 模型映射

模型映射把用户请求的模型名转换为上游模型名，内容必须是有效 JSON。例如：

```json
{
  "gpt-4o-mini": "provider-gpt-4o-mini"
}
```

保存前应检查映射的 JSON 格式，并用渠道测试或实际请求验证目标模型。映射不会自动替换其他渠道的模型列表。

### 分组

一个渠道可以配置一个或多个分组。分组名称使用逗号分隔；用户和 API 密钥还必须被分配到相应分组，才可能通过该渠道调用模型。若用户看不到模型，应依次检查模型元信息、渠道模型列表、渠道分组、用户分组和 API 密钥的模型限制。

## 路由与高级配置

### 优先级和权重

| 字段 | 行为 |
| --- | --- |
| 优先级 | 同一分组和模型的候选渠道按优先级选择；发生重试时，路由器会继续尝试符合条件的后续候选。 |
| 权重 | 同一优先级的候选渠道按权重参与选择；未设置或全部为零时，不能据此假定某个渠道固定获得请求。 |
| 测试模型 | 单渠道测试未显式指定模型时使用的模型。 |
| 自动禁用 | 由状态码、关键词、阈值等可靠性规则决定是否自动标记渠道不可用；自动禁用不等同于手动禁用。 |
| 标签 | 为渠道建立批量操作分组，可按标签启停、编辑或查看模型。 |

### 状态码和自动禁用

渠道状态包括启用、手动禁用和自动禁用。列表中的启停操作只接受启用与手动禁用；自动禁用状态由可靠性逻辑产生，排查时应查看错误、状态码和状态原因。启用或禁用渠道会同步更新对应的模型能力。

### 参数覆盖

简单参数覆盖是一个 JSON 对象，字段会在请求转发前写入或覆盖，例如：

```json
{
  "temperature": 0.8,
  "max_tokens": 2000
}
```

高级参数覆盖使用 `operations` 数组。当前编辑器支持设置、删除、移动、复制、追加、前置、字符串/正则替换、前后缀处理、大小写转换、条件判断、自定义错误、请求头透传与同步字段等操作。操作按数组顺序执行；路径、值和条件必须符合目标上游请求的结构。

### 请求头覆盖与代理

请求头覆盖可为上游请求增加、删除或转换请求头；代理、HTTP 协议、HTTP/2 连接分片等传输配置保存在渠道的额外设置中。它们属于敏感配置，修改前确认代理地址、证书和请求头不会泄露用户或渠道凭证。

### 高级自定义路由

高级自定义渠道可以为不同入口路径配置模型规则、上游路径、认证方式和协议转换器。每条路由可按精确名称或正则规则匹配模型；配置必须包含有效路由和转换器。若开启上游模型检测，还必须提供模型列表路由，否则保存或检测会失败。

## 多 Key 渠道

创建渠道时，密钥区域可能提供以下模式：

| 模式 | 说明 |
| --- | --- |
| 单 Key | 将一个密钥保存到一个渠道。 |
| 批量创建 | 每行一个密钥，创建多个独立渠道；可按密钥前缀自动生成名称。 |
| 多 Key 合并 | 将多个密钥放入同一个渠道，在渠道内随机或顺序轮询。 |

多 Key 渠道的轮询模式可以是随机或按顺序轮询。编辑时可追加密钥或覆盖现有密钥列表；Key 的启用状态、自动禁用原因和轮询位置会保存在渠道信息中。Codex、Vertex AI API Key 模式等特殊认证类型不支持所有批量/多 Key 组合，界面会根据渠道类型限制选项。

在「多 Key 管理」中可以分页查看密钥状态，并执行单个或全部启用、禁用、删除，以及清理已禁用密钥。删除密钥后不能从 New API 恢复，执行前应确认仍有可用密钥。

## 测试、同步与批量操作

渠道列表和行菜单支持以下操作，具体按钮受渠道类型与权限影响：

- 单渠道或全部渠道测试；
- 单渠道或全部渠道余额刷新；
- 从上游读取模型；
- 检测或应用上游模型列表变化；
- 启用、禁用和按标签批量操作；
- 复制渠道、修复渠道能力；
- 管理 Ollama 模型；
- 查看或刷新 Codex 凭证、用量和额度重置信息；
- 删除单个渠道、批量删除渠道，或清理已禁用渠道。

全部渠道测试、全部上游更新检测等操作可能创建后台系统任务或产生较多上游请求。不要把操作按钮出现理解为任务一定会在当前 Admin 的系统信息页面中可见；系统任务相关接口当前属于 Root 范围。

<Callout type="warn">
  「复制渠道」会复制渠道凭证和配置。复制后应立即检查名称、余额、密钥、分组和模型映射；复制接口默认重置余额与累计用量，但不要据此替代人工核对。
</Callout>

## 故障排查

1. 查看渠道状态、最近测试时间、响应时间和错误次数。
2. 使用单渠道测试确认认证信息、Base URL、代理和测试模型。
3. 检查模型列表、模型映射、分组、优先级和权重是否与用户/API 密钥限制一致。
4. 若渠道被自动禁用，查看状态原因、触发状态码/关键词及 Root 配置的阈值。
5. 在[日志与异步任务](/zh/docs/guide/feature-guide/user/log)中按渠道、模型、请求 ID 或上游请求 ID 定位请求。
6. 对多 Key 渠道检查单个 Key 的禁用状态；对高级自定义渠道检查路由、转换器和认证占位符。

<Callout type="info">
  渠道页面描述的是实例支持的配置能力，不代表每个实例都已配置对应服务商、Ollama、Codex 或高级自定义资源。实际可用性还取决于渠道凭证、上游服务和 Root 的系统设置。
</Callout>
