## 权限与安全边界

所有渠道接口先要求当前账户是 Admin 或 Root，再按具体操作检查渠道权限。常见权限与操作对应关系如下：

| 权限 | 主要操作 |
| --- | --- |
| ChannelRead | 查看列表、详情、模型列表、运行信息，以及 Codex 用量和额度重置时间。 |
| ChannelOperate | 测试渠道、查询余额、启用或手动禁用渠道、修复能力索引、检测上游更新、管理多 Key。 |
| ChannelWrite | 编辑普通路由字段、标签，以及应用渠道的上游模型更新。 |
| ChannelSensitiveWrite | 创建、删除和复制渠道，修改密钥、Base URL、代理、请求头覆盖、参数覆盖等敏感配置；创建时从上游获取模型也需要该权限。 |
| Root 与安全验证 | 查看或复制完整渠道密钥等高敏感操作。当前完整密钥接口还会执行安全验证、关键操作限流和禁止缓存等保护。 |

普通 Admin 的实际权限由 Root 在管理员权限矩阵中配置。没有敏感写权限时，编辑抽屉可能仍允许修改模型、分组、优先级和权重，但会锁定密钥、Base URL 等字段。

<Callout type="warn">
  不要把 API 密钥、服务账号 JSON、代理密码或请求头中的凭证写入截图、工单、代码仓库或普通日志。复制渠道会复制凭证；删除渠道或 Key 后，New API 不提供恢复入口。
</Callout>

## 创建与编辑渠道

点击「创建渠道」后，编辑器按以下四个步骤组织配置：

1. 基本信息；
2. 凭证；
3. 模型与分组；
4. 高级设置。

创建时前三步是主要部分，高级设置用于路由、转换和传输层的细化控制。建议先完成前三步并保存，再通过详细测试验证渠道。

### 基本信息

| 字段 | 必填/适用条件 | 说明 |
| --- | --- | --- |
| 类型 | 必填 | 决定认证方式、可用字段、支持的端点和条件操作。 |
| 名称 | 必填 | 用于管理员识别渠道；建议包含服务商、环境或用途。 |
| 已启用 | 可选 | 创建后是否立即加入渠道路由。关闭后渠道不会作为正常候选。 |
| OpenAI 组织 | OpenAI 类型 | 可选的组织标识，具体是否发送由协议适配器决定。 |
| API 地址 | 视渠道类型 | 自定义上游 Base URL。留空则使用默认内置地址：对于官方渠道，New API 具有内置地址。仅针对第三方代理站点或特殊端点填写此项。|
| API 密钥添加模式 | 凭证步骤使用 | 单密钥、批量创建或将多个密钥合并为一个多 Key 渠道。 |
| API 密钥/凭证 | 视渠道类型 | 由上游服务商提供的密钥、令牌或 JSON 凭证。 |

<Callout type="info">
「粘贴连接信息」可以在支持的编辑器中粘贴连接信息 JSON，自动填入密钥和 API 地址。粘贴后仍应逐项检查类型、地址、密钥、模型和分组；它不会替代模型、分组或高级设置的配置。
</Callout>

### 凭证

#### API 地址

API 地址填写的是上游服务的 Base URL，不是完整的聊天、Responses 或模型请求路径。对于界面提示需要自定义地址的渠道，应按该渠道的提示填写；不要把 /v1/chat/completions 等完整端点当作 Base URL。

OpenAI 兼容渠道的界面会提示不要额外添加 /v1 或尾部斜杠。不同渠道的地址规则可能不同，保存前应以当前类型显示的帮助文本和校验结果为准。

#### API 密钥添加模式

| 模式 | 行为 | 适用注意 |
| --- | --- | --- |
| 单密钥 | 使用一个凭证创建一个渠道。 | 适合先验证连接和模型配置。 |
| 批量创建 | 每行一个密钥，创建多个独立渠道。 | 可按密钥前缀生成名称；每个渠道需要单独参与路由。 |
| 多 Key 合并 | 将多个密钥保存到同一个渠道内。 | 可以随机选择或按顺序轮询；后续可在多 Key 管理中单独处理密钥。 |

<Callout type="info">
- 部分特殊类型不支持所有API 密钥添加模式。
- 例如 Codex 凭证必须是包含 access_token 和 account_id 的 JSON，Codex 不支持批量创建；
- Vertex AI 的 API Key 模式也不支持批量创建。界面会根据类型隐藏或禁用不兼容选项。
</Callout>

#### 编辑已有渠道时的密钥规则

- 编辑抽屉不会回填原密钥；
- 密钥留空表示保留原值；
- 输入新密钥才会替换原值；
- 修改密钥需要 ChannelSensitiveWrite；
- Root 在通过安全验证后，可以显示或复制当前完整密钥；
- Vertex、AWS、Codex 等类型的 JSON 或组合格式必须通过对应校验。

### 模型与分组

#### 模型列表

模型区域使用多选控件保存模型名称，也允许输入自定义模型。提交后模型列表会参与渠道能力索引，并影响用户可见的模型和路由候选。

可使用以下快捷操作：

| 操作 | 作用 |
| --- | --- |
| 填入相关模型 | 使用已加载的基础模型预填充相关模型。 |
| 填充所有模型 | 把当前可用模型目录全部加入列表。 |
| 从上游获取 | 调用上游模型列表接口读取模型，结果需要人工勾选并保存。 |
| 全部复制 | 复制当前模型列表，便于编辑或粘贴到其他配置。 |
| 清除全部 | 清空当前列表；保存前必须重新填写模型。 |

<Callout type="info">
上游获取失败不会自动替换原有模型列表。模型名称是否真的可调用，还取决于凭证、上游权限和协议适配器。
</Callout>

#### 模型映射

模型映射把用户请求的模型名转换为上游实际模型名，必须是 JSON 对象，且映射值必须是字符串。例如：

~~~json
{
  "gpt-4o-mini": "provider-gpt-4o-mini"
}
~~~

<Callout type="info">
保存前应验证 JSON 格式，并确认左侧名称出现在渠道模型列表中。若把映射后的供应商内部名称也加入公开模型列表，用户可能看到不希望暴露的上游名称；需要时应移除映射目标，只保留用户侧名称。
</Callout>

#### 分组

分组为必填项，可以选择一个或多个用户分组。用户和 API 密钥还必须被分配到对应分组，才可能通过该渠道调用模型。排查“模型不可见”时，应同时检查渠道模型、渠道分组、用户分组、API 密钥限制和模型元信息。

### 高级设置

高级设置分为路由策略、内部备注、覆盖规则、渠道额外设置、字段透传和上游模型检测。高级自定义渠道还会显示路由编辑器。

#### 路由策略

| 参数 | 默认/格式 | 作用 | 注意事项 |
| --- | --- | --- | --- |
| 优先级 | 默认 0 | 同一模型和分组的候选渠道按优先级从高到低选择。 | 只在其他条件匹配时生效。 |
| 权重 | 默认 0 | 同优先级候选渠道进行负载分配。 | 权重越高不代表严格固定比例；重试时可能选择其他渠道。 |
| 测试模型 | 可选文本 | 详细测试未指定模型时使用的模型。 | 应填写该渠道实际支持的模型。 |
| 自动封禁 | 默认开启 | 根据可靠性逻辑在重复失败时自动禁用渠道。 | UI 的“自动封禁”对应列表中的“自动禁用”状态，不等同于手动禁用。 |

<Callout type="info">
启用或禁用渠道会同步更新能力索引。手动启用不能保证上游凭证立即可用；如果可靠性检查再次失败，渠道仍可能被自动禁用。
</Callout>

#### 内部备注

| 参数 | 说明 |
| --- | --- |
| 标签 | 用于筛选、聚合和按标签批量启停或编辑。 |
| 备注 | 仅管理员可见，最多 255 个字符。不要写入密钥、令牌或用户隐私。 |

#### 覆盖规则

| 参数 | 格式/限制 | 作用 |
| --- | --- | --- |
| 状态码映射 | JSON 对象；状态码必须是 100–599 范围内的整数 | 将上游响应状态映射为 New API 处理所需的状态。 |
| 参数覆盖 | JSON 对象，或可视化 operations 配置 | 在请求转发前设置、删除、移动、复制、追加或替换字段。 |
| 请求头覆盖 | JSON 对象 | 增加、删除或转换发送给上游的请求头。 |

参数覆盖的操作按数组顺序执行，路径和值必须匹配目标请求结构。可视化编辑器支持设置、删除、移动、复制、追加、字符串替换、正则替换、前后缀处理、大小写转换和条件判断等操作。当前规则不能覆盖 stream 参数。请求头覆盖支持以下动态占位符：

- &#123;api_key&#125;：当前渠道实际使用的密钥；
- &#123;client_header:NAME&#125;：客户端请求头 NAME 的值。

<Callout type="info">
使用占位符前应确认不会把客户端令牌或渠道密钥转发到错误的上游。新增可能改变重试行为的状态码映射时，界面可能要求再次确认。
</Callout>

#### 渠道额外设置

| 参数 | 默认/范围 | 作用与限制 |
| --- | --- | --- |
| 强制格式化 | 默认关闭；按渠道类型显示 | 强制使用特定请求/响应格式。只在支持的 OpenAI 相关渠道中显示。 |
| 思维到内容 | 默认关闭 | 将 reasoning_content 转换为内容中的 &lt;think&gt; 标签后返回。 |
| 透传请求体 | 默认关闭 | 尽量把客户端原始请求体发送给上游，会减少部分字段转换、移除和参数覆盖。 |
| 跳过异步任务轮询延迟 | 默认关闭 | 不等待异步任务轮询之间的默认间隔；可能增加上游请求频率。 |
| 代理地址 | 可选 URL | 支持 HTTP、HTTPS、SOCKS5 和 SOCKS5H；必须包含有效主机。 |
| HTTP 协议 | 自动 或 HTTP/1.1 | 自动模式在可用时协商 HTTP/2；HTTP/1.1 强制使用 HTTP/1.1。 |
| HTTP/2 连接分片 | 1–8，默认 1 | 将 HTTP/2 流量分布到多个可复用连接；选择 HTTP/1.1 时必须为 1。 |
| 系统提示词 | 可选文本 | 应用于经过该渠道的请求。 |
| 系统提示词连接 | 默认关闭 | 将渠道系统提示词与用户提示连接起来；开启后会改变发送给上游的提示词内容。 |

<Callout type="info">
代理、请求头、参数覆盖和系统提示词都可能改变请求语义或泄露信息，修改后应立即执行详细测试。
</Callout>

#### 字段透传

- 字段透传开关只在适用的协议或渠道类型中显示，常见字段如下：

| 字段/开关 | 适用范围 | 说明 |
| --- | --- | --- |
| service_tier | OpenAI、Anthropic、Codex | 允许客户端传递服务等级字段。 |
| store | OpenAI、Codex | 可禁用该字段透传；禁用后可能影响依赖该字段的客户端。 |
| safety_identifier | OpenAI | 控制是否透传安全标识。 |
| include 用量混淆 | OpenAI、Codex | 控制 stream_options.include_obfuscation 等用量混淆字段是否透传。 |
| inference_geo | OpenAI、Anthropic | 控制推理地理位置/数据驻留相关字段是否透传。 |
| speed | Anthropic | 控制 Claude 推理速度模式字段是否透传。 |
| Claude beta 参数 | Anthropic | 控制是否追加或透传 anthropic-beta 相关参数。 |

#### 高级自定义路由

- 高级自定义渠道可以为不同入口路径配置上游路径、模型匹配规则、认证方式和协议转换器。每条路由可以使用精确模型名、re: 正则模型规则或空模型列表作为该路径的兜底规则。

配置时应确认：

1. 入口路径能匹配实际请求；
2. 上游路径是相对 Base URL 的路径，或明确使用完整 URL；
3. 转换器与上游协议相符；
4. Header 或 Query 认证值不会泄露；
5. 如果启用上游模型检测，必须配置有效的 /v1/models 路由；
6. 使用相对上游路径时，Base URL 不能为空。

#### 上游模型检测设置

| 参数 | 作用 |
| --- | --- |
| 上游模型更新检查 | 允许系统检测上游新增或移除的模型。 |
| 自动同步上游模型 | 检测到变化后自动更新渠道模型列表；必须先开启检查。 |
| 忽略上游模型 | 使用英文逗号分隔的精确名称，或以 regex: 开头的规则排除不希望同步的模型。 |
| 上次检查时间 | 最近一次检测的时间，属于运行结果。 |
| 待处理模型 | 最近检测到的可加入或可移除模型，需审核后应用。 |

<Callout type="info">
  - 自动同步和手动应用都会改变渠道模型列表，并在完成后刷新运行时能力索引。
  - 对于高级自定义渠道，模型检测还要求存在有效的模型列表路由。
</Callout>

## 参数覆盖系统

参数覆盖系统支持两种模式：简单覆盖模式（向前兼容）和高级操作模式。通过灵活的条件判断和操作类型，可以实现复杂的参数动态调整。

### 简单覆盖模式

向前兼容性，直接指定要覆盖的字段和值，系统会将这些字段合并到原始请求中：

```json
{
  "temperature": 0.8,
  "max_tokens": 2000,
  "model": "gpt-4"
}
```

### 高级操作模式

通过 `operations` 数组定义复杂的参数操作，支持条件判断、数组操作、字符串拼接与字符串规范化等高级功能。

#### 基本结构

```json
{
  "operations": [
    {
      "path": "temperature",
      "mode": "set",
      "value": 0.8,
      "conditions": [...],
      "logic": "AND"
    }
  ]
}
```

**字段说明（按需填写）：**

- `mode`: 必填
- `path`: 适用于 `set` / `delete` / `append` / `prepend` / `trim_prefix` / `trim_suffix` / `ensure_prefix` / `ensure_suffix` / `trim_space` / `to_lower` / `to_upper` / `replace` / `regex_replace`
- `value`: 常见于 `set` / `append` / `prepend` / `trim_prefix` / `trim_suffix` / `ensure_prefix` / `ensure_suffix`
- `from` / `to`: 适用于 `move` / `copy` / `replace` / `regex_replace`
- `keep_origin`: 用于 `set`（已有值则跳过）以及对象合并时的 `append` / `prepend`

### 操作模式 (mode)

#### 1. set - 设置值

设置指定路径的值：

```json
{
  "path": "temperature",
  "mode": "set",
  "value": 0.8,
  "keep_origin": false
}
```

**参数说明：**
- `keep_origin`: 为 `true` 时，如果目标路径已存在值则跳过设置

#### 2. delete - 删除字段

删除指定路径的字段：

```json
{
  "path": "messages.0",
  "mode": "delete"
}
```

#### 3. move - 移动字段

将一个字段的值移动到另一个位置：

```json
{
  "mode": "move",
  "from": "messages.0.content",
  "to": "system"
}
```

#### 4. append - 追加内容

在现有内容后追加新内容：

```json
{
  "path": "messages.0.content",
  "mode": "append",
  "value": "\n\n请用中文回答。"
}
```

**支持的数据类型：**
- **字符串**: 在原字符串末尾追加
- **数组**: 在数组末尾添加元素（支持添加单个元素或数组）
- **对象**: 合并对象属性

#### 5. prepend - 前置内容

在现有内容前添加新内容：

```json
{
  "path": "messages.0.content",
  "mode": "prepend",
  "value": "重要提示：请仔细阅读以下内容。\n\n"
}
```

**支持的数据类型：**
- **字符串**: 在原字符串开头前置
- **数组**: 在数组开头添加元素（支持添加单个元素或数组）
- **对象**: 合并对象属性

#### 6. copy - 复制字段

将 `from` 指定路径的值复制到 `to` 指定路径（不删除源字段）：

```json
{
  "mode": "copy",
  "from": "model",
  "to": "original_model"
}
```

#### 7. trim_prefix - 去除前缀

对字符串字段去除指定前缀（若不匹配则不变）：

```json
{
  "path": "model",
  "mode": "trim_prefix",
  "value": "openai/"
}
```

#### 8. trim_suffix - 去除后缀

对字符串字段去除指定后缀（若不匹配则不变）：

```json
{
  "path": "model",
  "mode": "trim_suffix",
  "value": "-latest"
}
```

#### 9. ensure_prefix - 确保前缀

确保字符串字段以指定前缀开头（已存在则不变）：

```json
{
  "path": "model",
  "mode": "ensure_prefix",
  "value": "openai/"
}
```

#### 10. ensure_suffix - 确保后缀

确保字符串字段以指定后缀结尾（已存在则不变）：

```json
{
  "path": "model",
  "mode": "ensure_suffix",
  "value": "-latest"
}
```

#### 11. trim_space - 去除首尾空白

对字符串字段执行 `TrimSpace`（空格、换行、制表符等都会被移除）：

```json
{
  "path": "model",
  "mode": "trim_space"
}
```

#### 12. to_lower - 转小写

将字符串字段转换为小写：

```json
{
  "path": "model",
  "mode": "to_lower"
}
```

#### 13. to_upper - 转大写

将字符串字段转换为大写：

```json
{
  "path": "model",
  "mode": "to_upper"
}
```

#### 14. replace - 字符串替换

对字符串字段执行子串替换：

```json
{
  "path": "model",
  "mode": "replace",
  "from": "openai/",
  "to": ""
}
```

**参数要求：**
- `from`: 必填且不能为空字符串
- `to`: 可选，省略时等同于空字符串

#### 15. regex_replace - 正则替换

对字符串字段执行正则匹配替换：

```json
{
  "path": "model",
  "mode": "regex_replace",
  "from": "^gpt-",
  "to": "openai/gpt-"
}
```

**参数要求：**
- `from`: 必填（正则表达式，Go regexp 语法）
- `to`: 可选，省略时等同于空字符串

### 条件判断

通过 `conditions` 数组设置操作执行的条件，仅当条件满足时才会执行对应操作。

#### 条件结构

```json
{
  "conditions": [
    {
      "path": "model",
      "mode": "contains",
      "value": "gpt-4",
      "invert": false,
      "pass_missing_key": false
    }
  ],
  "logic": "AND"
}
```

#### 条件匹配模式

- `full`: 完全匹配（默认）
- `prefix`: 前缀匹配
- `suffix`: 后缀匹配
- `contains`: 包含匹配
- `gt`: 大于（仅数字类型）
- `gte`: 大于等于（仅数字类型）
- `lt`: 小于（仅数字类型）
- `lte`: 小于等于（仅数字类型）

**须知：**
- 数值比较只能用于数字类型
- 字符串操作（prefix、suffix、contains）会将值转换为字符串进行比较

#### 条件参数说明

- `invert`: 反选功能，`true` 表示取反结果
- `pass_missing_key`: 当指定路径不存在时的行为
  - `true`: 路径不存在时条件通过
  - `false`: 路径不存在时条件不通过（默认）

#### 逻辑关系 (logic)

- `AND`: 所有条件都必须满足
- `OR`: 任意条件满足即可（默认）

### 路径语法

使用 JSON 路径语法访问嵌套字段：

- `temperature` - 根级字段
- `messages.0.content` - 数组第一个元素的 content 字段
- `messages.-1.content` - 数组最后一个元素的 content 字段
- `metadata.user.name` - 嵌套对象字段

同时，`path` 支持以下内置变量（无需在请求体中显式存在），可直接用于条件判断：

| 变量 | 含义 | 典型用途 |
| --- | --- | --- |
| `model` / `upstream_model` | 重定向后的目标模型 | 按实际调用的上游模型做条件匹配 |
| `original_model` | 重定向前的目标模型 | 按用户请求的原始模型做条件匹配 |

### 实用示例

#### 1. 动态调整模型参数

根据消息内容动态调整温度参数：

```json
{
  "operations": [
    {
      "path": "temperature",
      "mode": "set",
      "value": 0.3,
      "conditions": [
        {
          "path": "messages.0.content",
          "mode": "contains",
          "value": "代码"
        }
      ]
    },
    {
      "path": "temperature",
      "mode": "set",
      "value": 0.9,
      "conditions": [
        {
          "path": "messages.0.content",
          "mode": "contains",
          "value": "创意"
        }
      ]
    }
  ]
}
```

#### 2. 添加系统提示

在消息数组开头添加系统消息：

```json
{
  "operations": [
    {
      "path": "messages",
      "mode": "prepend",
      "value": [
        {
          "role": "system",
          "content": "你是一个专业的AI助手，请始终保持礼貌和专业。"
        }
      ]
    }
  ]
}
```

#### 3. 根据模型类型调整参数

根据不同模型设置不同的 max_tokens：

```json
{
  "operations": [
    {
      "path": "max_tokens",
      "mode": "set",
      "value": 4000,
      "conditions": [
        {
          "path": "model",
          "mode": "prefix",
          "value": "gpt-4"
        }
      ]
    },
    {
      "path": "max_tokens",
      "mode": "set",
      "value": 2000,
      "conditions": [
        {
          "path": "model",
          "mode": "prefix",
          "value": "gpt-3.5"
        }
      ]
    }
  ]
}
```

#### 4. 多条件组合（AND逻辑）

同时满足多个条件时才执行操作：

```json
{
  "operations": [
    {
      "path": "stream",
      "mode": "set",
      "value": false,
      "conditions": [
        {
          "path": "model",
          "mode": "contains",
          "value": "claude"
        },
        {
          "path": "messages.0.content",
          "mode": "contains",
          "value": "长文"
        }
      ],
      "logic": "AND"
    }
  ]
}
```

#### 5. 数值比较条件

根据数值大小进行条件判断：

```json
{
  "operations": [
    {
      "path": "temperature",
      "mode": "set",
      "value": 0.1,
      "conditions": [
        {
          "path": "max_tokens",
          "mode": "gt",
          "value": 1000
        }
      ]
    }
  ]
}
```

#### 6. 反选条件

使用 `invert` 实现反选逻辑：

```json
{
  "operations": [
    {
      "path": "stream",
      "mode": "set",
      "value": true,
      "conditions": [
        {
          "path": "model",
          "mode": "contains",
          "value": "gpt-3.5",
          "invert": true
        }
      ]
    }
  ]
}
```

#### 7. 处理缺失字段

使用 `pass_missing_key` 处理可能不存在的字段：

```json
{
  "operations": [
    {
      "path": "temperature",
      "mode": "set",
      "value": 0.7,
      "conditions": [
        {
          "path": "custom_field",
          "mode": "full",
          "value": "special",
          "pass_missing_key": true
        }
      ]
    }
  ]
}
```

#### 8. 字符串拼接示例

在用户消息后追加指导语：

```json
{
  "operations": [
    {
      "path": "messages.-1.content",
      "mode": "append",
      "value": "\n\n请详细解释你的思考过程。"
    }
  ]
}
```

### 注意事项

<Callout type="warn">
  **执行顺序**: 操作按照在 `operations` 数组中的顺序依次执行，前面的操作会影响后续操作
</Callout>

## 渠道操作

![渠道操作页面](/assets/guide/feature-guide/channel-management-channel-actions.png)

<Callout type="info">
渠道行的「更多操作」和卡片操作会根据权限与渠道类型动态显示。
</Callout>

### 测试连接

页面上有两个容易混淆的测试入口：

| 入口 | 行为 |
| --- | --- |
| 测试连接 | 快速执行单渠道测试，适合快速确认凭证和默认测试模型。 |
| 测试渠道连接 | 打开详细测试对话框，可选择端点类型、流式模式和模型，并查看每个模型的结果。 |

详细测试流程：

1. 选择端点类型；默认使用“自动检测”；
2. 按需选择流式模式；
3. 搜索或选择一个或多个渠道模型；
4. 执行单模型测试或「测试全部模型」；
5. 查看成功/失败状态、响应时间和错误详情；
6. 需要时勾选成功模型，或在确认后删除失败模型。

![测试连接页面](/assets/guide/feature-guide/channel-management-test-connection.png)

可选端点包括：

| 端点 | 路径 |
| --- | --- |
| OpenAI Chat | /v1/chat/completions |
| OpenAI Responses | /v1/responses |
| Responses Compact | /v1/responses/compact |
| Anthropic | /v1/messages |
| Gemini | /v1beta/models/&#123;model&#125;:generateContent |
| Jina Rerank | /v1/rerank |
| 图片生成 | /v1/images/generations |
| Embeddings | /v1/embeddings |

<Callout type="info">
  - Embeddings、图片生成、Jina Rerank 和 Responses Compact 不支持流式测试。批量测试最多同时运行 5 个模型，批次之间会短暂间隔，并可以在进行中停止后续测试。
  - 测试成功会更新渠道的测试时间和响应时间；
  - 测试失败只说明当前端点、模型或凭证组合失败，不等同于所有生产请求都不可用。
</Callout>

<Callout type="warn">
  「删除失败模型」会直接修改当前渠道的模型列表。执行前先确认失败是因为模型确实不可用，而不是临时网络、限流、代理或端点选择错误。
</Callout>

### 查询余额

在渠道操作菜单中选择「查询余额」：

1. 查看当前余额和上次更新时间；
2. 点击「更新余额」向上游发起余额查询；
3. 根据返回结果确认余额和更新时间；
4. 查询失败或渠道类型不支持时，以界面错误提示为准，不要用旧余额判断当前上游状态。

![查询余额页面](/assets/guide/feature-guide/channel-management-check-balance.png)

<Callout type="info">
  - 不同渠道类型调用的上游余额接口不同，并非所有渠道都支持余额查询。
  - Codex 类型可能显示用量或额度重置信息，而不是普通余额卡片。
  - 渠道余额也不等同于 New API 用户钱包余额、订阅额度或 API 密钥额度。
</Callout>

### 获取模型

可以从渠道行操作或创建/编辑抽屉中选择「获取模型」/「从上游获取」。

1. 发起上游模型列表请求；
2. 使用搜索框过滤模型；
3. 在「新模型」「现有模型」「已移除模型」之间切换；
4. 按提供商分组展开列表；
5. 勾选单个模型或整组模型；
6. 点击「保存模型」写回渠道模型列表。

![获取模型页面](/assets/guide/feature-guide/channel-management-fetch-models.png)

<Callout type="info">
「已移除模型」表示该模型仍在当前选择中，但上游本次返回中已不存在。获取模型不会在未点击保存时修改渠道；上游请求失败也不会自动替换原有列表。页面显示的模型数量是实时数据，不应作为固定配置值。
</Callout>

### 上游模型更新

上游更新用于持续维护已配置渠道的模型列表，推荐采用以下流程：

1. 先启用上游模型更新检查；
2. 执行单渠道或全部渠道检测；
3. 查看新增模型和待移除模型；
4. 检查忽略规则，避免同步测试模型或内部模型；
5. 选择性应用，或在确认影响范围后应用全部更新；
6. 重新执行渠道测试并检查用户可见模型。

<Callout type="info">
「检测所有上游更新」可能排队执行多个上游请求；已有同类任务运行时可能返回冲突。自动同步只有在检查开关和自动同步开关同时开启时才生效。
</Callout>

### 复制渠道

复制渠道会创建一个新的渠道记录，并复制原渠道的大部分配置和凭证：

1. 在操作菜单中选择「复制渠道」；
2. 设置名称后缀，默认是 _copy；
3. 确认新名称预览；
4. 决定是否勾选「重置余额和已用配额」；
5. 点击「复制渠道」；
6. 复制完成后重新检查名称、凭证、模型、分组、映射和路由参数。

![复制渠道页面](/assets/guide/feature-guide/channel-management-duplicate-channel.png)

<Callout type="info">
复制后会获得新的渠道 ID 和创建时间，测试时间与响应时间会重置。默认重置余额和累计用量；取消勾选后会保留原值，因此应根据实际用途选择。
</Callout>

### 启用、禁用和删除

- 手动切换只负责启用或手动禁用渠道；
- 自动禁用由可靠性逻辑产生，不能简单当作手动禁用；
- 多 Key 渠道还可能因为所有 Key 都不可用而自动失去路由能力；
- 删除渠道需要敏感写权限，删除后不能从 New API 恢复；
- 「删除所有已禁用」会批量删除目标渠道，执行前必须确认筛选范围。

### 修复渠道一致性

选择「修复渠道一致性」并确认后，系统会根据全部渠道配置重建路由/能力索引，包括：

- 支持的模型；
- 渠道分组；
- 优先级；
- 权重。

![修复渠道一致性页面](/assets/guide/feature-guide/channel-management-repair-channel.png)

<Callout type="info">
重建期间路由可能短暂不完整，建议在低峰期执行。完成后应重新刷新列表并用一个代表性模型测试路由，不要在高峰期频繁重复执行。
</Callout>

### 标签和批量操作

开启「批量操作」后，可以选择多个渠道进行状态或标签操作；开启「标签模式」后，可以按标签聚合渠道并执行统一的启用、禁用或编辑。批量测试、批量余额刷新和批量上游检测可能产生较多上游请求或后台任务，应先确认权限、请求量和维护窗口。

![标签和批量操作页面](/assets/guide/feature-guide/channel-management-bulk-actions.png)

## 多 Key 渠道

### 创建方式

| 模式 | 说明 |
| --- | --- |
| 单 Key | 一个密钥对应一个渠道。 |
| 批量创建 | 每行一个密钥，创建多个独立渠道；可按密钥前缀生成名称。 |
| 多 Key 合并 | 多个密钥保存在一个渠道中，并在请求间共享。 |

多 Key 合并支持：

| 选择模式 | 行为 |
| --- | --- |
| 随机 | 每次请求从可用 Key 池中随机选择。 |
| 轮询 | 按顺序使用可用 Key，并保存轮询位置。该模式依赖 Redis 和内存缓存；缺少这些组件时性能可能明显下降。 |

### 管理密钥

在「多 Key 管理」中可以分页查看每个 Key 的状态、禁用原因和禁用时间，并执行：

- 单个 Key 启用、禁用或删除；
- 全部启用或全部禁用；
- 删除已禁用 Key；
- 按状态筛选和分页查看。

![管理密钥页面](/assets/guide/feature-guide/channel-management-key-management.png)

<Callout type="warn">
删除 Key 后不能恢复。清理前应确认渠道仍有可用凭证；当所有 Key 都不可用时，渠道可能自动禁用或不再参与路由。
</Callout>

## 条件功能

以下操作只在对应渠道类型或配置条件满足时显示：

- Ollama 渠道的模型拉取、删除和版本查询；
- Codex 凭证刷新、用量和额度重置相关操作；
- 高级自定义路由；
- 特定协议的字段透传；
- 可从上游读取模型的渠道类型。

## 推荐配置流程

1. 确认管理员拥有所需的渠道权限，并准备好上游凭证；
2. 创建渠道，先完成基本信息、凭证、模型与分组；
3. 保存后执行详细测试，验证默认端点和代表性模型；
4. 按需配置优先级、权重、自动封禁、代理和覆盖规则；
5. 如果需要自动维护模型，再开启上游检查并审核首次检测结果；
6. 检查列表中的状态、响应时间、余额和上次测试时间；
7. 用实际用户分组和 API 密钥执行一次端到端请求；
8. 复制或批量操作后，再次核对名称、模型、分组和凭证。

## 故障排查

| 现象 | 建议检查 |
| --- | --- |
| 渠道无法保存 | 检查名称、类型、凭证、模型和分组是否填写；确认 JSON、代理、HTTP 协议和 HTTP/2 分片格式正确。 |
| 测试认证失败 | 检查 Base URL 是否为正确的上游地址、密钥是否过期、组织/项目/区域配置是否匹配。 |
| 模型不可见 | 检查渠道模型、模型映射、渠道分组、用户分组、API 密钥限制和模型元信息。 |
| 请求被路由到意外渠道 | 检查优先级、权重、标签聚合、渠道状态、请求路径和系统级重试设置。 |
| 渠道频繁自动禁用 | 查看失败状态码、错误原因和可靠性阈值；确认代理、上游限流和测试模型是否正常。 |
| 上游获取模型失败 | 检查渠道类型是否支持模型获取、凭证、/v1/models 路由和上游网络；失败不会自动替换原模型。 |
| 余额没有更新 | 确认渠道类型支持余额接口，并查看查询错误；不要把渠道余额与用户钱包余额混淆。 |
| 多 Key 渠道不可用 | 在多 Key 管理中检查每个 Key 的状态、禁用原因和剩余可用数量。 |
| 修复后仍然无法路由 | 等待索引重建完成，刷新列表后重新测试模型和分组；必要时检查所有渠道配置。 |

<Callout type="info">
排查具体请求时，可在[日志与异步任务](/zh/docs/guide/feature-guide/user/log)中按渠道、模型、请求 ID 或上游请求 ID 定位请求详情。
</Callout>
