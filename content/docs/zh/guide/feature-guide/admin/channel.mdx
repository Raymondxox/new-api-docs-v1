---
title: 渠道管理
description: 配置 AI 服务商渠道、模型、密钥、分组和可靠性策略。
---

渠道是 New API 连接上游 AI 服务商的核心配置单元。访问 `/channels` 查看渠道列表。Admin 默认拥有读取、测试、余额刷新、启停和非敏感路由编辑权限；创建/删除渠道、修改密钥、Base URL、代理或参数/请求头覆盖属于敏感写入，是否可用取决于 Root 配置的管理员权限。

## 创建渠道

1. 确认当前管理员拥有「敏感写入」权限，然后点击「创建渠道」。
2. 在基础信息中选择渠道类型、填写名称、Base URL 和认证信息。
3. 在模型区域填写或同步上游模型。
4. 在分组区域设置该渠道可被哪些分组使用。
5. 保存后在列表中确认渠道状态。

### 认证和 API 访问

不同渠道类型可能使用 API Key、Bearer Token、组织 ID、项目 ID、区域、服务账号或签名信息。渠道编辑器会根据渠道类型显示不同字段，编辑已有渠道时不会把原密钥回填到表单。

完整渠道密钥只能通过 Root 专属接口查看，并同时要求关键操作限流、禁止缓存和安全验证。权限目录中的「查看渠道密钥」是独立能力，但当前查看接口仍强制 Root；不要把授予该能力理解为普通 Admin 可以读取完整密钥。

### 模型和模型映射

模型列表决定用户可请求的模型。模型映射可把用户模型名转换为上游模型名，内容必须是有效 JSON；保存前用预览或测试请求验证。

## 高级配置

「路由与覆盖」以及「渠道额外设置」包含优先级、权重、测试模型、标签、参数覆盖、请求头覆盖、高级自定义路由、字段透传控制和上游模型更新检测等配置。

### 参数覆盖

简单模式直接填写要覆盖的 JSON 字段：

```json
{
  "temperature": 0.8,
  "max_tokens": 2000
}
```

高级模式使用 `operations` 数组，可执行 `set`、`delete`、`move`、`copy`、`append`、`prepend`、字符串规范化和正则替换，并可用 `conditions` 与 `logic` 控制执行条件。操作按数组顺序执行。

### 路由参数

| 参数 | 作用 |
| --- | --- |
| 优先级 | 同一分组和模型下按优先级从高到低选择；重试会继续尝试后续优先级 |
| 权重 | 在同一优先级候选渠道中进行加权选择；全部为 0 时按等权处理 |
| 测试模型 | 单渠道测试时优先使用的模型 |
| 自动禁用 | 由 Root 的路由可靠性规则根据状态码、关键词和阈值执行 |
| 标签 | 对渠道分组并执行批量操作 |

## 多 Key

创建渠道时可以选择单 Key、每行一个 Key 批量创建多个渠道，或把多个 Key 合并为一个多 Key 渠道。多 Key 渠道支持随机或顺序轮询；编辑时可追加或覆盖 Key。Codex 和部分特殊认证模式不支持批量/多 Key，界面会按渠道类型限制可选方式。

打开「多 Key 管理」可查看每个 Key 的启用、手动禁用和自动禁用状态，并执行单个或全部启停、删除单个 Key、清理已禁用 Key 等操作。

## 测试和批量操作

列表支持单渠道/批量测试、单个/全部余额刷新、拉取上游模型、批量启停、按标签编辑、复制渠道、修复能力表和删除禁用渠道。部分渠道还提供 Ollama 模型管理、Codex 账户与用量以及上游模型更新检测。测试和模型拉取可能产生上游请求或费用。

## 故障排查

1. 查看渠道状态、最近响应时间和错误次数。
2. 在“使用日志”中按渠道和状态筛选。
3. 检查模型映射、分组、参数覆盖和请求路径。
4. 使用单渠道测试确认上游凭证和 Base URL。
5. 若启用了自动禁用或渠道亲和，检查对应 Root 设置。
