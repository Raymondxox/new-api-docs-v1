运维配置位于 `/system-settings/operations`，仅 Root 可访问。页面包含「系统行为」「监控与告警」「SMTP 邮件」「Worker 代理」「日志维护」「性能」和「系统维护」七个分区。

这里的功能分别影响公开状态、通知发送、外部请求代理、数据库和服务器日志、请求体临时缓存以及 Relay 资源保护。它们不是一套统一的“维护模式”，各项配置的作用范围和验证方式不同。

## 保存与生效边界

系统行为、监控与告警、SMTP、Worker 和性能表单只提交发生变化的配置项，并按键逐项保存，不是整张表单的原子事务。后续字段保存失败时，之前成功的字段可能已经写入并生效。

日志维护还包含三类独立操作：保存消费日志开关、创建数据库日志清理系统任务，以及直接清理服务器日志文件。系统维护中的版本检查不写入系统设置。

敏感选项不会通过通用设置接口回显。SMTP Token 和 Worker Key 的输入框留空通常表示保留原值；需要轮换时填写新值。保存设置不会自动验证 SMTP、Worker、通知目标或外部网络是否可用。

<Callout type="warn">
  日志删除、缓存清理和强制 GC 都是即时运维操作，不属于可撤销的表单草稿。执行前先确认目标、影响范围和恢复方案，并避免在高峰期反复操作。
</Callout>

## 系统行为

系统行为分区包含三个实例级开关：

| 字段 | 实际作用与边界 |
| --- | --- |
| 默认折叠侧边栏 | 把 `default_collapse_sidebar` 作为兼容性默认偏好发布到公开状态。当前新版前端没有读取该字段，而是直接根据浏览器的 `sidebar_state` Cookie 决定初始展开状态；因此不能把此开关视为当前前端已生效的强制默认值。 |
| 演示站模式 | 把演示模式状态公开给前端，并影响部分演示站展示行为。它不是完整的只读模式、权限隔离或危险操作保护，不能替代角色权限和外部访问控制。 |
| 自用模式 | 隐藏部分面向注册用户的提示，并允许模型列表接受未配置倍率的模型；此时相关模型使用程序默认倍率 `37.5`。它不会关闭注册、认证或多用户能力。 |

默认侧边栏开关只需核对公开状态字段；当前新版前端仍依据 `sidebar_state` Cookie 决定初始状态。若实例用于演示站或自用模式，再使用普通用户、Root 和新浏览器会话检查界面、模型列表及实际权限，不要只根据设置页上的开关状态判断运行结果。

## 监控与告警

该分区包含用户剩余额度提醒和模型性能指标，两者用途不同。

### 额度提醒

「额度提醒阈值」使用内部 quota／Token 单位。Relay 结算链路会分别检查钱包和订阅额度：钱包按 `UserQuota - (quota + preConsumedQuota)` 比较，订阅按订阅总额减已使用量比较；低于阈值时异步发送额度不足通知。用户个人设置中非零的提醒阈值会优先于此全局值。当前钱包通知文本格式化的是 `UserQuota`，可能与触发比较使用的扣除后余额不同。

通知方式由用户设置决定，可以是邮件、Webhook、Bark 或 Gotify；未选择时默认使用邮件。通知失败只写入系统错误日志，不会回滚已经完成的扣费或请求结果。

<Callout type="info">
  使用邮件提醒前需要先完成本页 SMTP 配置；使用 Webhook、Bark 或 Gotify 时要检查对应用户通知设置和 SSRF 规则，只有配置了 Worker 时才需要进一步检查 Worker 地址、密钥和目标策略。阈值保存成功不代表通知链路已经可用。
</Callout>

### 模型性能指标

模型性能指标从 Relay 请求完成和计费链路收集模型、分组、请求耗时、首 Token 时间、成功率、输出 Token 和生成耗时，用于模型广场等性能展示。它不是 CPU、内存、磁盘或第三方 APM 监控。

| 字段 | 行为 |
| --- | --- |
| 启用模型性能指标 | 控制是否继续记录 Relay 性能样本。关闭后不会新增样本，刷盘循环也会跳过写库和过期清理；已有数据库记录不会自动删除，关闭前留在内存中的聚合桶也不会被立即清空。 |
| 刷盘间隔 | 至少 1 分钟，控制把已完成的内存聚合桶写入数据库以及执行过期数据清理的循环周期。它不是前端图表刷新频率。 |
| 聚合桶 | 可选择 1 分钟、5 分钟或 1 小时；修改后只影响后续样本的分桶。 |
| 保留天数 | `0` 表示不按天数自动删除；正数会在刷盘循环中清理更早的性能指标。 |

默认配置为启用、5 分钟刷盘、1 小时聚合桶、永久保留。选择较细的桶或较短的刷盘间隔会增加内存、数据库和后台写入负载；应结合模型数量、分组数量和请求量评估。

## SMTP 邮件

SMTP 用于注册验证码、密码重置、用户通知和其他系统邮件。主要字段包括主机、端口、账号、发件地址、密码或访问令牌，以及传输安全和认证兼容选项。

### 传输安全模式

页面把传输安全配置为三个互斥选项：

| 模式 | 行为与建议 |
| --- | --- |
| 无加密 | 直接建立明文 SMTP 连接。只适合受控内网或明确要求该模式的服务。 |
| SSL/TLS | 建立隐式 TLS 连接。即使没有显式选择，端口为 `465` 且未启用 STARTTLS 时，当前后端也会使用隐式 TLS。 |
| STARTTLS | 先建立普通 SMTP 连接，再要求服务器支持并升级到 STARTTLS；服务器未声明 STARTTLS 时发信失败。 |

「跳过 TLS 证书验证」允许自签名证书或主机名不匹配，但会削弱中间人攻击防护；只应用于经过评估的内部兼容场景。「强制 AUTH LOGIN」用于不兼容标准认证协商的 SMTP 服务，不会补齐错误账号或凭证权限。

SMTP 账号与 Token 都非空时才执行认证。发件地址留空时，后端会为兼容性回退到 SMTP 账号；生产环境仍应填写服务商允许的发件地址，并确认 SPF、DKIM、DMARC 和发件人策略。

SMTP 连接由后端直接建立，不经过 Worker 代理或 URL SSRF 校验；传输安全性由 SMTP 的 TLS、证书、认证配置和网络访问策略共同决定。

<Callout type="warn">
  SMTP Token 不会回显，留空保存不会清除旧凭证。当前页面没有“发送测试邮件”按钮；保存后必须通过验证码、密码重置或测试通知实际验证 DNS、端口、TLS、认证、发件人和投递结果。
</Callout>

> **截图建议：** SMTP 主机、端口和传输安全模式。遮盖账号、Token、内部主机名及证书例外信息。

## Worker 代理

Worker 代理用于源码中明确接入的服务端外部请求链路，例如远程文件或图片下载、用户 Webhook，以及 Bark 和 Gotify 通知。它不是渠道 Relay、支付、OAuth 或所有出站流量的通用代理。

| 字段 | 行为 |
| --- | --- |
| Worker URL | 必须为空或以 `http://`、`https://` 开头；保存时移除末尾 `/`。非空时相关链路才会把请求发送给 Worker。 |
| Worker Access Key | 随 Worker 请求发送，用于目标 Worker 校验来源；通用设置接口不会回显。 |
| 允许 HTTP 图片请求 | 关闭时 Worker 请求的目标 URL 必须以 HTTPS 开头；当前后端校验实际作用于所有 `DoWorkerRequest` 目标，不只图片。 |

Worker 负载可能携带目标 URL、请求头、通知内容和认证信息。`WorkerValidKey` 作为请求 JSON 的 `key` 字段发送，是否校验由 Worker 实现决定；New API 不使用它验证 Worker 响应，也不能用它替代目标 URL 的访问控制。普通下载、Webhook 和通知链路仍会在进入 Worker 前使用相应的 SSRF 校验，但 Worker URL 本身是 Root 配置的外部信任边界。

如果只把 Worker Access Key 输入框留空，页面会保留已有密钥；要清除旧密钥，需要同时清空 Worker URL，页面才会提交空的 `WorkerValidKey`。

<Callout type="warn">
  只使用由你控制并能审计日志的 Worker。启用 Worker 后，敏感通知或远程资源请求可能经过该服务；确认其 TLS、密钥验证、日志脱敏、超时、目标过滤和数据保留策略。
</Callout>

## 日志维护

日志维护分为消费日志开关、数据库历史日志清理和服务器日志文件清理。三者影响不同的数据源。

### 消费日志开关

「记录额度使用」控制是否创建逐请求的消费日志，包括普通 Relay 和异步任务结算产生的消费记录。关闭后会减少数据库写入，但使用日志、消费统计和依赖这些记录的分析将缺少新数据。

该开关不会停止错误、充值、管理审计、系统、退款或登录日志，也不会关闭服务器文本日志、Midjourney 任务表或异步任务表。已经存在的消费日志不会因关闭开关而删除。

### 数据库历史日志清理

选择时间并确认后，页面创建 `log_cleanup` 系统任务，删除 `logs` 表中严格早于该时间的记录。它删除的是该表中的所有日志类型，不只消费日志。

- 常规数据库按每批 100 条异步删除，并在页面显示进度、已处理数量和最终删除数。
- ClickHouse 日志库使用一次同步 mutation 删除全部匹配记录，执行特性与批量关系型数据库不同。
- 同一时间只能有一个待执行或运行中的 `log_cleanup`；再次提交会返回现有任务。
- 没有匹配记录时任务可以正常完成，并显示没有日志需要删除。

此操作不会清理 `quota_data` 聚合数据、性能指标、绘图与异步任务记录，也不会删除服务器上的日志文件。

### 服务器日志文件清理

服务器日志管理只在配置了日志目录时可用，并且只扫描该目录下名称匹配 `oneapi-*.log` 的文件。可以按以下方式清理：

- 按数量：按文件名降序保留前 N 个日志文件；文件命名异常时，这不一定等同于按修改时间保留最新 N 个文件；
- 按天数：删除修改时间早于 N 天前的日志文件。

两种方式都会跳过当前活动日志文件。部分文件删除失败时，接口会返回失败文件列表；已经成功删除的文件不会自动恢复。

<Callout type="warn">
  数据库日志和服务器日志文件的删除不可恢复。清理前确认审计、争议处理、支付、合规和故障排查所需的留存周期，并完成必要的数据库或日志归档。
</Callout>

> **截图建议：** 数据库日志清理时间、系统任务进度，以及服务器日志目录统计和保留方式。不要展示真实用户、请求或服务器路径中的敏感信息。

## 性能

性能分区同时管理请求体磁盘缓存、Relay 资源保护和当前进程统计。这些功能与「监控与告警」中的模型性能指标相互独立。

### 请求体磁盘缓存

启用后，达到阈值且未超过当前缓存容量边界的大请求体或文件数据会临时存到磁盘，以减少内存占用；不满足条件时继续使用内存。默认阈值为 10 MB，默认最大缓存大小为 1024 MB。

| 字段 | 行为与边界 |
| --- | --- |
| 磁盘缓存阈值 | 至少 1 MB；数据大小达到阈值后才考虑使用磁盘。 |
| 最大缓存大小 | 页面要求至少 100 MB。系统根据当前进程统计判断“现有用量 + 新请求大小”是否超过该值；它不是操作系统磁盘配额，也不能保证磁盘一定有相应可用空间。 |
| 缓存目录 | 非容器部署可以填写；留空使用系统临时目录下的 `new-api-body-cache`。容器环境不显示此字段，应通过挂载和容器存储策略管理。 |

磁盘缓存是请求生命周期中的临时存储，不是文件持久化或对象存储。磁盘创建失败时，部分链路会回退到内存；流式读取路径在 Reader 已被消费后可能直接返回错误。

### 系统资源保护

启用后，后台约每 5 秒采集 CPU、虚拟内存和缓存目录所在磁盘的使用率。当某个阈值大于 `0` 且最近快照的整数使用率严格高于阈值时，新 Relay 请求会被拒绝并返回 HTTP `503`。

资源保护中间件挂载在 Playground、`/v1`、Gemini、Midjourney 和 Suno 等 Relay 路径，不影响登录、普通管理 API 或全部后台任务。阈值 `0` 表示不检查该资源维度；CPU、内存和磁盘阈值建议配置在 1–100 之间。

<Callout type="info">
  资源保护使用周期性快照，不是排队或自动扩容系统。启用后通常每 5 秒更新一次；关闭期间监控循环最长约 30 秒才会重新检查配置，因此重新开启后短时间内可能仍读取上一份快照。流量尖峰也可能发生在两次采样之间；达到阈值的请求会直接失败，而不是等待资源恢复后自动重试。
</Callout>

### 性能统计与操作

页面显示当前 New API 进程中的磁盘／内存缓存用量和命中次数、活动缓存数量、缓存目录文件、磁盘空间、Go 内存以及 Goroutine 数量，并提供以下操作：

| 操作 | 实际影响 |
| --- | --- |
| 刷新统计 | 重新获取当前进程的统计信息。 |
| 清理不活跃缓存 | 删除缓存目录中修改时间超过 10 分钟的普通文件。实现只按文件修改时间判断，没有额外核对文件是否仍被请求引用；高峰期或存在长时间请求时应谨慎执行。 |
| 重置统计 | 只清零磁盘和内存缓存命中次数，不清空活动缓存、当前用量或目录文件。 |
| 执行 GC | 在当前 Go 进程中立即调用垃圾回收；可能造成短暂延迟抖动。 |

多实例部署时，这些统计和操作只作用于收到管理请求的实例，不会自动遍历其他节点。

> **截图建议：** 磁盘缓存和资源保护设置，以及性能统计面板。遮盖自定义缓存目录和内部磁盘布局。

## 系统维护

系统维护分区展示 `/api/status` 返回的当前版本和进程启动时间，并允许浏览器检查 GitHub Release。

点击「检查更新」时，浏览器直接请求：

```text
https://api.github.com/repos/Calcium-Ion/new-api/releases/latest
```

页面只读取 Release 的标签、名称、正文、链接和发布时间。当前实现仅比较远端 `tag_name` 与当前版本字符串是否完全相等；没有执行语义版本大小判断，因此任何不相等的标签都会按“有可用版本”展示。浏览器无法访问 GitHub、请求受到限流，或响应没有标签时，检查会失败。

<Callout type="warn">
  更新检查不会下载代码、验证升级兼容性、替换二进制、拉取镜像、迁移数据库、重建容器、重启服务或自动回滚。查看 Release 后，应按照实际部署方式制定备份、测试、升级和恢复流程。
</Callout>

> **截图建议：** 七个运维分区的导航，以及「检查更新」后的 Release 结果。不要展示内部版本分支、部署地址或其他敏感运维信息。

## 变更后验证

1. 每保存一个多字段分区后刷新页面，逐项确认是否存在部分成功；在多实例环境中为配置同步预留时间。
2. 检查公开状态是否包含默认侧边栏偏好，并用当前新版前端确认它仍由 `sidebar_state` Cookie 控制；再分别使用普通用户和 Root 验证演示站、自用模式及实际角色权限。
3. 用测试用户把余额降到阈值以下，分别验证邮件、Webhook、Bark 或 Gotify；确认通知失败不会改变结算结果。
4. 产生可控的 Relay 请求，等待至少一个性能指标刷盘周期，再检查模型广场中的延迟、成功率和分组数据。
5. 通过验证码或测试通知验证 SMTP 的 DNS、端口、TLS、认证、发件人和投递；轮换凭证后确认旧凭证已失效。
6. 对每条使用 Worker 的下载或通知链路分别测试 HTTPS、目标拒绝、Worker 密钥错误和超时，确认请求没有意外绕过网络策略。
7. 在备份或测试数据上执行数据库与服务器日志清理，核对删除阈值、任务进度、保留文件和失败列表。
8. 使用超过磁盘缓存阈值的测试请求验证内存／磁盘选择，并模拟资源超过阈值时的 Relay `503`；同时确认管理页面仍可访问。
9. 从运行管理页面的浏览器检查 GitHub 网络和 Release 展示，再按部署文档手动完成升级演练。

## 常见问题

- **修改默认侧边栏后当前前端没有变化**：该值已发布到公开状态，但当前新版前端只读取 `sidebar_state` Cookie，尚未消费该设置；清除 Cookie 只会回到前端自身的默认展开状态。该配置主要供兼容客户端使用。
- **开启演示站后危险操作仍可执行**：演示模式不是完整的权限或只读策略。应使用角色权限、网络边界、只读数据副本和外部访问控制保护演示实例。
- **开启自用模式后仍能注册或看到多个用户**：该开关不会关闭多用户与注册接口；要限制注册请在身份验证配置中关闭对应能力。
- **额度已低于阈值但没有通知**：检查用户是否设置了个人阈值和通知方式，再检查 SMTP、Webhook、Bark、Gotify、Worker、SSRF 与服务端错误日志。
- **模型性能指标没有立即出现**：样本先进入聚合桶，已完成的桶按刷盘周期写库。检查总开关、模型名、分组、桶时间和保留设置，并等待完整周期。
- **SMTP 保存后仍无法发信**：页面不测试连接。核对主机、端口、安全模式、证书、账号、Token、发件地址和服务商限制；端口 465 还会触发隐式 TLS 行为。
- **Worker 已配置但渠道请求仍直连上游**：Worker 只用于明确接入的下载和通知链路，不是模型渠道的通用网络代理。
- **关闭消费日志后仍有错误或管理日志**：该开关只控制消费类型日志；其他日志类型按各自流程继续记录。
- **清理数据库日志后看板历史数据仍存在**：日志任务只删除 `logs` 表，不会删除 `quota_data` 聚合、性能指标或任务记录。
- **清理服务器日志后仍保留一个旧文件**：当前活动日志始终跳过；按数量清理还会保留指定的最新文件数。
- **磁盘缓存达到上限后请求失败了吗**：系统通常改用内存；部分流式读取链路在磁盘创建失败且 Reader 已消费时可能直接报错。上限也不是磁盘配额保证。
- **资源使用率达到阈值但请求没有被拒绝**：比较条件是严格高于阈值，并使用最近一次采样的整数值；阈值为 `0` 时该维度不检查。
- **检查更新显示的版本并不比当前版本新**：页面只判断标签字符串是否相等，不做语义版本排序。请打开 Release 并人工核对版本、分支和升级路径。
