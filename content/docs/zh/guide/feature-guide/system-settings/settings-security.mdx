安全与限制配置位于 `/system-settings/security`，仅 Root 可访问。页面包含「速率限制」「敏感词」「SSRF 防护」和「Token 限制」四个分区。

这些设置分别作用于模型 Relay 请求、可提取的提示文本、服务端受保护的外部抓取，以及用户新建 API Token。它们不是一套覆盖全部 Web、管理 API、异步任务和上游请求的统一安全策略。

## 模型请求限流

「速率限制」用于按用户限制模型 Relay 请求，启用后可以配置限流周期、周期内总请求上限、成功请求上限和分组覆盖规则。

### 作用范围与计数维度

当前中间件挂载在 `/v1` 和 `/v1beta` 的模型 Relay 路由上，包括这些路由下实际实现的文本、图片、音频、嵌入、重排等请求。它不等同于登录、注册、管理 API、用户异步任务、Midjourney 或 Suno 路由的限流；这些路径可能还有由环境变量或其他中间件控制的独立限制。

| 字段 | 行为与边界 |
| --- | --- |
| 启用速率限制 | 总开关。关闭后，本分区的模型请求限流不执行，但其他 Web/API 限流仍可能返回 `429`。 |
| 限制周期 | 总请求和成功请求共同使用的时间窗口，单位为分钟。生产环境应使用大于 `0` 的整数。 |
| 每周期最大请求数 | 统计进入本限流中间件的请求，包括之后失败的请求；`0` 表示不启用这一维度。 |
| 最大成功请求数 | 只应允许在周期内完成的成功请求数量；当前页面要求至少为 `1`。 |
| 分组速率限制 | 为指定分组覆盖全局的总请求和成功请求上限，仍共用全局限制周期。 |

请求达到限制时会被拒绝，通常返回 HTTP `429`，不会进入等待队列或延迟到下一个周期自动执行。

### 分组规则

分组规则可以使用可视化编辑器，也可以切换为 JSON。格式为：

```json
{
  "default": [200, 100],
  "vip": [0, 1000]
}
```

数组第一项是总请求上限，允许为 `0`；第二项是成功请求上限，必须至少为 `1`。配置了当前分组后，该组的两个数值会一起覆盖全局值。

系统优先按请求所用 API Token 的分组匹配规则；Token 没有指定分组时才回退到用户分组。规则名应与实际分组名完全一致，不要填写展示名称、正则表达式或通配符。

### Redis 与单进程模式

启用 Redis 时，限流状态保存在 Redis 中；连接同一 Redis 的实例可以共享相应计数。未启用 Redis 时，计数只保存在当前进程内存，多实例之间不共享，因此部署的总可用请求量可能随实例数增加。

<Callout type="warn">
  当前无 Redis 路径在检查“成功请求上限”时会使用独立的内存检查计数；它与请求结束后记录的实际成功计数不是同一个键。因此，不应把无 Redis 模式下的成功请求限制视为与 Redis 路径完全等价。对成功次数有严格要求或使用多实例时，应在测试环境验证实际行为，并优先使用共享 Redis 或外部网关限流。
</Callout>

## 敏感词检查

敏感词分区包含两个开关和一份关键词列表。只有「启用过滤」与「检查用户提示词」同时开启时，请求 Relay 流程才会执行提示文本检查；只开启其中一个不会生效。关键词一行一个，保存时会移除空行和每行首尾空白，匹配不区分大小写。

检查发生在请求解析之后、请求发往上游之前。系统从当前请求格式的 Token 计数元数据中获取可拼接的文本并进行关键词匹配，例如常见消息文本、提示词、嵌入输入或重排文本。该过程有以下边界：

- 只检查当前请求格式能够提取到的文本，不保证覆盖所有扩展字段、工具参数、文件正文或多媒体二进制内容；
- 图片 URL 等非文本内容不会作为图片本身进行识别；
- 命中关键词后会阻断请求并返回敏感词错误，不会自动替换后再发往上游；
- 当前 Relay 流程没有启用模型输出的敏感词检查，因此本功能不是输出审核系统。

清空关键词列表会使匹配结果为空，即使两个开关仍保持开启也不会阻断内容。添加或调整规则后，应使用无敏感词、大小写变化、嵌入输入、图片和文件等代表性请求分别验证，避免误以为所有输入类型都已覆盖。

<Callout type="info">
  关键词匹配是直接的文本包含检查，不理解上下文、否定关系或语义。常见短词可能造成大量误报；上线前应先用测试账户和真实请求样本校验。
</Callout>

## SSRF 防护

SSRF 防护用于限制 New API 在明确受保护的功能链路中访问外部 URL。启用后，目标必须使用 HTTP 或 HTTPS，并按私有/特殊用途 IP、域名规则、IP/CIDR 规则和允许端口进行检查。

### 规则字段

| 字段 | 作用与建议 |
| --- | --- |
| 启用 SSRF 防护 | 总开关。关闭后，受保护的抓取客户端会退回普通 HTTP 客户端，其他过滤字段不再提供该层保护。生产环境应保持开启。 |
| 允许私有 IP | 允许私有、回环、链路本地及其他特殊用途地址。仅在经过隔离的可信内网集成中开启。 |
| 域名过滤模式 | 黑名单只拒绝列表中的域名；白名单只允许列表中的域名。域名列表每行一项，支持精确域名和 `*.example.com`。 |
| IP 过滤模式 | 黑名单拒绝列表中的 IP/CIDR；白名单只允许列表中的 IP/CIDR。IP 列表每行一项。 |
| 允许端口 | 当前表单按逗号分隔解析单个端口，例如 `80,443,8080`；留空表示不额外限制端口。 |
| 对解析后的域名应用 IP 过滤 | 访问域名时同时检查 DNS 解析结果，并在实际直连拨号前使用已校验的 IP，降低域名解析到私网地址及 DNS 重绑定的风险。 |

当过滤模式设为白名单且对应列表为空时，不会“允许全部”，而是没有目标能匹配该白名单；黑名单模式下空列表则表示没有额外的列表项可阻断。建议先填写列表，再切换到白名单模式并保存。端口必须处于 `1`–`65535`；虽然后端解析器支持端口范围，当前管理表单会把输入按逗号转换为数字数组，因此应按页面支持的单端口格式填写。

启用「对解析后的域名应用 IP 过滤」时，只要域名解析出的任一地址不满足 IP 和私有地址规则，请求就会被拒绝。通过受保护客户端发起直连时，系统还会在拨号阶段重新解析并校验地址；HTTP 重定向目标也会再次检查。

<Callout type="warn">
  「允许私有 IP」会放开比常见 RFC 1918 私网更广的特殊地址范围，包括回环、链路本地和部分保留地址。不要仅为了让一个内网服务可用而在公网实例上全局开启；优先使用严格的域名、IP 和端口白名单，并测试云元数据地址等敏感目标仍被阻断。
</Callout>

### 保护链路与非覆盖范围

当前源码在以下显式链路使用 SSRF 校验或受保护的 HTTP 客户端：

- 用户请求中需要由服务端下载的远程图片或文件；
- 用户配额通知的 Webhook、Bark 和 Gotify 请求；
- Midjourney 图片代理和视频结果代理；
- 下载 Worker 接收的目标 URL 及其非 Worker 回源流程；
- 其他明确调用受保护抓取客户端的外部下载。

本设置不会自动包住所有出站网络请求。渠道 Base URL、渠道代理和供应商适配请求由 Root 管理，使用通用 Relay HTTP 客户端，可以合法指向私有网络、自托管服务或私有链路，因此不受本页 SSRF 规则普遍拦截。支付网关、OAuth、SMTP 等其他管理员配置的外部连接也应按各功能自身的验证和网络策略评估。

## API Token 数量上限

「Token 限制」设置每个用户最多可创建的 API Token 数量，页面要求至少为 `1`，默认值为 `1000`。用户提交新建 Token 时，后端会统计该用户已有 Token；数量达到或超过上限后，本次新建会被拒绝。

修改上限不会自动删除、禁用、过期或更改已有 Token。若把上限调低到某些用户当前持有数量以下，这些 Token 仍然可用，但用户不能继续新建，直到其数量低于新上限。已有 Token 的状态、额度、有效期、模型范围、IP、分组和请求频率仍在用户自己的 API Token 编辑器中配置，与本字段无关。

<Callout type="info">
  该上限用于控制凭证数量和列表规模，不是单个 Token 的调用频率限制。设置过大可能增加列表、统计和搜索成本；超过当前上限的用户还会失去使用 `%` 通配符进行模糊 Token 搜索的能力，只能精确搜索。
</Callout>

## 保存与验证

四个分区分别保存发生变化的配置项，不是一次性提交整页的原子事务。修改前记录原值，并按以下顺序验证：

1. 使用测试 Token 发送 `/v1` 或 `/v1beta` 请求，分别验证全局限流、分组覆盖、成功与失败请求以及 `429` 响应。
2. 如果使用多实例，分别验证所有节点是否连接同一 Redis；未使用 Redis 时按每个进程独立计数评估容量。
3. 使用无敏感词、命中关键词和非文本输入测试提示词检查，确认阻断范围符合预期。
4. 对 SSRF 规则分别测试允许域名、禁止域名、公网 IP、私有 IP、非允许端口和重定向；同时复测远程图片、文件、Webhook 和媒体代理。
5. 用接近 Token 上限的测试用户验证新建被拒绝、删除后可再次新建，并确认已有 Token 未被改变。

## 常见问题

- **关闭模型限流后仍收到 `429`**：检查环境变量控制的全局 Web/API 限流、关键操作限流、搜索限流，以及上游供应商自身的限制。本页只控制模型 Relay 中间件。
- **分组规则没有生效**：确认规则名与实际 Token 分组完全一致；Token 分组优先于用户分组。再确认总开关已开启并保存。
- **设置成功请求上限后，非 Redis 环境的结果与预期不同**：当前内存实现的成功检查计数与实际成功记录存在差异，不能按 Redis 语义推导。需要严格一致时使用共享 Redis 或外部限流层。
- **敏感词开关已开但请求未被阻断**：确认两个开关都已开启、列表非空，并检查该请求格式是否能把目标字段提取为提示文本。文件和多媒体内容不会被完整扫描。
- **敏感词误伤正常请求**：匹配不区分大小写且不理解语义；缩短或删除过于宽泛的词条，再用真实请求样本验证。
- **开启 SSRF 后远程图片、文件或通知失败**：检查协议、域名/IP 黑白名单、私有 IP 开关、端口和域名解析结果；重定向后的地址也必须通过规则。
- **域名白名单中的服务仍被拒绝**：如果同时启用了域名解析后的 IP 过滤，还要把其解析 IP 或网段加入 IP 白名单，并确认没有命中私有/特殊地址限制。
- **渠道的内网 Base URL 没有被 SSRF 规则阻止**：这是当前职责边界。渠道地址由 Root 管理并走通用 Relay 客户端；本页保护的是显式的外部抓取链路。
- **降低 Token 上限后已有 Token 仍能调用**：上限只在新建时检查，不会回收已有凭证。需要停用旧 Token 时由用户删除或在相应管理流程中处理。
