计费与支付配置位于 `/system-settings/billing`，仅 Root 可访问。

## 计费与支付配置简介

该工作区包含「额度设置」、「货币与展示」、「模型定价」、「分组定价」、「支付网关」、「签到奖励」六个分区。用于配置模型和工具定价、分组倍率、邀请奖励与额度预扣、货币汇率及显示、充值规则与支付网关，以及签到奖励。

| 分区 | 入口 | 主要用途 |
| --- | --- | --- |
| [额度设置](#额度设置) | `/system-settings/billing/quota` | 新用户额度、预扣、邀请奖励及外部链接。 |
| [货币与展示](#货币与展示) | `/system-settings/billing/currency` | 金额显示模式、汇率与 Token 统计。 |
| [模型定价](#模型定价) | `/system-settings/billing/model-pricing` | 模型价格、表达式、工具价格及上游同步。 |
| [分组定价](#分组定价) | `/system-settings/billing/group-pricing` | 调用与充值倍率、用户可用分组及 Auto 顺序。 |
| [支付网关](#支付网关) | `/system-settings/billing/payment` | 合规确认、充值规则及各网关凭证和回调。 |
| [签到奖励](#签到奖励) | `/system-settings/billing/checkin` | 每日签到开关和奖励范围。 |

配置时先区分四种量：
1. **内部额度 quota** 是余额和扣费的计量单位；
2. **显示金额**是 quota 格式化后的结果；
3. **模型费用**由请求用量和价格规则计算；
4. **网关实收**由各支付渠道的订单决定。

<Callout type="warn">
  计费与支付配置会影响扣费、余额和支付入账。修改前需记录原配置，用测试用户核对价格，并在支付服务商允许的测试环境中验证。注意保管 API 密钥、Webhook 密钥、RSA 私钥、完整签名或含凭证的请求 URL。示例图中的模型、金额、商户和产品均是示例，不是推荐值或可直接使用的凭证。
</Callout>

## 配置分区

### 额度设置

配置新用户初始额度、邀请双方奖励、请求预扣及免费模型预扣开关，以及充值和文档链接。

<div className="[&_table]:min-w-[48rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 页面字段 | 默认或填写要求 | 说明 |
| --- | --- | --- |
| 新用户额度 | 默认 `0`；填写非负整数 quota | 授予新用户的初始配额，不追补已有用户。 |
| 预消耗配额 | 默认 `500`；填写非负整数 | 向用户收费前消耗的配额。 |
| 邀请者奖励 | 默认 `0`；填写非负整数 quota | 符合条件的邀请注册后，授予邀请人的配额。 |
| 受邀者奖励 | 默认 `0`；填写非负整数 quota | 授予被邀请人的配额。 |
| 免费模型预消耗 | 默认开启 | 启用后，零成本模型也会在最终结算前预先消耗配额。 |
| 充值链接 | 默认空 | 供用户购买配额的外部链接，不会自动接入该网站的支付回调。 |
| 文档链接 | 默认 `https://docs.newapi.pro` | 站点文档入口，也供顶部导航等位置使用。 |

</div>

**操作流程**

1. 核对额度单位。
2. 设置新用户额度、预扣和奖励；配置正数邀请奖励前，先到支付网关确认合规声明。
3. 填写充值、文档链接并保存，刷新检查非敏感字段。
4. 用新建测试用户验证初始额度；用邀请注册验证双方奖励，用请求日志核对预扣与最终费用。

### 货币与展示

配置额度的显示模式、货币符号与换算汇率，以及是否展示 Token 用量统计。

<div className="[&_table]:min-w-[48rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 页面字段 | 默认或填写要求 | 说明 |
| --- | --- | --- |
| 显示模式 | 默认 `USD` ；可选`USD`、`元`、`自定义货币`| 选择如何向用户展示配额值。 |
| 美元汇率 | 后端默认 `7.3`；表单最小 `0.0001` | 美元与您的支付网关货币之间的实际汇率。 |
| 自定义货币符号 | 默认 `¤`；仅自定义货币 时必填，最多 8 字符 | 显示价格时使用的前缀；仅 CUSTOM 模式显示。 |
| 每 USD 单位数 | 默认 `1`；仅自定义货币 时必填，最小 `0.0001` | 从美元到您的自定义货币的转换率，表示 `1 USD = X` 个自定义货币单位。 |
| 显示 Token 统计信息 | 默认开启 | 在用户界面中显示令牌使用统计信息。 |

</div>

**操作流程**

1. 选择货币显示模式 USD、元 或 自定义货币；使用 自定义货币 时需填写自定义货币符号以及每 USD 单位数。
2. 填写相关配置信息，核对 Token 统计信息开关，保存。
3. 在钱包、价格页和日志中对照同一笔额度，确认货币符号、小数和换算值。

### 模型定价

模型定价配置页分为「模型价格」「未设置价格的模型」「工具价格」「上游价格同步」四个标签。配置模型计费模式、各类用量价格与计费表达式、工具调用价格，并支持补全未定价模型和同步上游价格。

<Callout type="warn">
配置或编辑模型价格时，计费模式推荐使用计费表达式；「按 Token」、「按次」为已弃用的计费模式，但仍可在对应界面将旧数据编辑转换为计费表达式。
</Callout>

#### 模型价格

列表用于搜索、检查和维护模型价格，不会自动给渠道增加模型。价格配置应与请求使用的模型标识和实际计费路径一致。

- 计费与支付-模型价格-模型价格
![模型价格](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-model-prices.png)

- 添加或修改流程

1. 搜索模型并编辑，或点击添加模型定价。新建时填写准确模型名，编辑时模型名不可直接更改。
2. 选择定价货币和模式，设置价格或表达式。模板只是起点，先核对当前供应商价格和缓存规则。
3. 输入已知用量检查估算；含请求条件时，再模拟请求体、请求头和时间。
4. 点击保存模型价格，并确认列表及刷新后的价格符合预期。
5. 用测试请求在日志中核对真实用量、分组倍率和最终费用。

- 基础字段

<div className="[&_table]:min-w-[48rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 页面字段 | 默认或填写要求 | 说明 |
| --- | --- | --- |
| 模型名称 | 新建必填 | API 请求中使用的确切模型标识符。 |
| 定价货币 | USD | 系统底层统一使用美元计价。选择站点货币是为了方便输入和换算，金额会按站点汇率转换为美元。切换货币不会改变实际价格；原始计费表达式始终使用美元。 |
| 计费模式 | 计费表达式 or 按Token or 按次 | 推荐使用计费表达式；「按 Token」、「按次」为已弃用的计费模式，但仍可在对应界面将旧数据编辑转换为计费表达式。 |
| 编辑器模式 | 可视化编辑器或表达式编辑器 | 原始表达式和预设使用美元。货币选择仅换算可视化价格输入和金额预览。 |
| 预设模板 | 按实际模型选择 | 包括固定、阶梯、多模态、请求规则和时间条件；应用预设会替换当前编辑内容，仍需核对和保存。 |
| 档位名称 | 为各档位使用可识别名称 | 用于标识命中的价格档位，例如 `base`、`standard`。 |
| 档位计费模式 | 按 Token 或 按每次调用 | Token 单价按每百万对应 Token 填写；每次调用 按每次请求价格填写 USD/请求的固定金额。 |
| 阶梯条件与顺序 | 按业务设置 | 点击「添加计费分支」可添加计费阶梯条件，阶梯条件内可增加对时间、完整输入长度、计费输入token、计费输出token的条件组；从前向后匹配，首条命中决定档位；兜底档位处理此前均未命中的请求。 |

</div>

- Token价格与媒体价格参数说明

价格单位均为 单位货币 / 百万 Token（单位货币/1M token）。

| 参数名称 | 表达式变量 | 定义说明 |
| --- | --- | --- |
| 输入价格 | `p` | 输入 Token 的基础单价。 |
| 输出价格 | `c` | 模型输出 Token 的基础单价。 |
| 缓存读取价格 | `cr` | 复用已有提示词缓存时，命中缓存的输入 Token 单价。 |
| 缓存创建（5m） | `cc` | 创建有效期为 **5 分钟**的提示词缓存时，写入缓存的 Token 单价。 |
| 1 小时缓存写入价格 | `cc1h` | 创建有效期为 **1 小时**的提示词缓存时，写入缓存的 Token 单价。 |
| 图像输入价格 | `img` | 输入图片对应的图像 Token 单价。 ||
| 图片缓存输入价格 | `img_cr` | 命中缓存的图像输入 Token 单价；需要上游提供有效的图片缓存用量明细。 |
| 图像输出价格 | `img_o` | 模型生成图片对应的图像输出 Token 单价。 |
| 音频输入价格 | `ai` | 输入音频对应的音频 Token 单价。 |
| 音频输出价格 | `ao` | 模型生成音频对应的音频 Token 单价。 |

- 请求模拟参数说明

| 字段／控件 | 定义与作用 | 填写要求或说明 |
| --- | --- | --- |
| 请求模拟 | 展开或收起模拟区域，预览当前规则下的费用。 | 输入变化后自动重算，无需点击运行按钮。 |
| 模拟请求体 | 为计价规则提供请求参数。 | 必须是 JSON 对象，如 `{"priority":true}`；无参数时填写 `{}`。 |
| JSON 状态标识 | 提示 JSON 语法是否有效。 | 绿色标识只代表语法通过，不代表满足所有字段要求。 |
| `1:1` | 编辑器光标位置。 | 表示第 1 行、第 1 列，不参与计费。 |
| 复制／格式化 JSON | 复制编辑器内容，或整理缩进与换行。 | 格式化不会修复错误语法。 |
| 模拟请求头 | 为请求头相关计价规则提供测试数据。 | 名称和值按键值对填写；值必须是字符串。 |
| JSON 模式／添加行 | 切换请求头编辑方式，或新增请求头。 | 如 `{"tier":"fast"}`，等同于添加名称为 `tier`、值为 `fast` 的一行。 |
| 模拟时间 | 选择计价规则使用的模拟时刻。 | 支持“当前时间”和“指定时间”。 |
| 指定时间输入框 | 固定测试时刻，便于复现分时价格。 | 必须带时区，如 `2026-09-18T09:00:00+08:00`；`Z` 表示 UTC。 |
| 时间函数时区提示 | 说明时间条件按表达式内的时区判断。 | 输入时间确定时刻，表达式中的时区决定对应的小时、星期等。 |
| 模拟请求费用 | 当前测试条件下的费用结果。 | **包含请求规则，不包含分组倍率**。 |
| 命中档位 | 本次计算使用的计价档位名称。 | 图中的 `base` 是档位名称，不是用户分组。 |

- 请求规则计费与模拟

| 字段或操作 | 填写要求 | 说明 |
| --- | --- | --- |
| 请求体参数 | 参数路径、比较方式和值 | 读取请求 JSON 路径；例如按 `service_tier` 区分服务等级。 |
| 请求头条件 | Header 名称、比较方式和值 | 根据实际发送的请求头匹配。 |
| 时间条件 | 时间项、时区、比较值或范围 | 明确时区，例如 `Asia/Shanghai`。 |
| 规则组倍率 | 填入业务所需倍率 | 同组条件同时满足才命中；多个命中组的倍率相乘，小于 `1` 表示折扣。 |
| Token 估算器 | 输入、输出、缓存和媒体用量 | 检查基础费用和命中档位，不含用户/分组倍率；指定完整输入长度可单独测试阶梯边界。 |
| 模拟请求体 | JSON 对象 | `{}` 表示未提供相应字段。 |
| 模拟请求头 | 键值行或 JSON | 可添加、删除行，用于检验 Header 条件。 |
| 模拟时间 | 当前或指定时间 | 用于验证时间规则，表达式中的时区仍生效。 |
| 模拟请求费用 | 查看结果与命中条件 | 包含请求规则，不含分组倍率；不是已发起上游请求或最终账单。 |

#### 计费表达式部分说明

- 计费用量变量

| 变量     | 名称                 | 定义                                               |
| -------- | -------------------- | ------------------------------------------------------------ |
| `len`    | 完整输入上下文长度   | 用于按长度选择档位。 |
| `p`      | 基础输入 Token       | 按输入基础价计费的用量。 |
| `c`      | 基础输出 Token       | 按输出基础价计费的用量。 |
| `cr`     | 缓存读取 Token       | 命中并复用提示词缓存的输入用量。 |
| `cc`     | 缓存创建 Token       | Claude 的 5 分钟缓存创建用量；其他上游用量语义中为通用缓存创建用量。 |
| `cc1h`   | 1 小时缓存创建 Token | Claude 的 1 小时缓存创建用量。`1h` 是缓存有效期。 |
| `img`    | 图像输入 Token       | 输入图像对应的 Token 用量。 |
| `img_cr` | 图片缓存读取 Token   | 命中缓存的图像输入用量。 |
| `img_o`  | 图像输出 Token       | 模型生成图像对应的输出 Token 用量。 |
| `ai`     | 音频输入 Token       | 输入音频对应的 Token 用量。 |
| `ao`     | 音频输出 Token       | 模型生成音频对应的输出 Token 用量。 |

- 函数与参数定义

| 函数                | 参数定义                                         | 作用／返回值                                                 | 示例                                                         |
| ------------------- | ------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `tier(name, value)` | `name`：档位名称字符串；`value`：计价表达式。    | 返回计价结果，同时记录命中档位名称。                         | `tier("base", p * 2 + c * 8)`                                |
| `fixed(amount)`     | `amount`：有限、非负的数值常量，单位为美元／次。 | 设置按次基础价格，必须直接写在 `tier()` 的第二个参数位置。   | `tier("request", fixed(0.01))`                               |
| `max(a, b)`         | 两个数值。                                       | 返回较大值，可用于设置计算下限。                             | `max(p * 2 + c * 8, 1000)` 对应 Token 表达式费用至少 0.001 美元。 |
| `min(a, b)`         | 两个数值。                                       | 返回较小值，可用于限制某项计算值。                           | `min(p, 100000)` 返回不超过 100,000 的输入用量。             |
| `ceil(x)`           | 一个数值。                                       | 向上取整。                                                   | `ceil(1.2)` 得到 `2`。                                       |
| `floor(x)`          | 一个数值。                                       | 向下取整。                                                   | `floor(1.8)` 得到 `1`。                                      |
| `abs(x)`            | 一个数值。                                       | 返回绝对值。                                                 | `abs(-2)` 得到 `2`。                                         |
| `header(name)`      | `name`：请求头名称字符串。                       | 返回请求头字符串；名称忽略大小写，名称和值去除两端空白；缺失时返回空字符串。 | `header("service-tier") == "priority"`                       |
| `param(path)`       | `path`：请求体字段路径字符串。                   | 返回请求体字段值，保留字符串、数值、布尔值等类型；缺失时为 `nil`。支持点分隔的嵌套路径。 | `param("service_tier") == "priority"`、`param("stream_options.fast_mode") == true` |
| `has(source, text)` | `source`：待检查的值；`text`：查找的子串。       | 将非空值转为文本后进行区分大小写的子串检查；来源为 `nil` 或查找文本为空时返回 `false`。 | `has(header("anthropic-beta"), "fast-mode")`                 |

- 时间函数

| 函数          | 返回值                                | 示例含义                                                 |
| ------------- | ------------------------------------- | -------------------------------------------------------- |
| `hour(tz)`    | 小时，`0–23`。                        | `hour("Asia/Shanghai") >= 21` 表示当地时间 21 点及以后。 |
| `minute(tz)`  | 分钟，`0–59`。                        | `minute("UTC") < 30` 表示当前小时的前 30 分钟。          |
| `weekday(tz)` | 星期，`0–6`；`0` 为周日，`6` 为周六。 | `weekday("Asia/Shanghai") == 0` 表示周日。               |
| `month(tz)`   | 月份，`1–12`。                        | `month("Asia/Shanghai") == 12` 表示 12 月。              |
| `day(tz)`     | 当月日期，`1–31`。                    | `day("Asia/Shanghai") == 1` 表示每月 1 日。              |

- 常用语法

| 语法                             | 含义                         | 示例                                                         |
| -------------------------------- | ---------------------------- | ------------------------------------------------------------ |
| `+`、`-`、`*`、`/`               | 加、减、乘、除。             | `p * 2 + c * 8`                                              |
| `>`、`>=`、`<`、`<=`             | 大小比较，返回真假。         | `len <= 200000`                                              |
| `==`、`!=`                       | 相等、不相等。               | `param("priority") == true`                                  |
| `&&`                             | 逻辑“且”，两个条件都满足。   | `len < 32000 && c < 200`                                     |
| `\|\|`                           | 逻辑“或”，至少一个条件满足。 | `hour("UTC") >= 21 \|\| hour("UTC") < 6`                     |
| `!`                              | 逻辑取反。                   | `!(param("priority") == true)`                               |
| `条件 ? A : B`                   | 条件为真执行 A，否则执行 B。 | `len <= 200000 ? tier("short", p * 2) : tier("long", p * 4)` |
| `(...)`                          | 分组，明确计算顺序。         | `(基础表达式) * (条件 ? 2 : 1)` 是结构示意，需替换其中中文占位内容。 |
| `"文本"`、`true`、`false`、`nil` | 字符串、布尔值与空值。       | `true` 与 `"true"` 不是同一种类型。                          |

<Callout type="info">

- 推荐使用LLM辅助设计提示词，让LLM辅助设计计费表达式：

1. 打开辅助面板；在计价配置中选择“表达式编辑器”，点击“LLM 辅助设计提示词”；展开后可查看内置提示词。
2. 复制提示词；点击面板右侧的“复制提示词”； 出现复制成功提示后，提示词已写入剪贴板；若复制失败，可选中文本手动复制。
3. 粘贴到 LLM；打开 ChatGPT、Claude 等工具，将提示词粘贴到对话输入框；保留内置的语法说明，便于模型按系统支持的格式设计表达式。
4. 补充计价需求；在提示词后追加模型名称、价格、计价方式、档位条件及倍率规则；明确价格单位；若修改已有方案，附上当前表达式并说明需要调整的部分。不要仅凭模型名称让 LLM 猜测价格。
5. 生成表达式；发送完整内容，要求 LLM 返回可直接粘贴的表达式、规则解释和测试样例；对缺少或有歧义的信息，要求先确认，不要自行补全价格和规则。
6. 核对并粘贴；检查价格、变量、条件边界和倍率，将表达式复制回输入框；只粘贴表达式正文，不包含 Markdown 代码围栏、解释文字或测试数据。
7. 验证结果；在 Token 估算器填写用量；涉及请求或时间条件时，再使用“请求模拟”；检查费用和命中档位，并测试阈值前、阈值上、阈值后，以及字段缺失等场景。请求模拟不包含分组倍率。
8. 修正并保存；如果结果不符，将表达式、报错或测试输入、实际结果、期望结果反馈给 LLM；验证通过后在价格配置界面保存；复制提示词或修改模拟样例不会自动保存计价配置。

</Callout>

| --- | --- | --- |

#### 特殊可用分组规则

`group_ratio_setting.group_special_usable_group` 针对指定用户组调整可选目标组：

| 规则 | JSON 键 | 作用 |
| --- | --- | --- |
| 额外可见 | `+:目标组` | 添加目标组及描述。 |
| 隐藏 | `-:目标组` | 从该用户组的候选中移除目标组。 |
| 直接添加或覆盖描述 | 普通目标组键 | JSON 模式支持；可视化可见规则会以 `+:` 形式保存。 |

选择用户组，添加规则类型、目标组和描述后保存。公共列表取消勾选并不保证该组对所有用户消失：用户自己的分组最后会被补回，特殊可见规则也可重新加入它。不要同时为同一用户组和目标组设置互相冲突的 `+:`、`-:` 和普通键，不能依赖其处理顺序。

#### 自动分配顺序

| 页面字段 | 默认或填写要求 | 说明 |
| --- | --- | --- |
| 自动分配顺序 | `AutoGroups` 默认 `["default"]` | 从上到下查找可用渠道，不是轮询；支持添加、移除及调整顺序。 |
| 每个令牌的最大自定义分组数 | `MaxTokenAutoGroups` 默认 `5`，必须正整数 | 只限制令牌专属 Auto 快照，不限制继承全局列表的长度。 |
| 默认使用自动分组 | `DefaultUseAutoGroup` 默认关闭 | 影响支持该默认值的新建入口，不修改已有令牌，也不保证直接 API 创建会自动填入 `auto`。 |

**配置与运行边界**

1. 先向对应用户开放 `auto` 选项，并确保候选目标组可选、存在倍率及可用渠道；仅设置顺序或打开默认开关不够。
2. 调整全局顺序并保存。控制台新建令牌还需用户可用组中包含 `auto` 才采用该默认；注册时自动生成初始令牌的流程也可能使用此开关。
3. 令牌没有自定义快照时继承全局列表；保存非空快照后按该快照运行，仍受当前权限和数量上限过滤。清空快照恢复继承。
4. 自定义快照因后续权限变化被过滤为空时，不会自动回退全局列表。切为固定组会清除自定义 Auto 快照及跨组重试设置。
5. 某候选组没有模型渠道时，选择阶段直接检查下一组；已发起请求后是否跨组重试，还需令牌的跨组重试开关、重试次数及错误条件，不能理解为每次失败立即换组。

<Callout type="warn">
  删除或改名基础分组不会级联修改用户、令牌、渠道、Auto 列表和特殊规则。先迁移引用并验证，再清理旧组。使用 JSON 时按对象或数组结构填写，清空使用 `{}` 或 `[]`，不要留空或只以“保存成功”判断运行配置完整生效。
</Callout>

#### 支付合规确认

Root 需通过后台会话阅读并确认当前条款版本，API Access Token 不能代替该会话。确认记录包含用户、时间、IP 和条款版本；界面显示确认状态后再配置支付。

确认前应核实上游授权、转售或分发范围、运营与收费责任，以及适用的备案、内容安全、标识、日志和个人信息保护要求。合规状态影响支付设置界面、钱包入口、回调处理，以及兑换码、订阅、邀请奖励的相关操作，但不能将其当作所有充值接口统一的服务端访问防护。

<Callout type="warn">
  确认声明不是法律意见、资质审核或合法性保证。测试环境、测试回调路径也不等于独立用户账本；请使用专门测试账号核对余额，不要向生产用户发起试单。
</Callout>

#### Stripe

钱包入口需要合规已确认，并配置 API 密钥、Webhook 密钥和 Price ID；真正的支付结果还需验签和订单处理成功。

**操作流程**

1. 在 Stripe 创建正确货币和单价的 Price，将同一环境的密钥和 Price ID 填入。
2. 为 `<ServerAddress>/api/stripe/webhook` 配置 Webhook，包含 `checkout.session.completed` 和 `checkout.session.expired`；使用延迟支付方式时，还需覆盖 `checkout.session.async_payment_succeeded`、`checkout.session.async_payment_failed`。
3. 核对单价、最低值、优惠码后保存，以测试用户完成一笔支付。

**三种金额不能混为一谈**

| 阶段 | 当前处理 |
| --- | --- |
| 本地报价 | 使用 `StripeUnitPrice`、充值分组倍率及金额优惠。 |
| Checkout 收费 | 提交 `StripePriceId` 与原始充值数量，实际金额由 Stripe Price 和其支付规则决定；本地优惠不会自动改写该 Price。 |
| 站内入账 | 根据订单记录的充值数量与账户组充值倍率折算 quota，不以本地优惠乘数减少到账额度。 |

保存前确保三者符合售卖方案。兼容 TOKENS 模式下最低额换算和原始数量上限可能冲突，不要直接沿用普通美元模式数值。自定义成功、取消返回地址还需满足可信域名校验；返回页面本身不会代替 Webhook 入账。

#### Waffo Pancake

Pancake 用商户凭证获取商店与一次性产品目录，并将选定产品绑定到钱包充值。没有单独的启用开关；合规、商户 ID、私钥及钱包产品配置共同影响入口和回调可用性。

- 计费与支付-支付网关-Waffo Pancake
![Waffo Pancake MoR](/assets/guide/feature-guide/system-settings-billing-and-payments-payment-gateway-waffo-pancake-mor.png)

| 页面字段或状态 | 填写要求 | 说明 |
| --- | --- | --- |
| Merchant ID | 提供方分配的商户 ID | 不是截图占位值；更换商户时同步核对私钥与目录归属。 |
| API Private Key | 对应商户的 RSA 私钥 | 不回显；保存时空白保留旧值。该文本框可显示新输入私钥，截图前务必清除敏感内容。 |
| Return URL | 新产品的支付成功返回地址 | 创建产品时写入 SuccessURL；之后只修改本地配置不会更新已有产品返回地址。 |
| Store | 目录加载后选择 | 商店绑定，切换商店后需重新选择产品。 |
| Product | 选择有效的一次性产品 | 钱包充值使用该产品并在 checkout 中设置本次价格，不必为每个充值金额创建 SKU。 |
| 创建商店和产品 | 确认外部写入后执行 | 会实际创建并发布资源，不是本地预览。 |
| 已保存绑定 | 保存后核对 | 自动预选、当前选择和已保存绑定是不同状态。 |

**操作流程**

1. 输入完整商户 ID 和私钥后，页面自动验证并加载目录；已有凭证可在打开页面时使用。不要寻找不存在的独立“测试连接”按钮。
2. 选择已有商店和产品；如果确实需要新资源，先填写返回地址，再执行创建商店和产品。
3. 核对当前商户、商店及产品，保存所有设置，确认已保存绑定。
4. 在提供方分别配置 `<ServerAddress>/api/waffo-pancake/webhook/test` 和 `/api/waffo-pancake/webhook/prod`。
5. 使用专门测试账户验证 checkout、签名通知和余额；再按生产商户要求检查正式配置。

**注意事项**

- 目录可能自动选中首个可用产品，不能把预选理解为旧绑定已修复。保存只检查必要字段，不替代产品归属、发布状态和环境验证。
- 创建、发布有真实外部副作用，取消、刷新或本地保存失败都不会撤销资源。部分创建失败时先检查提供方后台，避免重复创建。
- `test`、`prod` 路径用于检查通知 mode 与路径一致，不保证独立账本。不要让生产用户参与测试支付。
- 钱包产品与[订阅管理](/zh/docs/guide/feature-guide/admin/subscription)的套餐产品不同；套餐使用独立产品，但仍需满足共用 Webhook 的全局配置条件。
- 新私钥用于目录请求时可能出现在请求 URL 中，排错时不要公开完整 URL、代理访问日志或浏览器网络记录。保存成功不代表已完成支付验收。

#### 金额与入账核对

| 网关 | 配置时重点核对 |
| --- | --- |
| EPay | 本地单价、充值倍率、优惠与服务商实收；到账基于订单充值额度。 |
| Stripe | 本地报价不等于 Stripe Price 实收；分组倍率参与站内入账，优惠码和本地优惠不是同一机制。 |
| Creem | 产品实际价格与站内展示一致；`quota` 直接作为内部额度入账。 |
| Waffo | 环境、实际货币、单价、倍率和通知地址；不要用显示汇率推断网关金额。 |
| Pancake | 钱包 checkout 使用本次 USD 价格；提供方税费及最终应付需在 checkout 核对。 |

签名正确、订单匹配和状态允许后才会入账；重复成功通知不会重复发放同一订单额度。不要通过刷新成功页面、重复发起付款或盲目补单处理回调故障。TOKENS 兼容模式存在换算、整数取整及限额差异，不要承诺任意 Token 数量都能精确购入；有待结订单时不要修改额度换算基准。

## 保存后的验证清单

- [ ] 刷新设置，核对变更字段；模型价格遇到版本冲突时重新加载，普通设置检查是否部分成功。
- [ ] 用已知 Token、缓存、媒体和工具用量验证估算及真实日志；不要把估算器当真实账单。
- [ ] 用不同账户组和令牌组验证实际渠道、分组倍率及 Auto 顺序。
- [ ] 比较同一额度在钱包和日志中的显示，确认未混淆显示汇率与支付单价。
- [ ] 每个网关分别测试下单、实际收费、签名通知、订单状态与到账额度；确认返回页不是唯一成功依据。
- [ ] 测试新用户、邀请注册、邀请额度转移及重复签到，确认奖励进入正确余额。

## 常见问题

- **保存成功但价格没变？** 区分编辑草稿与最终保存，检查模型名、当前模式、提供方覆盖及请求开始时的价格快照。
- **关闭某项价格是否就是免费？** 不一定。移除覆盖可能恢复默认；工具价格还可能匹配更具体前缀。显式零值、未配置和删除是不同状态。
- **公开价格接口为什么访问失败？** 检查公开倍率开关，当前路径为 `/api/ratio_config`。
- **100 的优惠为什么没有用于 200？** 金额优惠按原始金额精确匹配，不是最低阈值规则。
- **Stripe 报价与付款页不一致？** 核对 Stripe Price 的货币、单价和数量，以及本地单价、充值倍率、优惠与 Stripe 优惠码的区别。
- **Creem 产品额度填 1 为什么不是到账 1 美元？** 该字段是内部 quota；默认基准下系统 1 USD 对应 500000 quota。
- **密钥框为空是否未配置？** 不一定。多数 API 密钥和私钥不回显；各字段留空规则不同，尤其不能将 Waffo 公钥当成留空保留的私钥。
- **用户不能选择某个组？** 核对公共可用列表、特殊规则、账户自身组、倍率配置及令牌限制；使用 Auto 还需开放 `auto`。
- **Pancake 创建成功为何没有完成配置？** 外部资源创建、当前选择和本地绑定保存是三个阶段，需核对并保存绑定。
- **签到每天都是最小值？** 检查最大值是否不大于最小值，并确认输入使用的是 quota。
