计费与支付配置位于 `/system-settings/billing`，仅 Root 可访问。这里决定请求如何定价、额度如何展示，以及用户如何充值和领取奖励。

## 计费与支付配置简介

| 分区 | 入口 | 主要用途 |
| --- | --- | --- |
| [额度设置](#额度设置) | `/system-settings/billing/quota` | 新用户额度、预扣、邀请奖励及外部链接。 |
| [货币与展示](#货币与展示) | `/system-settings/billing/currency` | 金额显示模式、汇率与 Token 统计。 |
| [模型定价](#模型定价) | `/system-settings/billing/model-pricing` | 模型价格、表达式、工具价格及上游同步。 |
| [分组定价](#分组定价) | `/system-settings/billing/group-pricing` | 调用与充值倍率、用户可用分组及 Auto 顺序。 |
| [支付网关](#支付网关) | `/system-settings/billing/payment` | 合规确认、充值规则及各网关凭证和回调。 |
| [签到奖励](#签到奖励) | `/system-settings/billing/checkin` | 每日签到开关和奖励范围。 |

配置时先区分四种量：**内部额度 quota** 是余额和扣费的计量单位；**显示金额**是 quota 格式化后的结果；**模型费用**由请求用量和价格规则计算；**网关实收**由各支付渠道的订单决定。修改显示货币不会批量重写用户余额，也不会自动修改网关商品价格。

<Callout type="warn">
  本页会影响扣费、余额和支付入账。修改前记录原配置，用测试用户核对价格，并在支付服务商允许的测试环境中验证。不要公开 API 密钥、Webhook 密钥、RSA 私钥、完整签名或含凭证的请求 URL。截图中的模型、金额、商户和产品均是示例，不是推荐值或可直接使用的凭证。
</Callout>

### 保存方式

| 操作 | 提交与生效边界 |
| --- | --- |
| 额度、货币、分组、签到及普通支付设置 | 通常逐字段提交变更；中途失败不会撤销已成功保存的字段。刷新后核对，再补充保存。 |
| 模型价格及上游同步应用 | 使用带版本校验的模型定价接口；同一批价格在数据库事务中保存。版本冲突时重新加载并核对，不要直接重复覆盖。 |
| 公开倍率开关 | 独立保存，不与模型价格共用一次事务。 |
| Waffo Pancake 绑定 | 通过专用接口在同一数据库事务中保存绑定信息；不会回滚此前的普通设置或已经创建的第三方资源。 |
| 弹窗添加、列表编辑和选择 | 是否落库取决于所属页面的保存流程；支付方式、产品和分组弹窗确认后仍需保存所在分区。 |

密钥是否回显、留空是否保留，按各网关字段说明处理，不要用占位字符覆盖真实凭证。「重置表单」恢复已保存值，不等于恢复系统出厂配置。

## 额度设置

管理新用户赠送、邀请奖励和请求预扣的基础配置。

<div className="[&_table]:min-w-[48rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 页面字段 | 默认或填写要求 | 说明 |
| --- | --- | --- |
| 新用户额度 | 默认 `0`；填写非负整数 quota | `QuotaForNewUser`，新用户创建时获得的初始额度，不追补已有用户。 |
| 预扣额度 | 默认 `500`；填写非负整数 | `PreConsumedQuota`，普通 Token 倍率路径中用于预估的 Token 数下限，不是每次固定扣除的金额。 |
| 邀请人奖励 | 默认 `0`；填写非负整数 quota | `QuotaForInviter`，符合条件的邀请注册后进入邀请人的邀请额度 `aff_quota`。 |
| 被邀请人奖励 | 默认 `0`；填写非负整数 quota | `QuotaForInvitee`，进入被邀请人的普通余额。 |
| 免费模型预扣 | 默认开启 | `quota_setting.enable_free_model_pre_consume`，关闭后，有效模型价格、倍率或分组倍率为零的相应路径跳过预扣；不代表所有附加收费都被关闭。 |
| 充值链接 | 默认空 | `TopUpLink`，用户购买额度或兑换码的外部入口，不会自动接入该网站的支付回调。 |
| 文档链接 | 默认 `https://docs.newapi.pro` | `general_setting.docs_link`，站点文档入口，也供顶部导航等位置使用。 |

</div>

**操作流程**

1. 核对额度单位。默认 `QuotaPerUnit = 500000` 时，`500000 quota` 对应系统 `1 USD` 余额，而不是实际输入或输出了 500000 Token。
2. 设置新用户额度、预扣和奖励；配置正数邀请奖励前，先到支付网关确认合规声明。
3. 填写充值、文档链接并保存，刷新检查非敏感字段。
4. 用新建测试用户验证初始额度；用邀请注册验证双方奖励，用请求日志核对预扣与最终费用。

![额度设置](/assets/guide/feature-guide/system-settings-billing-and-payments-quota-settings.png)

**注意事项**

- 普通 Token 倍率路径以 `max(输入 Token 数, PreConsumedQuota)` 加上请求指定的最大输出量，再结合模型、分组倍率估算预扣；实际结算另按用量计算。按次和表达式有各自的估算逻辑，不能套用这个下限推算所有请求。
- 邀请人的奖励不会立即进入普通余额。用户转移邀请额度时，单次至少为一个 `QuotaPerUnit`，且邀请额度必须足够；转移同样要求合规已确认。
- 新用户额度和邀请奖励是不同设置。截图中的格式化金额仅帮助核对，不会改变输入数值的单位。

## 货币与展示

此分区控制金额格式化，不替代模型或支付网关的价格配置。

<div className="[&_table]:min-w-[48rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 页面字段 | 默认或填写要求 | 说明 |
| --- | --- | --- |
| 显示模式 | 默认 `USD` | USD 按美元显示；CNY 使用美元汇率；CUSTOM 使用自定义符号和汇率。兼容的 TOKENS 模式显示原始 quota。 |
| 美元汇率 | 后端默认 `7.3`；表单最小 `0.0001` | `USDExchangeRate`，CNY 显示时表示 `1 USD = X CNY`；非 TOKENS 模式显示该输入。不会自动更新 Stripe Price 或其他网关商品。 |
| 自定义货币符号 | 默认 `¤`；CUSTOM 时必填，最多 8 字符 | 例如 `HK$`；仅 CUSTOM 模式显示。 |
| 每美元对应单位数 | 默认 `1`；CUSTOM 时必填，最小 `0.0001` | `custom_currency_exchange_rate`，表示 `1 USD = X` 个自定义货币单位。 |
| 显示 Token 统计 | 默认开启 | `DisplayTokenStatEnabled`，控制相关界面的用量统计展示，不改变扣费。 |
| 每单位额度 | 默认 `500000`；只读 | `QuotaPerUnit`，每个系统 USD 对应的 quota；仅 TOKENS 模式或数值不同于默认基准时显示。 |
| 按货币显示 | 兼容字段 | `DisplayInCurrencyEnabled`，当前值为关闭时才显示此开关；新版金额格式化以显示模式为准。 |

</div>

**操作流程**

1. 选择 USD、CNY 或 CUSTOM；使用 CUSTOM 时填写符号及换算率。
2. 核对 Token 统计开关，保存；需要放弃未保存修改时使用重置。
3. 在钱包、价格页和日志中对照同一笔额度，确认符号、小数和换算值。

![货币与展示](/assets/guide/feature-guide/system-settings-billing-and-payments-currency-and-display.png)

**注意事项**

- TOKENS 属于兼容状态，只有当前表单处于该模式时才显示对应选项，不能将其描述为所有实例始终可新选的模式。
- 例如内部 `500000 quota` 在默认基准下为 `$1`；CNY 汇率为 `7.3` 时显示约 `¥7.3`，余额本身没有增加。
- 支付场景仍有独立的货币和金额计算；即使额度采用 TOKENS 显示，部分支付金额界面也仍使用货币。

## 模型定价

分为「模型价格」「未设置价格的模型」「工具价格」「上游价格同步」四个标签。新建模型价格默认使用计费表达式；「按 Token」「按次」在当前界面标为已弃用，但仍用于兼容已有配置。

### 模型价格

列表用于搜索、检查和维护模型价格，不会自动给渠道增加模型。价格配置应与请求使用的模型标识和实际计费路径一致。

![模型价格](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-model-prices.png)

**添加或修改流程**

1. 搜索模型并编辑，或点击添加模型定价。新建时填写准确模型名，编辑时模型名不可直接更改。
2. 选择定价货币和模式，设置价格或表达式。模板只是起点，先核对当前供应商价格和缓存规则。
3. 输入已知用量检查估算；含请求条件时，再模拟请求体、请求头和时间。
4. 点击保存模型价格，并确认列表及刷新后的价格符合预期。批量复制先更新草稿，还需保存。
5. 用测试请求在日志中核对真实用量、分组倍率和最终费用。

![添加模型定价](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-model-prices-add-model-pricing.png)

**基础字段**

<div className="[&_table]:min-w-[48rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 页面字段 | 默认或填写要求 | 说明 |
| --- | --- | --- |
| 模型名称 | 新建必填 | API 请求使用的模型标识；不是供应商的展示名称，也不是任意正则匹配规则。 |
| 定价货币 | USD 或可用的站点货币 | 只换算可视化价格输入和金额预览；原始表达式与内置预设仍使用 USD。 |
| 计费模式 | 新建默认表达式 | 普通模型初始草稿为零价表达式，不能把截图价格当默认值；保存前务必填入实际定价。 |
| 编辑器模式 | 可视化或原始表达式 | 普通表达式无法无损解析时不能直接转为可视化；不要为切换模式丢失自定义逻辑。 |
| 预设模板 | 按实际模型选择 | 包括固定、阶梯、多模态、请求规则和时间条件；应用预设会替换当前编辑内容，仍需核对和保存。 |
| 档位名称 | 为各档位使用可识别名称 | 用于标识命中的价格档位，例如 `base`、`standard`，不是模型名。 |
| 阶梯条件与顺序 | 按业务设置 | 从前向后匹配，首条命中决定档位；兜底档位处理此前均未命中的请求。 |
| 计费分支 | 按 Token 或按请求 | Token 单价按每百万对应 Token 填写；按请求分支填写 USD/请求的固定金额。 |

</div>

**Token、缓存与媒体价格**

| 页面字段 | 对应内容 | 单位与边界 |
| --- | --- | --- |
| 输入、输出价格 | 输入和输出基础用量 | 表达式可视化 Token 分支按所选货币/1M Token 输入。 |
| 缓存读取价格 | `cr` | 对可识别的缓存读取用量单独计价。 |
| 缓存创建/写入价格 | `cc` | 对缓存创建用量计价；Claude 场景可区分 5 分钟与 1 小时缓存。 |
| 1 小时缓存写入价格 | `cc1h` | 仅对相应缓存用量生效，不代表所有模型都支持该缓存时长。 |
| 图像输入、输出价格 | `img`、`img_o` | 对对应图像 Token 类别计价，不要与按张收费混用。 |
| 图片缓存价格 | 图片缓存 Token 类别 | 按编辑器的对应类别填写，需上游返回可识别的用量。 |
| 音频输入、输出价格 | `ai`、`ao` | 按对应音频 Token 类别计价，不是每秒音频价格。 |

选择单独计价的类别后，表达式按所用变量区分基础和子类别用量，避免重复计算。完整上下文长度 `len` 用于阶梯条件，不因子类别单独计价而缩短。未启用某类别单价，不应直接理解为该类别免费；需检查生成表达式和基础用量的处理。

![编辑模型定价](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-model-prices-edit-model-pricing.png)

**请求规则计费与模拟**

| 字段或操作 | 填写要求 | 说明 |
| --- | --- | --- |
| 请求体参数 | 参数路径、比较方式和值 | 读取请求 JSON 路径；例如按 `service_tier` 区分服务等级。 |
| 请求头条件 | Header 名称、比较方式和值 | 根据实际发送的请求头匹配，不要依赖客户端没有携带的字段。 |
| 时间条件 | 时间项、时区、比较值或范围 | 明确时区，例如 `Asia/Shanghai`；不是一律按浏览器本地时间解释。 |
| 规则组倍率 | 填入业务所需倍率 | 同组条件同时满足才命中；多个命中组的倍率相乘，小于 `1` 表示折扣。 |
| Token 估算器 | 输入、输出、缓存和媒体用量 | 检查基础费用和命中档位，不含用户/分组倍率；指定完整输入长度可单独测试阶梯边界。 |
| 模拟请求体 | JSON 对象 | `{}` 表示未提供相应字段，不代表自动使用真实请求。 |
| 模拟请求头 | 键值行或 JSON | 可添加、删除行，用于检验 Header 条件。 |
| 模拟时间 | 当前或指定时间 | 用于验证时间规则，表达式中的时区仍生效。 |
| 模拟请求费用 | 查看结果与命中条件 | 包含请求规则，不含分组倍率；不是已发起上游请求或最终账单。 |

**兼容旧价格与任务模型**

- 旧倍率 JSON 使用 `ModelRatio`、`CompletionRatio`、`CacheRatio`、`CreateCacheRatio`、`ImageRatio`、`AudioRatio`、`AudioCompletionRatio`；可视化输入的是金额，不能原样复制到倍率 JSON。`ModelRatio = 1` 对应基础输入约 `$2/1M Token`；输出等相对倍率还需乘基础价，音频输出倍率则基于音频输入价。
- `ModelPrice` 是旧按次 USD 价格。图片等路径可能进一步结合数量或请求条件，不能保证任何请求都只收一个 `ModelPrice`。
- 空缺覆盖和显式 `0` 不同：空缺可能恢复内置默认，`0` 才是明确零值。旧倍率中从属价格依赖基础价格；无法表达的零基础价、多类别组合应使用表达式。
- 显式表达式优先于旧按次、倍率路径。旧价格转换先预览，再保存；不支持的协议、任务或价格组合可能拒绝转换，不能承诺所有模型一键无损迁移。
- 任务模型按插件声明的 usage 字段、单位、规格和数量计价，任务表达式结果直接表示 USD；不能将普通 Token 表达式的换算规则套到秒、次数等任务用量。提供方独立价格与共享模型价格不同，详见[任务插件管理](/zh/docs/guide/feature-guide/admin/task-plugins)。

<Callout type="warn">
  重置价格恢复程序内置默认，不会获取供应商最新报价。请求开始后的表达式计费使用当时的快照；结算表达式出错也不保证退回全部预扣。批量复制、转换或重置前记录原配置，遇到版本冲突先重新加载核对。
</Callout>

### 未设置价格的模型

此列表基于渠道可用模型及当前定价快照，不是模型数据库的全部条目。只有输出或缓存倍率而没有基础价格，不等于已配置完整价格；显式零价则属于已定价。

![未设置价格的模型](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-models-without-prices.png)

1. 筛选未定价模型并进入价格编辑。
2. 单独配置，或从已核对的源模型复制价格到所选目标。
3. 核对每个目标的协议、缓存和媒体计费差异，再保存。
4. 刷新列表，发起测试请求确认没有“价格未配置”错误。

复制使用源模型当前编辑草稿，不自动等于已保存价格；共享模型价格复制不会替换目标提供方的独立插件覆盖。

### 工具价格

工具价格配置键为 `tool_price_setting.prices`，单位为 **USD/1000 次可计费调用**，不是 USD/次或 USD/1M Token。

![工具价格](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-tool-prices.png)

| 字段或规则 | 填写要求 | 说明 |
| --- | --- | --- |
| 工具名称 | 使用已支持的计费工具标识 | 如 `web_search`、`file_search`；新增任意名称不会让系统自动识别该工具调用。 |
| 模型前缀覆盖 | `工具名:模型前缀*` | 如 `web_search:gpt-4o*`；这是前缀规则，不是正则或通用通配语法。 |
| 价格 | 有限非负数 | `10` 表示每 1000 次收费 `$10`，即每次 `$0.01`，之后还需考虑适用的计费规则。 |
| 零价 | 显式 `0` | 命中的零价规则终止该规则的价格查找；工具默认零价不能覆盖更具体的模型前缀规则。 |

先核对工具标识，设置默认价及必要的模型覆盖，保存后用实际工具调用验证。多个前缀命中时最长前缀优先，再使用工具默认价；删除规则可能恢复程序内置价格，不等于免费。

### 公开倍率和上游同步

开启公开倍率后，外部可通过 `/api/ratio_config` 获取价格配置；关闭时返回未启用。公开开关独立保存，启用前确认这些信息适合公开。

![上游价格同步](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-upstream-price-sync.png)

| 页面项目 | 默认或填写要求 | 说明 |
| --- | --- | --- |
| 渠道与上游来源 | 选择可信来源 | 只获取候选价格，不会自动修改本地配置。 |
| 端点 | 默认 `/api/pricing`，按上游调整 | 不同上游接口格式不同，不应将公开倍率接口和所有同步端点混为一谈。 |
| 超时 | 界面默认 10 秒 | 上游无响应或格式不支持会显示获取失败；多个来源可能部分成功。 |
| 价格来源选择 | 每个模型选择一个来源 | 选择的是该来源整套模型价格，不是随意拼接各来源的单个倍率。 |
| 应用同步 | 先预览，再确认 | 预览不写入；确认后通过版本化模型价格接口保存。 |

1. 选择渠道、端点，获取上游价格。
2. 查看本地与上游差异，为需要变更的模型选择来源。

![选择价格来源](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-upstream-price-sync-select-price-source.png)

3. 点击应用同步，检查预览中的目标模型、旧值和新值。

![应用同步确认](/assets/guide/feature-guide/system-settings-billing-and-payments-model-pricing-upstream-price-sync-apply-sync.png)

4. 确认变更；遇到并发版本冲突，重新加载、获取并选择，不要直接重试覆盖。
5. 验证已选模型的价格与请求费用。同步是手动操作，不会持续追踪上游改价。

表达式来源可能替换对应旧价格字段；目标提供方独立覆盖仍需另行检查。只访问可信上游，尤其是可能使用渠道凭证获取模型数据的来源，避免在调试截图中暴露密钥或内部端点。

## 分组定价

用户分组是账户所属组；计费分组是本次请求实际使用的目标组；渠道分组决定渠道能服务哪些组。调用倍率按实际计费组计算，充值倍率按账户所属用户组应用，两者不能混用。

![分组定价](/assets/guide/feature-guide/system-settings-billing-and-payments-group-pricing.png)

### 基础分组与详情

| 页面字段 | 默认或填写要求 | 说明 |
| --- | --- | --- |
| 分组名称 | 非空、稳定且不重复的标识 | 基础表来自倍率、充值倍率和公共可用组配置的键，不代表数据库中的所有分组。建议避免逗号；改名不会同步修改其他记录。 |
| 倍率 | 内置 `default`、`vip`、`svip` 均为 `1` | `GroupRatio`，实际调用该组时使用的基础倍率；后端要求非负。 |
| 充值倍率 | 上述内置组为 `1` | `TopupGroupRatio`，作用于账户组；缺省回退 `1`，部分网关对 `0` 也回退 `1`，不能用 `0` 实现免费充值。各网关作用点不同。 |
| 用户可选 | 内置公共列表含 `default`、`vip` | `UserUsableGroups`，勾选后进入公共候选列表；自身组及特殊规则仍可能增加候选。 |
| 说明信息 | 用户可选时填写 | 用户选择分组时看到的描述，不改变组标识。 |
| 分组详情 | 点击信息入口 | 用于核对该组信息和配置关系，不会自动迁移关联记录。 |

![分组详情](/assets/guide/feature-guide/system-settings-billing-and-payments-group-pricing-group-details.png)

**操作流程**

1. 添加分组，设置名称、调用倍率、充值倍率和可选状态。
2. 在[渠道管理](/zh/docs/guide/feature-guide/admin/channel)配置该组可用的渠道与模型，在[用户管理](/zh/docs/guide/feature-guide/admin/user)设置账户组。
3. 配置下述特殊规则或 Auto 顺序后，点击保存分组比率。
4. 用不同账户组、固定组及 Auto 令牌发起请求，核对实际组、渠道和费用。

![分组使用指南](/assets/guide/feature-guide/system-settings-billing-and-payments-group-pricing-usage-guide.png)

### 特殊倍率规则

规则表达的是“某用户组使用某计费组时，采用指定倍率”。命中后**替代**该计费组的基础倍率，不是再与其相乘，也不会改变用户账户所属组。

![添加用户分组](/assets/guide/feature-guide/system-settings-billing-and-payments-group-pricing-special-multiplier-rules-add-user-group.png)

| 弹窗字段 | 填写要求 | 说明 |
| --- | --- | --- |
| 用户分组 | 选择或填写规则适用的账户组 | 表示哪些用户享受覆盖，不是本次调用的目标组。 |

![添加倍率覆盖](/assets/guide/feature-guide/system-settings-billing-and-payments-group-pricing-special-multiplier-rules-user-group-add-multiplier-override.png)

| 弹窗字段 | 填写要求 | 说明 |
| --- | --- | --- |
| 计费分组 | 填写实际使用的目标组 | 应存在有效倍率和可用渠道；名称错误时不能因为存在覆盖就获得路由能力。 |
| 倍率 | 使用有限非负数 | 例如 `0.9` 为此组合的最终分组倍率；不要依赖所有编辑入口都会完整拦截负数或重复项。 |

先添加用户组，再添加其计费组覆盖，确认后保存分区。JSON 对应 `GroupGroupRatio`，例如 `{"vip":{"default":0.9}}`。内置的 `edit_this` 是示例键，不表示所有 VIP 用户自动享受九折。

### 特殊可用分组规则

`group_ratio_setting.group_special_usable_group` 针对指定用户组调整可选目标组：

| 规则 | JSON 键 | 作用 |
| --- | --- | --- |
| 额外可见 | `+:目标组` | 添加目标组及描述。 |
| 隐藏 | `-:目标组` | 从该用户组的候选中移除目标组。 |
| 直接添加或覆盖描述 | 普通目标组键 | JSON 模式支持；可视化可见规则会以 `+:` 形式保存。 |

选择用户组，添加规则类型、目标组和描述后保存。公共列表取消勾选并不保证该组对所有用户消失：用户自己的分组最后会被补回，特殊可见规则也可重新加入它。不要同时为同一用户组和目标组设置互相冲突的 `+:`、`-:` 和普通键，不能依赖其处理顺序。

### 自动分配顺序

| 页面字段 | 默认或填写要求 | 说明 |
| --- | --- | --- |
| 自动分配顺序 | `AutoGroups` 默认 `["default"]` | 从上到下查找可用渠道，不是轮询；支持添加、移除及调整顺序。 |
| 每个令牌的最大自定义分组数 | `MaxTokenAutoGroups` 默认 `5`，必须正整数 | 只限制令牌专属 Auto 快照，不限制继承全局列表的长度。 |
| 默认使用自动分组 | `DefaultUseAutoGroup` 默认关闭 | 影响支持该默认值的新建入口，不修改已有令牌，也不保证直接 API 创建会自动填入 `auto`。 |

**配置与运行边界**

1. 先向对应用户开放 `auto` 选项，并确保候选目标组可选、存在倍率及可用渠道；仅设置顺序或打开默认开关不够。
2. 调整全局顺序并保存。控制台新建令牌还需用户可用组中包含 `auto` 才采用该默认；注册时自动生成初始令牌的流程也可能使用此开关。
3. 令牌没有自定义快照时继承全局列表；保存非空快照后按该快照运行，仍受当前权限和数量上限过滤。清空快照恢复继承。
4. 自定义快照因后续权限变化被过滤为空时，不会自动回退全局列表。切为固定组会清除自定义 Auto 快照及跨组重试设置。
5. 某候选组没有模型渠道时，选择阶段直接检查下一组；已发起请求后是否跨组重试，还需令牌的跨组重试开关、重试次数及错误条件，不能理解为每次失败立即换组。

<Callout type="warn">
  删除或改名基础分组不会级联修改用户、令牌、渠道、Auto 列表和特殊规则。先迁移引用并验证，再清理旧组。使用 JSON 时按对象或数组结构填写，清空使用 `{}` 或 `[]`，不要留空或只以“保存成功”判断运行配置完整生效。
</Callout>

## 支付网关

六个标签依次为常规、EPay、Stripe、Creem、Waffo Pancake、Waffo。配置前确认公网 `ServerAddress`、HTTPS 和服务商回调可达性；反向代理需保留原始请求体和验签头。

### 支付合规确认

Root 需通过后台会话阅读并确认当前条款版本，API Access Token 不能代替该会话。确认记录包含用户、时间、IP 和条款版本；界面显示确认状态后再配置支付。

确认前应核实上游授权、转售或分发范围、运营与收费责任，以及适用的备案、内容安全、标识、日志和个人信息保护要求。合规状态影响支付设置界面、钱包入口、回调处理，以及兑换码、订阅、邀请奖励的相关操作，但不能将其当作所有充值接口统一的服务端访问防护。

<Callout type="warn">
  确认声明不是法律意见、资质审核或合法性保证。测试环境、测试回调路径也不等于独立用户账本；请使用专门测试账号核对余额，不要向生产用户发起试单。
</Callout>

### 常规设置

| 页面字段 | 默认或填写要求 | 说明 |
| --- | --- | --- |
| 单价（本地货币/USD） | `Price` 默认 `7.3` | EPay 每购买 1 个系统 USD 余额对应的收款单价，不是所有网关共用价格。 |
| 最低充值 | `MinTopUp` 默认 `1`；填写整数 | EPay 最低充值值。虽部分输入允许小数，后端该配置按整数解析，应避免填写小数。 |
| 支付方式 | `PayMethods` 数组 | 常规钱包按钮的名称、类型和额外最低值；不替代各网关凭证。 |
| 快捷金额 | 默认 `[10,20,50,100,200,500]` | `payment_setting.amount_options`，使用正整数；只是快捷按钮，不是允许金额白名单。空列表也可能触发钱包默认按钮回退。 |
| 金额优惠 | 默认空对象 | `payment_setting.amount_discount`，按原始充值金额精确匹配的价格乘数；适用范围见网关说明。 |

![支付网关常规设置](/assets/guide/feature-guide/system-settings-billing-and-payments-payment-gateway-general.png)

先设置 EPay 单价和最低值，再维护支付方式、快捷金额与优惠，最后保存所有设置。必须分别到各网关完成凭证和回调配置，常规标签保存成功不代表可收款。

**添加支付方式**

![添加常规支付方式](/assets/guide/feature-guide/system-settings-billing-and-payments-payment-gateway-general-payment-methods-add-method.png)

| 弹窗字段 | 填写要求 | 说明 |
| --- | --- | --- |
| 名称 | 必填 | 钱包按钮的显示名称。 |
| 图标 | 可选 | 用于展示，不决定支付路由。 |
| 类型 | 必填 | `stripe` 走 Stripe，`waffo_pancake` 走 Pancake；其他普通方式作为 EPay 类型处理。Creem 产品和 Waffo 方法使用独立配置，不要随意填写类型来启用它们。 |
| 最低充值 | 可选，建议正整数 | 钱包按钮的额外门槛，与公共最低值取更高者；不能当作所有后端接口的独立限额。 |

点击添加或更新只修改本地列表，仍需保存所有设置。模板预填值不是系统强制默认，删除按钮同样要保存后才持久化。

**添加金额优惠**

![添加金额优惠](/assets/guide/feature-guide/system-settings-billing-and-payments-payment-gateway-general-amount-discounts-add-discount-tier.png)

| 弹窗字段 | 填写要求 | 说明 |
| --- | --- | --- |
| 充值金额 | 正整数；编辑时不可直接改键 | 对应原始请求金额的整数键。`100` 只匹配该金额，不覆盖 `101` 或更大金额。 |
| 优惠率 | 可视化要求大于 `0` 且不大于 `1` | 实付乘数，`0.95` 表示按原价 95% 收取，不是减去 95%。 |

<Callout type="info">
  截图中的“最低金额”提示不能理解为阶梯阈值，当前后端按金额精确匹配。JSON 模式与可视化校验不同，不建议用大于 1 或非正数模拟优惠；TOKENS 模式还需核对原始请求单位。
</Callout>

### EPay

EPay 是一种支付协议，不是唯一的支付官方网站。接入前自行核实服务商、费率和授权，不要把截图地址当作可用服务。

| 页面字段 | 默认或填写要求 | 说明 |
| --- | --- | --- |
| EPay 端点 | 默认空；非空需 `http://` 或 `https://` | `PayAddress`，支付服务商基础地址。 |
| 回调地址 | 可选；站点 origin | `CustomCallbackAddress`，例如 `https://api.example.com`；不要填通知路径、查询参数或片段，留空回退 `ServerAddress`。 |
| 易支付商户 ID | 默认空；服务商提供 | `EpayId`，按字符串填写。 |
| EPay 密钥 | 默认空 | `EpayKey`，本页不回显，空输入不提交；轮换时填入新密钥。 |

![EPay 网关](/assets/guide/feature-guide/system-settings-billing-and-payments-payment-gateway-epay.png)

**操作流程**

1. 确认合规，填写端点、商户 ID 和密钥。
2. 在常规标签配置单价、最低充值和至少一种服务商支持的支付方式。
3. 保存所有设置，配置并检查回调站点的公网可达性。
4. 小额测试下单、服务商支付、验签通知及余额入账；用户返回页面不作为入账依据。

| 回调或返回用途 | 地址 |
| --- | --- |
| 钱包通知 | `<回调站点>/api/user/epay/notify` |
| 订阅通知 | `<回调站点>/api/subscription/epay/notify` |
| 订阅返回 | `<回调站点>/api/subscription/epay/return` |
| 钱包支付返回 | `<ServerAddress>/usage-logs` |

普通货币模式下，EPay 报价由充值值、`Price`、账户组充值倍率和精确匹配的优惠乘数组成；入账基于订单充值额度，不按优惠后的实收重新发放余额。

### Stripe

钱包入口需要合规已确认，并配置 API 密钥、Webhook 密钥和 Price ID；真正的支付结果还需验签和订单处理成功。

| 页面字段 | 默认或填写要求 | 说明 |
| --- | --- | --- |
| API 密钥 | 默认空；使用 `sk_` 或 `rk_` 凭证 | `StripeApiSecret`，空输入保留；测试与生产由 Stripe 凭证和 Price 所属环境决定，无独立测试开关。 |
| Webhook 密钥 | 默认空 | `StripeWebhookSecret`，对应当前端点的签名密钥；空输入保留。 |
| 价格 ID | 默认空 | `StripePriceId`，Stripe 后台 Price 标识；不是 New API 模型价格。 |
| 单价（本地货币/USD） | `StripeUnitPrice` 默认 `8` | 用于本地报价，不能替代或自动修改 Stripe 后台 Price。 |
| 最低充值（美元） | `StripeMinTopUp` 默认 `1`；填写整数 | 单次请求还受原始数量不大于 `10000` 的限制。 |
| 促销代码 | 默认关闭 | `StripePromotionCodesEnabled`，允许在 Stripe Checkout 输入优惠码；截图开启状态不是默认值。 |

![Stripe 网关](/assets/guide/feature-guide/system-settings-billing-and-payments-payment-gateway-stripe.png)

**操作流程**

1. 在 Stripe 创建正确货币和单价的 Price，将同一环境的密钥和 Price ID 填入。
2. 为 `<ServerAddress>/api/stripe/webhook` 配置 Webhook，包含 `checkout.session.completed` 和 `checkout.session.expired`；使用延迟支付方式时，还需覆盖 `checkout.session.async_payment_succeeded`、`checkout.session.async_payment_failed`。
3. 核对单价、最低值、优惠码后保存，以测试用户完成一笔支付。
4. 分别核对本地报价、Checkout 实际收费、订单状态和到账余额；不要只比较页面显示价格。

**三种金额不能混为一谈**

| 阶段 | 当前处理 |
| --- | --- |
| 本地报价 | 使用 `StripeUnitPrice`、充值分组倍率及金额优惠。 |
| Checkout 收费 | 提交 `StripePriceId` 与原始充值数量，实际金额由 Stripe Price 和其支付规则决定；本地优惠不会自动改写该 Price。 |
| 站内入账 | 根据订单记录的充值数量与账户组充值倍率折算 quota，不以本地优惠乘数减少到账额度。 |

保存前确保三者符合售卖方案。兼容 TOKENS 模式下最低额换算和原始数量上限可能冲突，不要直接沿用普通美元模式数值。自定义成功、取消返回地址还需满足可信域名校验；返回页面本身不会代替 Webhook 入账。

### Creem

Creem 使用产品列表提供充值方案；API Key 和非空产品列表影响钱包入口，Webhook 验签还必须配置对应密钥。

| 页面字段 | 默认或填写要求 | 说明 |
| --- | --- | --- |
| API 密钥 | 默认空 | `CreemApiKey`，空输入保留已有值。 |
| Webhook 密钥 | 默认空 | `CreemWebhookSecret`，用于通知验签；不能只配置 API Key 就认为能到账。 |
| 测试模式 | 默认关闭 | `CreemTestMode`，切换测试与生产 API；凭证、产品及 Webhook 必须对应同一环境。 |
| 产品 | 默认空列表 | `CreemProducts`，可视化或 JSON 编辑，决定展示的充值产品及发放额度。 |

![Creem 网关](/assets/guide/feature-guide/system-settings-billing-and-payments-payment-gateway-creem.png)

**添加产品**

![添加 Creem 产品](/assets/guide/feature-guide/system-settings-billing-and-payments-payment-gateway-creem-add-product.png)

| 弹窗字段 | 填写要求 | 说明 |
| --- | --- | --- |
| 产品名称 | 必填 | 用户看到的名称。 |
| 产品 ID | 必填；编辑时不可更改 | Creem 后台真实产品标识，截图 `prod_xxx` 仅为示例。 |
| 货币 | 界面可选 USD、EUR | 与 Creem 后台产品货币保持一致。 |
| 价格 | 最小 `0.01` | 货币主单位，不是分；站内配置不能代替修改 Creem 后台商品价格。 |
| 额度 | 至少 `1`，填写整数 quota | 直接加入用户余额的内部额度，不乘 `QuotaPerUnit`。默认基准下 `500000` 才对应系统 `$1`，截图的 `1` 不是 `$1`。 |

1. 在 Creem 创建对应产品，确定实际货币、价格及站内发放 quota。
2. 填写同一环境的 API、Webhook 密钥，配置 `<ServerAddress>/api/creem/webhook`。
3. 添加产品并保存所有设置，测试购买后核对实际收费及到账 quota。
4. 切换生产时同步核对生产凭证、产品 ID 和 Webhook；不要只关闭测试开关。

回调异常先核对订单和验签结果，不要把手动补单当作默认排错步骤；不同网关订单的金额与额度单位不同。

### Waffo Pancake

Pancake 用商户凭证获取商店与一次性产品目录，并将选定产品绑定到钱包充值。没有单独的启用开关；合规、商户 ID、私钥及钱包产品配置共同影响入口和回调可用性。

![Waffo Pancake MoR](/assets/guide/feature-guide/system-settings-billing-and-payments-payment-gateway-waffo-pancake-mor.png)

| 页面字段或状态 | 填写要求 | 说明 |
| --- | --- | --- |
| Merchant ID | 提供方分配的商户 ID | 不是截图占位值；更换商户时同步核对私钥与目录归属。 |
| API Private Key | 对应商户的 RSA 私钥 | 不回显；保存时空白保留旧值。该文本框可显示新输入私钥，截图前务必清除敏感内容。 |
| Return URL | 新产品的支付成功返回地址 | 创建产品时写入 SuccessURL；之后只修改本地配置不会更新已有产品返回地址。 |
| Store | 目录加载后选择 | 商店绑定，切换商店后需重新选择产品。 |
| Product | 选择有效的一次性产品 | 钱包充值使用该产品并在 checkout 中设置本次价格，不必为每个充值金额创建 SKU。 |
| 创建商店和产品 | 确认外部写入后执行 | 会实际创建并发布资源，不是本地预览。 |
| 已保存绑定 | 保存后核对 | 自动预选、当前选择和已保存绑定是不同状态。 |

**操作流程**

1. 输入完整商户 ID 和私钥后，页面自动验证并加载目录；已有凭证可在打开页面时使用。不要寻找不存在的独立“测试连接”按钮。
2. 选择已有商店和产品；如果确实需要新资源，先填写返回地址，再执行创建商店和产品。
3. 核对当前商户、商店及产品，保存所有设置，确认已保存绑定。
4. 在提供方分别配置 `<ServerAddress>/api/waffo-pancake/webhook/test` 和 `/api/waffo-pancake/webhook/prod`。
5. 使用专门测试账户验证 checkout、签名通知和余额；再按生产商户要求检查正式配置。

**注意事项**

- 目录可能自动选中首个可用产品，不能把预选理解为旧绑定已修复。保存只检查必要字段，不替代产品归属、发布状态和环境验证。
- 创建、发布有真实外部副作用，取消、刷新或本地保存失败都不会撤销资源。部分创建失败时先检查提供方后台，避免重复创建。
- `test`、`prod` 路径用于检查通知 mode 与路径一致，不保证独立账本。不要让生产用户参与测试支付。
- 钱包产品与[订阅管理](/zh/docs/guide/feature-guide/admin/subscription)的套餐产品不同；套餐使用独立产品，但仍需满足共用 Webhook 的全局配置条件。
- 新私钥用于目录请求时可能出现在请求 URL 中，排错时不要公开完整 URL、代理访问日志或浏览器网络记录。保存成功不代表已完成支付验收。

### Waffo

先选择沙盒或生产环境，再填写该环境的完整凭证。仅开启开关并不意味着网关可用。

| 页面字段 | 默认或填写要求 | 说明 |
| --- | --- | --- |
| 启用 Waffo | 默认关闭 | 钱包入口与回调还要求合规和当前环境的 API Key、RSA 私钥、平台公钥。 |
| 沙盒模式 | 默认关闭 | 开启后使用沙盒凭证及服务地址，不能混用生产三件套。 |
| API Key / 沙盒 API Key | 默认空 | 本页空输入保留已有值，轮换时填写新值。 |
| RSA Private Key / 沙盒私钥 | 默认空 | SDK 使用 Base64 DER PKCS#8 RSA 私钥；不要直接将任意 PEM 文本当成兼容格式。空输入保留。 |
| Waffo Public Key / 沙盒公钥 | 默认空 | 平台验签公钥，使用 Base64 X.509 SPKI RSA 格式；可回显，清空保存会移除，不适用私钥的留空保留规则。 |
| 商户 ID | 服务商提供 | `WaffoMerchantId`，核对与当前凭证的账户关系。 |
| 货币 | 只读，可能显示空 | 下单未配置时回退 USD，不跟随系统显示货币自动切换。 |
| 单价 | 默认 `1` | `WaffoUnitPrice`，结合充值值、账户组充值倍率和精确匹配优惠计算；不使用显示汇率自动换算。 |
| 最低充值 | 默认 `1`；填写正整数 | `WaffoMinTopUp`，避免使用表单允许但后端按整数解析的小数。 |
| 通知地址 | 可选 | `WaffoNotifyUrl`，填写完整通知地址；为空时按回调站点拼接 `/api/waffo/webhook`。 |
| 返回地址 | 可选 | `WaffoReturnUrl`，为空时返回 `<ServerAddress>/wallet?show_history=true`，不负责入账。 |

![Waffo 网关](/assets/guide/feature-guide/system-settings-billing-and-payments-payment-gateway-waffo.png)

**新增支付方式**

![新增 Waffo 支付方式](/assets/guide/feature-guide/system-settings-billing-and-payments-payment-gateway-waffo-add-payment-method.png)

| 弹窗字段 | 填写要求 | 说明 |
| --- | --- | --- |
| 显示名称 | 必填 | 用户看到的按钮名称。 |
| 图标 | 可选；上传不超过 100 KiB | 支持选择 PNG、JPG、SVG、WebP；建议尺寸不超过 128×128，图标不决定路由。 |
| 支付方式类型 | 按服务商要求填写 | 例如 `CREDITCARD,DEBITCARD`，对应 `payMethodType`，不是常规支付方式的 `type`。 |
| 支付方式名称 | 可选的网关方法标识 | 对应 `payMethodName`，如具体钱包方式；不同于显示名称。 |

1. 开启 Waffo，选择环境并填写对应三项凭证、商户资料和金额设置。
2. 核对通知和返回地址，新增或编辑支付方式；弹窗确认仅更新列表。
3. 保存所有设置，再用测试账户选择相应方式下单。
4. 核对 `X-SIGNATURE` 验签、订单成功状态、到账额度及日志。支付页面返回不代表入账成功。

通知地址优先级为：`WaffoNotifyUrl` → `CustomCallbackAddress + /api/waffo/webhook` → `ServerAddress + /api/waffo/webhook`。返回地址独立处理。存在待结订单时不要随意关闭网关或切换验签环境，否则正常通知也可能无法处理。

### 金额与入账核对

| 网关 | 配置时重点核对 |
| --- | --- |
| EPay | 本地单价、充值倍率、优惠与服务商实收；到账基于订单充值额度。 |
| Stripe | 本地报价不等于 Stripe Price 实收；分组倍率参与站内入账，优惠码和本地优惠不是同一机制。 |
| Creem | 产品实际价格与站内展示一致；`quota` 直接作为内部额度入账。 |
| Waffo | 环境、实际货币、单价、倍率和通知地址；不要用显示汇率推断网关金额。 |
| Pancake | 钱包 checkout 使用本次 USD 价格；提供方税费及最终应付需在 checkout 核对。 |

签名正确、订单匹配和状态允许后才会入账；重复成功通知不会重复发放同一订单额度。不要通过刷新成功页面、重复发起付款或盲目补单处理回调故障。TOKENS 兼容模式存在换算、整数取整及限额差异，不要承诺任意 Token 数量都能精确购入；有待结订单时不要修改额度换算基准。

## 签到奖励

签到奖励直接增加用户普通 quota，不通过支付网关。开启后才显示奖励范围输入。

| 页面字段 | 默认或填写要求 | 说明 |
| --- | --- | --- |
| 启用签到功能 | 默认关闭 | `checkin_setting.enabled`，允许用户每日领取随机额度。 |
| 最小签到额度 | 默认 `1000`；非负整数 quota | `checkin_setting.min_quota`，奖励下限；默认基准下约为系统 `$0.002`。 |
| 最大签到额度 | 默认 `10000`；非负整数 quota | `checkin_setting.max_quota`，奖励上限；默认基准下约为系统 `$0.02`。 |

1. 开启签到，填写奖励范围并核对 quota 单位。
2. 点击保存签到设置，刷新确认。
3. 用测试用户签到，核对奖励和系统日志，再次签到应被拒绝。

![签到奖励](/assets/guide/feature-guide/system-settings-billing-and-payments-check-in-rewards.png)

**注意事项**

- 截图展示关闭状态，因此没有奖励输入框；并非缺少奖励配置能力。
- 最大值大于最小值时，在包含两端的区间内随机发放；否则固定发放最小值。当前表单不会因最小值大于最大值自动报错，保存前自行核对。
- 每日按服务进程的本地日期判断，不按每位用户的浏览器时区判断；多实例应保持时区一致。
- 用户和日期的唯一约束防止同一天重复领取；开启全局 Turnstile 时，签到请求也需通过对应校验。

## 保存后的验证清单

- [ ] 刷新设置，核对变更字段；模型价格遇到版本冲突时重新加载，普通设置检查是否部分成功。
- [ ] 用已知 Token、缓存、媒体和工具用量验证估算及真实日志；不要把估算器当真实账单。
- [ ] 用不同账户组和令牌组验证实际渠道、分组倍率及 Auto 顺序。
- [ ] 比较同一额度在钱包和日志中的显示，确认未混淆显示汇率与支付单价。
- [ ] 每个网关分别测试下单、实际收费、签名通知、订单状态与到账额度；确认返回页不是唯一成功依据。
- [ ] 测试新用户、邀请注册、邀请额度转移及重复签到，确认奖励进入正确余额。

## 常见问题

- **保存成功但价格没变？** 区分编辑草稿与最终保存，检查模型名、当前模式、提供方覆盖及请求开始时的价格快照。
- **关闭某项价格是否就是免费？** 不一定。移除覆盖可能恢复默认；工具价格还可能匹配更具体前缀。显式零值、未配置和删除是不同状态。
- **公开价格接口为什么访问失败？** 检查公开倍率开关，当前路径为 `/api/ratio_config`。
- **100 的优惠为什么没有用于 200？** 金额优惠按原始金额精确匹配，不是最低阈值规则。
- **Stripe 报价与付款页不一致？** 核对 Stripe Price 的货币、单价和数量，以及本地单价、充值倍率、优惠与 Stripe 优惠码的区别。
- **Creem 产品额度填 1 为什么不是到账 1 美元？** 该字段是内部 quota；默认基准下系统 1 USD 对应 500000 quota。
- **密钥框为空是否未配置？** 不一定。多数 API 密钥和私钥不回显；各字段留空规则不同，尤其不能将 Waffo 公钥当成留空保留的私钥。
- **用户不能选择某个组？** 核对公共可用列表、特殊规则、账户自身组、倍率配置及令牌限制；使用 Auto 还需开放 `auto`。
- **Pancake 创建成功为何没有完成配置？** 外部资源创建、当前选择和本地绑定保存是三个阶段，需核对并保存绑定。
- **签到每天都是最小值？** 检查最大值是否不大于最小值，并确认输入使用的是 quota。
