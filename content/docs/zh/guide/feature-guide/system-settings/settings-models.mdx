## 模型与路由配置简介

该工作区包含「全局模型配置」「路由可靠性」「Gemini」「Claude」「Grok」「渠道亲和」和「模型部署」七个分区。负责实例级的模型协议适配、重试和可靠性策略。

| 分区 | 入口 | 主要用途 |
| --- | --- | --- |
| [全局模型配置](#全局模型配置) | `/system-settings/models/global` | 请求透传、思考后缀豁免、ChatCompletions 转换、流式心跳。 |
| [路由可靠性](#路由可靠性) | `/system-settings/models/routing-reliability` | 重试、渠道健康检查、自动禁用与恢复。 |
| [Gemini](#gemini) | `/system-settings/models/gemini` | Gemini/Vertex 转换默认值与思考适配。 |
| [Claude](#claude) | `/system-settings/models/claude` | Claude 请求头覆盖、默认输出上限与思考适配。 |
| [Grok](#grok) | `/system-settings/models/grok` | 使用规范违规的额外扣费。 |
| [渠道亲和](#渠道亲和) | `/system-settings/models/channel-affinity` | 按请求标识复用上次成功渠道。 |
| [模型部署](#ionet-模型部署) | `/system-settings/models/model-deployment` | io.net 托管部署的开关与凭证。 |

## 配置分区

模型与路由域下有七个独立分区：

### 全局模型配置

- 请求透传

启用后，Relay 会在相关协议链路中把客户端原始请求体直接发送给上游，跳过许多请求体转换、字段移除、系统提示词合并和参数覆盖步骤。

<Callout type="info">
- 分别发送一次非流式请求和一次流式请求，检查上游是否识别全部字段。
- 对比开启前后的模型映射、用量统计和错误响应。
</Callout>

- 不自动处理思考后缀的模型

此处列出的模型不会自动添加或移除 -thinking / -nothinking 后缀。命中的模型同时豁免 @ 修饰符解析与 400 校验。以 re: 开头的条目会按 Go 正则匹配完整模型名，例如 re:.*@sha256:.*。

- ChatCompletions → 响应兼容

渠道匹配与模型正则需要同时满足。页面提供「填充示例（指定渠道）」和「填充示例（全部渠道）」两个按钮。

**字段说明：**

| 字段 | 作用 |
| --- | --- |
| `enabled` | 总开关；关闭时其他字段不生效。 |
| `all_channels` | 为 `true` 时允许所有渠道参与匹配。 |
| `channel_ids` | `all_channels` 为 `false` 时按渠道 ID 匹配，命中任一即通过。 |
| `channel_types` | `all_channels` 为 `false` 时按渠道类型编号匹配，命中任一即通过。 |
| `model_patterns` | 正则表达式数组；请求模型至少命中一项才转换。 |

<Callout type="warn">
- 此功能为实验性功能。配置格式和行为可能会发生变化。
- 全局请求透传或目标渠道的请求体透传开启时不会进入该转换链路
</Callout>

- 渠道健康检查

<div className="[&_table]:min-w-[48rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 页面字段 | 配置键 | 默认值 | 校验与范围 | 说明 |
| --- | --- | --- | --- | --- |
| 定期渠道测试 | `monitor_setting.auto_test_channel_enabled` | `false` | 布尔 | 在后台自动探测所有渠道。 |
| 渠道测试模式 | `monitor_setting.channel_test_mode` | `scheduled_all` | 主动检查全部渠道 / 主动检查已开启自动禁用的渠道 / 仅检查被自动禁用的渠道 | 定时检查除手动禁用外的全部渠道，用于主动发现故障并自动恢复渠道。 |
| 测试间隔（分钟） | `monitor_setting.auto_test_channel_minutes` | `10` | 最小 `1` | 系统测试所有渠道的频率。 |
| 渠道测试并发数 | `monitor_setting.channel_test_concurrency` | `1` | `1–32` | 同时测试的最大渠道数。 |
| 成功后重新启用 | `AutomaticEnableChannelEnabled` | `false` | 布尔 | 检查成功后使渠道恢复在线。 |

</div>

**渠道测试模式：**

| 模式 | 测试范围 |
| --- | --- |
| 主动检查全部渠道 | 测试除手动禁用外的渠道，可检测故障并恢复自动禁用渠道。 |
| 主动检查已开启自动禁用的渠道 | 只测试开启渠道级自动禁用且未被手动禁用的渠道。 |
| 仅检查被自动禁用的渠道 | 只测试自动禁用渠道，不对健康渠道定时探测，也不在本轮继续禁用其他渠道。 |

<Callout type="info">
手动禁用的渠道不会被自动恢复。
</Callout>

- 自动禁用规则

<div className="[&_table]:min-w-[48rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 页面字段 | 配置键 | 默认值 | 校验与范围 | 影响范围 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 失败时禁用 | `AutomaticDisableChannelEnabled` | `false` | 布尔 | 全局自动禁用开关 | 当测试失败时自动禁用渠道。 |
| 禁用阈值（秒） | `ChannelDisableThreshold` | `5` | 非负数 | 仅渠道测试耗时 | 自动禁用超出此响应时间的渠道。 |
| 自动禁用状态码 | `AutomaticDisableStatusCodes` | `401` | 状态码或区间列表 | 真实请求与渠道测试 | 接受逗号分隔的状态码和包含性范围，命中即禁用渠道。 |
| 失败关键词 | `AutomaticDisableKeywords` | 7 条内置关键词，每行一条 | 多行文本 | 上游错误文本 | 如果上游错误包含以下任何关键字（不区分大小写），渠道将自动禁用。 |

</div>

<Callout type="info">
自动禁用会记录原因并通知 Root，多密钥渠道可能只更新发生错误的密钥状态。
</Callout>

### Gemini

Gemini 分区控制 Gemini 和部分 Vertex 转换链路使用的实例级默认行为。

<div className="[&_table]:min-w-[48rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 页面字段 | 默认值 | 校验与范围 | 说明 |
| --- | --- | --- | --- |
| 安全设置 | `{"default":"OFF"}` | JSON 字符串映射 | 以 JSON 格式提供按类别划分的安全覆盖。使用 `default` 作为回退值。 |
| 版本覆盖 | `{"default":"v1beta","gemini-1.0-pro":"v1"}` | JSON 字符串映射 | 将模型标识符映射到 Gemini API 版本。当未找到特定匹配项时，将应用 `default` 条目。 |
| 支持的 Imagine 模型 | 7 项内置模型 | JSON 字符串数组 | 接受支持 Imagine API 的模型标识符的 JSON 数组。 |
| 思考后缀适配器 | `false` | 布尔 | 支持 `-thinking`、`-thinking-\|{{budget}}` 和 `-nothinking` 后缀，同时路由到正确的 Gemini 变体。 |
| 预算令牌比例 | `0.6` | `0.002–1` | 预算令牌 = 最大令牌数 × 比例。接受 0.002 到 1 之间的十进制数。建议与上游计费保持一致。 |
| 启用 FunctionCall 思维签名填充 | `true` | 布尔 | 仅为使用 OpenAI 格式的 Gemini/Vertex 渠道填充 thoughtSignature |
| 移除 functionResponse.id 字段 | `true` | 布尔 | Vertex AI 不支持 functionResponse.id 字段，开启后将自动移除该字段 |

</div>

<Callout type="info">
- 「支持 Imagine 的模型」只改变转换时的输出模态，不会自动添加模型、价格或渠道能力；应填写模型映射后的上游名称。
- 即使禁用适配器，Gemini 也会继续自动检测思维模式。仅当您需要对定价和预算进行更精细的控制时才启用思考后缀适配器。
</Callout>

![Grok 分区](/assets/guide/feature-guide/system-settings-models-and-routing-grok.png)

<Callout type="warn">
1. 只有在上游错误中出现受支持的违规标记（例如内容违反使用规范的提示）时才触发。普通上游错误、内容审核失败或所有 Grok 请求不会因此额外扣费；这类错误还会被标记为不可重试。
2. 实际扣费按「基础金额 × 系统分组倍率」换算，并在正常预扣失败流程之外单独写入一条消费记录，排查时应同时查看原请求错误和违规费日志。页面提供指向 x.ai 官方说明的链接。
3. 该设置直接扣减用户余额。启用或调整金额前应核对上游最新违规收费规则、分组倍率和面向用户的价格说明，并用可控测试验证日志与额度变化。
</Callout>

### 渠道亲和性

渠道亲和性会基于从请求上下文或 JSON Body 提取的 Key，优先复用上一次成功的渠道。

<div className="[&_table]:min-w-[48rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 页面字段 | 默认值 | 校验与范围 | 影响范围 | 说明 |
| --- | --- | --- | --- | --- |
| 启用 | `true` | 布尔 | 全局亲和 | 渠道亲和性会基于从请求上下文或 JSON Body 提取的 Key，优先复用上一次成功的渠道。 |
| 最大条目数 | `100000` | 非负整数 | 内存缓存容量 | - |
| 默认 TTL（秒） | `3600` | 非负整数 | 缓存有效期 | - |
| 成功后切换亲和 | `true` | 布尔 | 重试成功后的缓存更新 | 如果亲和到的渠道失败，重试到其他渠道成功后，将亲和更新到成功的渠道。 |
| 渠道禁用后保留亲和 | `false` | 布尔 | 缓存渠道不可用时的处理 | 开启后，亲和到的渠道被禁用，或不再适用于当前分组/模型时，仍保留这条亲和；关闭时会删除并重新选择渠道。 |
| 规则 | 2 条内置模板 | JSON 数组 | 匹配与缓存键 | 可在可视化与 JSON 模式间切换。 |

</div>

**基础参数**

<div className="[&_table]:min-w-[48rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 页面字段 | 默认或填写要求 | 说明 |
| --- | --- | --- |
| 名称 | 必填 | 用于识别规则；启用「包含规则名」时也参与缓存隔离。建议为不同规则设置不同名称。 |
| 模型正则（每行一个） | 至少一项 | 对请求模型名进行 Go 正则匹配，任意一项匹配即可。需要匹配完整名称时使用 `^` 和 `$`，例如 `^gpt-4o.*$`。 |
| 路径正则（每行一个） | 可选，默认空 | 对请求 URL 路径进行正则匹配，任意一项匹配即可；留空不限制路径。填写后，模型和路径条件必须同时满足，例如 `^/v1/chat/completions$`。 |
| 失败后不重试 | 默认关闭 | 开启后，匹配到该规则的请求在失败时受禁止重试策略约束，不限于已经命中亲和缓存的请求。关闭此项也不保证一定重试，仍需满足全局重试条件。 |
| Key 来源 | 至少一个有效来源 | 指定用于识别同一会话或请求主体的值。可添加或删除来源，多个来源按排列顺序取第一个非空值，不会拼接。 |

</div>

**Key 来源类型**

<div className="[&_table]:min-w-[48rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 类型 | 填写内容 | 说明 |
| --- | --- | --- |
| `context_int` | 请求上下文键名，例如 `token_id` | 读取上下文中的正整数并转换为字符串；值不存在或不大于 `0` 时尝试下一个来源。 |
| `context_string` | 请求上下文键名，例如 `username` | 读取上下文字符串并去除首尾空白；空值时尝试下一个来源。 |
| `request_header` | 请求头名称，例如 `X-Session-ID` | 读取指定请求头并去除首尾空白；客户端需要实际携带该请求头。 |
| `gjson` | JSON Body 的 GJSON 路径，例如 `metadata.conversation_id` | 从请求体中提取值；路径不存在或提取结果为空时尝试下一个来源。 |

</div>

**高级参数**

<div className="[&_table]:min-w-[48rem] [&_td:first-child]:whitespace-nowrap [&_th]:whitespace-nowrap">

| 页面字段 | 默认或填写要求 | 说明 |
| --- | --- | --- |
| User-Agent include（每行一个） | 可选，默认空 | 对请求的 User-Agent 进行不区分大小写的包含匹配，任意一项满足即可，例如 `curl`。不是正则表达式；留空不限制。 |
| Value 正则 | 可选，默认空 | 使用 Go 正则校验提取到的 Key 值，不用于截取或替换内容。需要完整匹配时使用 `^` 和 `$`；留空不校验。 |
| TTL（秒，0 表示默认） | 默认 `0`，填写非负整数 | `0` 表示继承亲和分区的「默认 TTL（秒）」；正数表示该规则缓存条目的有效期。 |
| 参数覆盖模板（JSON） | 可选，默认空 | 填写 JSON 对象，规则匹配后与所选渠道的参数覆盖合并。普通同名键保留渠道值；`operations` 数组按规则模板在前、渠道操作在后的顺序合并。完整语法见[参数覆盖系统](/zh/docs/guide/feature-guide/admin/channel#参数覆盖系统)。 |
| 包含分组 | 默认开启 | 将当前使用分组加入缓存键，隔离不同分组下的相同 Key。 |
| 包含模型 | 默认关闭 | 开启后将请求模型名加入缓存键，隔离不同模型下的相同 Key。 |
| 包含规则名 | 默认开启 | 将规则名加入缓存键；按规则统计和清空缓存依赖此项。关闭后，不同规则在其他缓存键组成相同时可能共享条目。 |

</div>

**操作流程与注意事项**

1. 填写参数后点击弹窗「保存」，只会更新当前页面的规则草稿；还需点击亲和分区的「保存」才会提交配置。点击「取消」不会提交本次弹窗编辑。
2. 规则按列表顺序匹配。第一条满足模型、路径、User-Agent 条件并取得通过 Value 正则校验的非空 Key 的规则确定后，即使没有命中缓存，也不会继续寻找后面的规则。
3. 多个 Key 来源只取第一个非空值。如果该值未通过 Value 正则，会跳过整条规则，不会继续尝试该规则后面的 Key 来源。
4. 弹窗会检查模型正则是否填写、是否有有效 Key 来源，以及参数覆盖模板是否为 JSON 对象，但不会保证正则合法。保存成功后仍需用实际请求验证。

### 模型部署

当前模型部署集成支持 io.net。Root 从「系统设置 → 模型与路由 → 模型部署」进入，或访问 `/system-settings/models/model-deployment`。本分区用于启用接入和配置凭证，不是创建部署资源的表单。

**字段与按钮说明**

| io.net API 密钥 | 首次配置时填写 | 配置键为 `model_deployment.ionet.api_key`，用于 io.net 部署 API 授权。重新加载页面后不回显，输入框为空不表示尚未配置。 |

**配置流程**

1. 开启「启用 io.net 部署」，展开密钥配置区域。
2. 点击「前往 io.net API 密钥」，打开 [io.net API 密钥页面](https://ai.io.net/ai/api-keys)。创建或选择密钥时，将 Project 设置为 `io.cloud`。
3. 复制密钥，粘贴到「io.net API 密钥」输入框。已有密钥且无需更换时，可保持重新加载后的空框不变。
4. 点击「测试连接」。成功后页面显示连接成功提示；失败时根据错误信息检查密钥、项目和网络连接。没有输入密钥且没有已保存密钥时，测试会提示需要 API Key。
5. 点击右上角「保存 io.net 设置」。确认保存成功后刷新页面，核对启用状态，并在密钥输入框为空时再次测试，以验证已保存的凭证。

<Callout type="warn">
  关闭本分区的接入开关不会终止已有 io.net 部署，也不代表第三方费用停止。创建、延长和终止部署会改变第三方资源和费用，执行前应核对 io.net 账户、资源配置及账单；New API 不保证第三方容量、账单或部署成功率。
</Callout>

## 变更后验证

1. 刷新当前分区，确认非敏感字段显示为预期值。
2. 用测试 Token 分别发送非流式与流式请求，检查模型映射、上游请求格式、用量和日志。
3. 用可控的失败渠道验证重试次数、状态码、自动禁用原因和自动恢复，避免在生产高峰制造大量失败。
4. 为亲和规则准备固定 Key，连续请求并检查渠道 ID、缓存条目与重试后的缓存切换。
5. 分别验证 Gemini、Claude 或 Grok 的真实适配场景，不要只确认 JSON 能保存。
6. 部署场景先做连接测试和价格估算，再创建最小部署，并单独验证渠道配置。

## 常见问题

- **保存后字段没有变化**：确认点击的是该分区的保存按钮，并检查是否有 `success:false` 提示；逐键保存时失败项不会自动重试。
- **正则写了却没有匹配**：`thinking_model_blacklist` 的正则必须以 `re:` 开头，并按完整模型名匹配；无效正则只在运行期记录系统错误。
- **开启透传后转换策略失效**：全局或渠道级请求透传会跳过转换链路。
- **重试没有生效**：检查重试次数、状态码集合、Token 是否固定渠道、错误是否被标记为不可重试，以及是否存在可用备选渠道。
- **渠道被自动禁用**：同时检查全局自动禁用开关、渠道级自动禁用、状态码集合和失败关键词；响应时间阈值只在渠道测试中比较。
- **渠道没有自动恢复**：恢复需要开启自动恢复开关并有一次成功的渠道测试；手动禁用的渠道不会自动恢复。
- **计划测试间隔与页面不一致**：部署环境可能设置了 `CHANNEL_TEST_FREQUENCY` 或 `CHANNEL_TEST_ENABLED`，它们会覆盖页面值。
- **按规则清空缓存报错**：该规则未启用「包含规则名」，缓存键无法归属。
- **缓存条目数始终为 0**：检查亲和总开关、规则是否命中，以及规则是否启用了「包含规则名」。
- **Claude 请求缺少 `max_tokens` 被上游拒绝**：确认 `default_max_tokens` 保留 `default` 键，且数值未超过上游输出上限。
- **Grok 出现额外扣费**：查看原请求错误是否包含违规标记，再核对分组倍率和违规费消费日志。
- **部署页提示未启用**：需要同时开启开关并保存有效 API Key，两个条件缺一不可。
- **部署已创建但模型请求没有使用它**：部署不会自动创建或绑定渠道，需要手动配置端点。
